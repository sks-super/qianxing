# TickHop（滴答咔哒）千星奇域实现方案

> 以一个已跑通的「割绳子」工程为参照系，把 TickHop 的时间解谜平台跳跃玩法的完整实现路径写清楚。
> 本文档对应代码为同目录下的 `game.lua` / `config.lua` / `state.lua` / `timeSystem.lua` / `level.lua` / `physics.lua` / `utils.lua` / `audio.lua` / `signal.lua` / `fadeScreen.lua` 与 `编辑器.html`。

---

## 一、玩法拆解：把观感翻译成系统

从原版截图的两个关键帧可以直接读出规则：

- **第 02 关**：纯黑背景、白色线条平台、倒计时 `9.01`、左下角有个白色小方块（带两只眼睛）。这是一关**教学关**——平台是常驻的，考的是移动与跳跃。
- **第 11 关**：黄紫配色、平台是深紫色、平台底部分别标着 `6 / 5 / 6 / 5`、倒计时 `6.39`。这是**核心机制关**——每个平台绑一个秒数，只有倒计时的整数部分等于它时才实心。

由此抽象出四个系统：

| 观感 | 系统 | 关键约束 |
|---|---|---|
| 顶部跳动的数字（两位小数） | **时间系统** | 倒计时递减；整数部分决定平台状态；可加时、可反转 |
| 带数字的平台忽明忽暗 | **计时平台** | 按 `floor(当前时间)` 切换实体/虚化，虚化时不可碰撞 |
| 小方块的跑跳 | **平台跳跃物理** | 重力 + 水平加速 + 跳跃缓冲/土狼时间 + AABB 分轴碰撞 |
| 白色方块门 | **终点与结算** | 玩家与门重叠即过关；时间耗尽/掉出关卡即失败 |

**核心设计诀窍**：平台亮灭的判据只有 `floor(now)` 一个值，所以整个游戏的"节奏"完全由时间轴驱动，不需要任何动画状态机——时间推进 → 整数部分变化 → 平台整体刷新。这让增删机关的成本极低。

## 二、从割绳子继承的经验（哪些直接复用）

割绳子与 TickHop 是两套**玩法内核完全不同**的游戏（前者=连续绳索物理，后者=时间状态机 + 平台碰撞），但工程骨架可以整体平移：

| 割绳子的做法 | 是否复用 | TickHop 的沿用方式 |
|---|---|---|
| `config.lua` 作为 `DEFAULT_*` 唯一真源 | ✅ 直接复用 | 同上；编辑器 `DEFAULTS` 用 `_check_refs.py` 强制同步 |
| `state.lua` 集中声明全部运行时字段 | ✅ 直接复用 | 同上，杜绝动态建字段 |
| 容器化父节点管理 UI 层级 | ✅ 直接复用 | 改为 7 层：bg → platform → goal → pickup → player → hud → fade |
| 黑幕过渡掩护关卡切换（onPeak 时机加载） | ✅ 直接复用 | `fadeScreen` 原样搬用，仅换依赖字段名 |
| 过关/失败走 `signal.send` 上报 | ✅ 直接复用 | 事件名改为「到达终点 / 游戏失败」 |
| 服务端下发「进入关卡」切关 | ✅ 直接复用 | `signal.register` + `getIntParam` |
| 编辑器「画布 + 属性面板 + 导入导出 Lua」 | ✅ 直接复用 | 对象类型换成平台/门/道具/起点/文本 |
| 两个 Python 静态校验器 | ✅ 升级为通用版 | 自动识别游戏目录与模块集合 |
| Lua 前置声明陷阱（`local f` + `f = function`） | ⚠️ 必须遵守 | `doLoadLevel` 同理 |
| 物理子步长 / pcall 容错 / 控件预创建复用 | ✅ 直接复用 | 见 `physics.lua` |

**唯一需要完全重写的**是玩法层：绳索约束（`rope.lua` / `catenary.lua`）整体废弃，替换为 `timeSystem.lua` + `level.lua` 的平台刷新；刀光拖尾（`bladeTrail.lua`）与本作无关，删除。

## 四、时间系统设计（`timeSystem.lua`）

### 4.1 状态与语义

| 字段 | 含义 |
|---|---|
| `now` | 当前剩余时间（浮点秒），显示为 `秒.百分秒` |
| `limit` | 本关初始时间，同时是**反转时的上限**（时间不能倒流回关卡开始之前） |
| `direction` | `-1` = 递减（常规倒计时）；`+1` = 递增（时间反转后） |
| `tick` | `floor(now)`，**平台实体判定的唯一依据** |
| `expired` | 是否已归零（递减到 0 后置位，停止推进） |

显示格式：`string.format("%d.%02d", floor(now), floor((now % 1) * 100 + 0.5))`，与截图中的 `9.01` / `6.39` 一致。

### 4.2 平台显隐规则

```
tick == -1            → 永驻平台，始终实体
tick >= 0 且 == 当前tick → 实体（亮色、可碰撞）
其余                   → 虚化（暗色、不可碰撞，玩家可穿过）
```

实现上**不销毁重建控件**，只改颜色与 alpha——这是从割绳子继承的性能约定（避免 Instantiate 抖动）。

### 4.3 时间操控

| 接口 | 行为 |
|---|---|
| `M.add(seconds)` | 剩余时间增加，夹取到 `[0, limit]`；若此前已归零则**复活计时**（让"濒死加时"成立） |
| `M.reverse()` | 翻转 `direction`；反弹回递减且已归零时重新置 `expired` |
| `M.setRunning(bool)` | 暂停/恢复推进（关卡切换的黑幕期间会短暂暂停） |

### 4.4 关键细节：黑幕期间不扣时

关卡在 `fadeScreen.onPeak`（黑幕最黑的瞬间）重建。若此时就开始走表，玩家会在"还看不见关卡"时被扣掉约 0.4 秒。
处理方式：重建完成后立即 `setRunning(false)` 并置 `state.pendingStart = true`，在 `OnUpdate` 中检测到 `fadeScreen.active == false`（黑幕散尽）后再启动计时。

## 五、玩家物理与碰撞（`physics.lua`）

### 5.1 手感参数（全部在 `config.lua` 可调）

| 参数 | 默认 | 设计意图 |
|---|---|---|
| `DEFAULT_MOVE_SPEED` | 260 | 水平最大速度 |
| `DEFAULT_GROUND_ACCEL` / `FRICTION` | 2600 / 3200 | 地面响应迅速，操作跟手 |
| `DEFAULT_AIR_ACCEL` / `FRICTION` | 1500 / 300 | 空中保留惯性，跳跃有"重量感" |
| `DEFAULT_JUMP_SPEED` | 520 | 起跳初速度 |
| `DEFAULT_GRAVITY` / `FALL_GRAVITY_MULT` | 1600 / 1.35 | 下落重力加大，落点干脆（平台跳跃经典手感） |
| `DEFAULT_MAX_FALL_SPEED` | 1000 | 上限防穿透 |
| `DEFAULT_COYOTE_TIME` | 0.10 | 土狼时间：刚离地仍可跳 |
| `DEFAULT_JUMP_BUFFER_TIME` | 0.12 | 跳跃缓冲：落地前提前按跳仍生效 |
| `DEFAULT_PHYSICS_SUBSTEPS` | 4 | 子步长，降低高速穿透 |

### 5.2 分轴碰撞解算

每一物理子步内：

1. 水平输入 → 加速度逼近目标速度，得到 `vx`
2. 跳跃判定（缓冲 + 土狼时间同时满足才起跳）
3. 施加重力（下落时乘 `FALL_GRAVITY_MULT`）
4. **X 轴**：`x += vx*dt` → 与所有 `solid` 平台做 AABB 检测 → 命中则按速度方向贴边并清零 `vx`
5. **Y 轴**：`y += vy*dt` → 命中则按速度方向贴顶/落地，落地时置 `onGround = true` 并清零 `vy`

分轴解算的好处：贴墙、贴顶、落地、角落都不会卡住，也不需要引入"穿透深度"排序。

可变跳跃高度：松开跳跃键时把上升速度乘 `0.45`，实现"轻点小跳、长按高跳"。

### 5.3 玩家表现

极简风格下玩家 = 一个方块 + 两只眼睛（眼睛用背景色绘制，在浅色方块上呈现为深色点）。眼睛随 `face`（朝向）水平镜像偏移，成本极低但辨识度足够。

## 六、关卡数据结构（`config.lua` 的 `LEVELS`）

```lua
{
    name = "第01关",
    time = 12.00,                                  -- 倒计时初始值（秒）
    spawn = {x = -300, y = -180},                  -- 玩家出生点（中心坐标）
    goal  = {x = 200, y = -100, width = 56, height = 84},
    palette = { bg = "3A2B45", platform = "F5D96B" },   -- 可选，覆盖默认配色
    platforms = {
        {x = -200, y = -240, width = 420, height = 24, tick = -1},  -- 永驻
        {x = 180,  y = -160, width = 150, height = 22, tick = 4},   -- 第 4 秒亮起
    },
    pickups = {
        {x = -120, y = -80, type = "time",    value = 4.00},        -- 加时 4 秒
        {x = 40,   y = 10,  type = "reverse", value = 0},           -- 时间反转
    },
    texts = {
        {x = -140, y = 120, text = "平台上的数字 = 它会亮起的秒数"},
    },
}
```

### 坐标系约定

- 世界原点在 UI 画布中心，**Y 轴向上为正**（与割绳子一致，`SetAnchoredPosition` 直接可用）
- 画布逻辑尺寸默认 `800 × 600`，实际运行时以 `game.GetUICanvasSize()` 为准
- 所有对象坐标均为**中心点**；编辑器与运行时使用同一套坐标，无需换算

### 配色（`DEFAULT_PALETTE`）

`bg / platform / ghost / label / player / goal / hud / pickup / reverse / danger`，全部为 6 位十六进制字符串，由 `utils.hexToColor` 转 `Color`。关卡可用 `palette` 字段局部覆盖，实现"每关一套配色"的原作观感。

## 七、关卡编辑器（`编辑器.html`）

单文件、零依赖，直接双击打开。

### 7.1 布局

| 区域 | 功能 |
|---|---|
| 顶栏 | 关卡切换 / 新建 / 复制 / 删除、关卡名、倒计时、配色预设、**秒数预览滑块**、居中、导入、导出 |
| 左栏 | 工具选择：选择移动、计时平台、永驻平台、玩家起点、终点门、加时道具、反转道具、提示文本、删除 |
| 中间 | Canvas 画布（滚轮缩放、中键平移、拖拽移动、点击放置） |
| 右栏 | 选中对象的属性面板（数值编辑即时反映到画布） |

### 7.2 秒数预览（本编辑器最核心的辅助功能）

顶部滑块选择 0–20 的任意秒数，画布上**所有平台会实时按该秒数显示亮/暗**，数字标签同步变灰。
设计师不需要进游戏就能验证"第 4 秒时玩家脚下是否有落点"——这直接对应 TickHop 最难的关卡设计问题：**时间窗的可行性**。

### 7.3 数据流

```
编辑器（内存关卡数组）
   ├─ 导出 → 生成 M.LEVELS = { ... }  Lua 片段 → 复制 → 覆盖 config.lua 的 LEVELS
   └─ 导入 ← 粘贴 M.LEVELS 片段 → 正则解析（含 palette 块）
```

导出格式与 `config.lua` 中手写的关卡**逐字节同构**，因此可以双向无损来回。往返一致性已由 `_shared/_tmp/test_roundtrip.js` 自动验证（覆盖平台 tick、道具类型、文本、配色）。

参数默认值集中在编辑器顶部的 `const DEFAULTS = { ... }`，与 `config.lua` 的 `DEFAULT_*` **机械对应**（key 大写即常量名），由 `_check_refs.py` 强制校验，杜绝"编辑器里看到的默认值 ≠ 游戏实际行为"。

## 八、千星沙箱落地步骤

### 8.1 需要在编辑器里准备的元件

| 用途 | 脚本变量名 | 是否必填 | 说明 |
|---|---|---|---|
| 纯色矩形底图 | `rectPrefabId` | **必填** | 一张白色/纯色方块图片元件，游戏会对其染色，用于背景、平台、玩家、门、道具、虚拟按钮 |
| 文本控件 | `textPrefabId` | 建议 | 倒计时、平台秒数标签、提示文本；缺失则这些内容不显示 |
| 玩家外观 | `playerPrefabId` | 可选 | 不填则回退 `rectPrefabId` |
| 终点门外观 | `goalPrefabId` | 可选 | 不填则回退 `rectPrefabId` |

音效（均可选，`0` 表示不播放）：`jumpAudioId` / `landAudioId` / `switchAudioId` / `pickupAudioId` / `winAudioId` / `failAudioId`。

> 变量名后缀 `PrefabId` / `AudioId` **不可改**，否则 `script:GetParam` 读不到。

### 8.2 装配

1. 新建一个「客户端控件容器」，把 `game.lua` 挂上去
2. 依次粘贴其余模块（`config` / `state` / `timeSystem` / `level` / `menu` / `physics` / `utils` / `audio` / `signal` / `fadeScreen`）
3. 在脚本参数里填好上表的元件 ID
4. 运行 —— 默认从第 1 关开始，键盘 **A/D/←/→** 移动、**空格/W/↑** 跳跃、**R** 重开、**T/P** 切换关卡、**L** 开选关面板

### 8.3 触屏

`game.GetDevice()` 返回 `Mobile` / `MobileController` 时，代码自动在左下角创建 `← →`、右下角创建「跳」三个虚拟按钮。按钮与键盘写入**同一套输入状态**，因此物理层无需区分输入来源。

## 八·五、选关与结算面板（`menu.lua`）

### 8.5.1 为什么是三态复用而非三套界面

选关、通关、失败三个界面**控件构成高度重合**（遮罩 + 面板 + 标题 + 副标题 + 网格/按钮区 + 底部提示），
差别只在文字与显隐。若各建一套，控件数三倍、层级容器互相遮挡、状态切换还要销毁重建。
因此 `menu.init()` 一次性建好全部控件挂到 `containerMenu`，`M.refresh()` 按 `state.menuMode`
改写文字与 `SetActive`，**切换零分配**。

### 8.5.2 三种模式

| 模式 | 触发 | 网格区 | 底部按钮 |
|---|---|---|---|
| `select` | 按 `L` | 关卡卡片（含 `√` 通关标记、光标高亮） | `继续游戏` + `重玩本关` |
| `win` | 到达终点 | 剩余时间（大字） | `重玩本关` + `下一关 →`（末关变 `返回选关`） |
| `fail` | 时间耗尽 / 掉出关卡 | 失败原因 | `重玩本关` + `返回选关` |

> `select` 模式在 `state.gameWon or state.gameFailed` 时**不提供「继续游戏」**——否则会回到一个已经结束的画面。

### 8.5.3 分页与光标

网格尺寸由 `gridLayout()` 从配置推导：`cols = DEFAULT_MENU_COLS`、`rows = DEFAULT_MENU_ROWS`、
`perPage = cols * rows`、`pages = ceil(可玩关数 / perPage)`。卡片按索引线性排入网格，
左右两侧是 `← →` 翻页箭头（`PAGE_BTN_W/H`），页码并入底部提示文本。

光标 `state.menuCursor` 是**可玩关序号**（不是页内下标），`moveCursor` 跨页时自动 `setPage`，
所以「光标在哪一关」与「当前在第几页」永远一致，不需要额外同步。

### 8.5.4 暂停语义

`M.open()` 置 `state.paused = true`，`game.OnUpdate` 首行即：

```lua
if state.paused then
    level.updateTimerDisplay()
    fadeScreen.update(dt)
    return
end
```

即**冻结玩法**（计时、物理、拾取、结束判定全部不跑），但**黑幕与 HUD 仍每帧推进**，
避免面板期间黑幕卡死、HUD 倒计时文本冻结在错误值。

### 8.5.5 输入分流

面板键与玩法键**复用同一批物理键**（`←` `→` `空格/W`），靠 `state.menuOpen` 分流：

- `bindPair`（玩法）—— `menuOpen` 或 `keysEnabled` 为假时直接 `return false`（不吞键）
- `bindMenuKey`（菜单）—— 仅 `menuOpen` 为真时响应
- `bindGlobal`（`R`/`T`/`P`/`L`）—— **绕过 `keysEnabled`**，保证面板打开（`keysEnabled` 已被置 false）时
  仍能关闭面板、切换关卡

> 这是关键：`L` 若不绕过总开关，面板打开后就再也关不掉。

### 8.5.6 依赖解耦

`menu.lua` **不** `require("game")`（否则 `game → menu → game` 循环）。改为 `game.lua` 在 `OnStart` 里注入：

```lua
menu.setActions({ onSelect = loadLevel, onReload = reloadLevel, onNext = nextLevel })
```

`menu.lua` 只持有回调表，调 `M.enterLevel(idx)` → `t.onSelect(idx)`。

### 8.5.7 层级

`containerMenu` 是**第 8 个**容器（`bg → platform → goal → pickup → player → hud → menu → fade`）：
压在 HUD 之上、黑幕之下。面板自己再分三层：**遮罩**（`DEFAULT_MENU_OVERLAY_ALPHA = 215` 压暗游戏画面）
→ **面板底** → **文字/卡片/按钮**。

## 九、事件约定

| 方向 | 信号名 | 参数 | 触发时机 |
|---|---|---|---|
| 客户端 → 服务器 | `客户端事件` | `"到达终点"` | 玩家进入终点门 |

## 十一、后续可扩展的机关（预留位置）

当前版本已跑通"倒计时 + 计时平台 + 玩家跳跃 + 门 + 两类道具"的核心闭环。以下机制可在不改架构的前提下增量添加：

| 机关 | 落点 | 说明 |
|---|---|---|
| **开关平台** | `level.lua` 平台加 `switch` 字段 | 玩家踩下后永久翻转亮灭（叠加在 tick 规则之上） |
| **移动平台** | `level.lua` + `physics.lua` | 平台带位移轨迹；玩家需跟随（把平台速度带入玩家水平速度） |
| **消失砖** | 平台加 `life` 字段 | 踩上去后 N 秒碎裂 |
| **时间门** | 新增 `type = "gate"` | 仅在指定秒数可通过 |
| **加速/减速带** | 玩家 `MOVE_SPEED` 临时乘系数 | 进入区域生效 |
| **弹簧** | 碰撞时给 `vy` 一个额外冲量 | 落在平台上时判定 `tick` 是否为弹簧 |
| **限时收集** | 复用 `pickups` + 新增 `type = "key"` | 集齐钥匙才开门 |
| **时间暂停道具** | `timeSystem.setRunning(false)` 定时恢复 | 接口已就绪 |

**扩展原则**：凡是"随时间/条件切换实体状态"的机关，一律挂在 `level.refreshPlatforms()` 的同一套刷新逻辑里，共享 `state.timeTick`；凡是"玩家碰到就发生的事"，一律走 `physics.step()` 的碰撞分支。这样新增机关永远是**局部改动**。

## 十二、设计备注（给关卡设计师）

1. **时间窗必须留冗余**：平台亮起时长 = 1.00 秒（在 `now` 为 `N.99 → N.00` 之间）。玩家从看到平台亮起到踩上去，实际可用时间约 0.7 秒。设计连续跳点时，相邻平台的 tick 差建议 ≥ 1。
2. **首关不要放计时平台**：原作第 02 关就是纯移动教学。让玩家先熟悉"跑跳手感"，第 3 关之后再引入数字平台。
3. **用配色代替 UI 说明**：平台亮/暗的对比度直接决定可读性。`DEFAULT_PALETTE` 中 `platform` 与 `ghost` 的明度差应足够大（如 `#F2F2F2` vs `#3A3A44`）。
4. **倒计时数字要够大**：它是本作唯一的 HUD，字号默认 72，位于顶部居中——玩家需要在大脑被平台占据时余光可读。
5. **善用秒数预览滑块**：在编辑器里把滑块拖到每个 tick 上，检查"这一秒有没有落脚点"，这是避免做出不可通关的最有效手段。
