# _inbox —— 外部成果归集区

这个目录是**收件箱**：协作者把自己的产出原样放进来，由仓库所有者 `sks-super`
逐文件 review 后决定怎么并进正式代码。

> 命名沿用本仓库惯例（`_shared/`、`_tools/`、`_simulator/` 同为下划线前缀的非正式/工具目录）。

---

## 目录约定

| 子目录 | 归谁 | 内容 |
| --- | --- | --- |
| `_inbox/hzy/` | 协作者 **hzy** | 他的全部产出 |

**一人一目录**，互不覆盖。

---

## 规则

1. **只有对应的人能往自己的子目录里写**，不要去动别人的子目录。
2. **放交付物，不放垃圾**：
   - ✅ `.lua`、`编辑器.html`、关卡数据、文档、配置等文本产出
   - ❌ `node_modules/`、`.git/`、`_simulator/`、截图/录像/压缩包、含密钥或隐私的文件
3. **保留原有子目录结构**，便于逐文件 diff。
4. **必须附 `说明.md`**，写清四件事：
   1. 文件来自哪里 / 哪个游戏目录
   2. 打算合并到仓库里的哪个目录
   3. **哪些是新增、哪些会覆盖同名文件**
   4. 改了什么、为什么、怎么验证的
5. **不要在这里改仓库已有文件** —— 只放新文件。要改已有文件，
   在 `说明.md` 里说明意图，由 `sks-super` 决定并执行。

---

## 合并流程（只有 sks-super 做）

1. 看 `_inbox/<人>/说明.md`，对照 diff 逐个文件 review
2. 用 `git mv` / 复制把文件落到正式目录（如 `TickHop/`）
3. 跑校验：

   ```bash
   python _shared/_check_blocks.py TickHop
   python _shared/_check_refs.py TickHop
   node _shared/_check_editor_roundtrip.js
   ```

4. 合并该协作者的 PR（`<人>` → `main`）
5. 合并完成后，把 `_inbox/<人>/` 里已经落位的文件清理掉，**保持收件箱是空的**
   —— 空目录才看得出"这一批已经处理完了"

| 批次 | 提交 | 落位结果 | 校验 |

> ★ **合并完成后要把 `hzy` 快进回 `main`**，否则对方下一批仍基于旧基线，会把已落位/已删除的文件又带回来：
>
> ```bash
> git push origin main:refs/heads/hzy      # 管理员执行
> ```
>
> 之后协作者在自己那边 `git pull origin hzy`（或重新干净克隆）再开始下一批。
