## 3. 核心：同一根木头的「两个姿态」

第 5 批已经把「立着的也是一根**无叶树干**」这件事在**规则层**做对了（`tree.bare` 标记）。
本批解决的是**表现层**：光「没有树叶」还不够，玩家一眼扫过去还是容易把两者看成一回事。

所以给同一根木头立了**两套完全不同的形状 + 配色语言**，四个维度同时拉开：

| 维度 | 躺着的木头 | 立起来的树干 |
| --- | --- | --- |
| **剪影** | 长而扁 `1.00 × 0.50` 格（横着一段） | 窄而高 `0.36 × 1.00` 格（竖着一截） |
| **明暗** | 暗一档的旧木色 `logSide 9C6C36` + **贴地暗边** → 「躺在地上的旧木头」 | 亮一档的新木色 `logStandSide AB7A3E` + **根部土堆** `logStandFoot 6A4A23` → 「扎在地里」 |
| **受光** | 受光边**横着一条**（落在上沿/左沿） | 受光边**竖着一条**（`logStandEdge D6A863`） —— 光从斜上方来 |
| **端面** | 两端**切口**：深色外圈 `logEnd 5C4020` + 年轮芯 `logTop C09455` | 顶端**切面**：亮外圈 `logStandEdge` + 最亮芯 `logStandCap EDCB8C`（朝天的新鲜切面） |

外加一条**成对原则**：受光亮边与背光暗边**永远成对**出现在主体的两侧。
第一版把暗边一律画在下沿，结果竖躺（南北向）时它和下端切口叠成一团黑；
改成成对之后，横躺时暗边天然落在下沿（顺带兼作「贴地」线索），竖躺时落在右沿（配成圆柱感）。

### 3.1 ⚠️ 一条必须守住的边界：视觉高度 = 玩法高度

`TRUNK_H = 1.00` 格 —— 立起来的树干**在画面上**就是一格高，
因为它在**玩法上**就是一格高（`world` 里可以直接踩上去 / 跨不过去）。
躺着的木头 `LOG_THICK = 0.50` 格同理，对应 `H_LOG_LAND = 0.5`。

**这两个数不能为了「好看」随便调** —— 调了就会出现
「看着能踩上去、实际踩不上」这类**画面与规则的漂移**。要改就得连着玩法一起改。

### 3.2 过渡怎么做：代理池，不碰真实木头

倒 / 立的过程**不能直接改真实木头的控件** —— 真实木头是 `rebuildObjects()` 按格子数据重建的，
每帧插值会被下一次重建覆盖掉。所以另起了一个**过渡代理池**：

- `state.objProxyCtrls` / `objProxyUsed`：代理控件池（在 `RESTACK_POOLS` 里，
  必须挂在**世界容器**中才参与「近处压远处」的深度排序）；
- `M.setObjectAnim(act)`：按 `act.animFrom` / `act.animTo` 算出**起止两个形态**；
- `M.paintObjProxy()`：逐帧画插值形态；
- `M.animateObject(dt)`：播完清标志 + `rebuildObjects()`；否则 `paintObjProxy + restackWorld()`。

配套两个细节：

1. **`hideAnimAt(c, r)`**：过渡期间，终点格上的真实木头**先不画**（否则会和代理叠成两个自己）。
   实现是「在 `rebuildObjects()` 里比对 `state.objAnimTo.c/r` 后跳过」。
2. **配色过渡用「盖一层」而不是「两边各降一半 alpha」**：
   如果两头各 50% 透明度，中间态会露出底下的草地，读作「木头变透明了」；
   改成躺色打底 255、再用 `aNew = floor(255 * stand)` 把立色盖上去，
   全程不透明，只是在两套配色之间**硬切过渡**。

### 3.3 缓动与扬尘

- `easeBack(k, o)`：带回弹过冲的缓动。
  `knock`（倒下）用 `DEFAULT_OBJ_ANIM_OVERSHOOT = 1.35`（「甩过头再落定」），
  `raise` / `slide` 用 1.15（轻轻到位）。
  时长 `DEFAULT_OBJ_ANIM_TIME = 0.22 s` —— **比小人走一格更长**，看得清。
- 过渡期间 `row`（深度键里的行）用 **raw 线性插值**而不是过冲插值 ——
  否则过冲那一下会把木头`甩`到隔壁行去，前后遮挡会跳。
- 扬尘 `M.spawnDust(c, r, scale)`：撞倒 `1.5`（重）/ 立起·侧推 `0.85`（轻），
  时长 `0.34 s`、初始直径 `0.62` 格、峰值 alpha `150`；
  推进时 `grow = 1 + 0.85 * smoothstep(k)`、alpha 按 `(1-k)²` 衰减。
  颜色 `dust E9DCBE` 刻意选**偏沙色** —— 压在绿草和青蓝海面上都读得出来。

```lua
base.animFrom = { c = qc, r = qr, stand = true }   -- 起点形态（stand = 立姿）
base.animTo   = { c = fc, r = fr, dir = key }      -- 终点形态
```

它们是**纯表现信息**，规则层不读 —— 所以玩法行为与第 5 批逐字节等价。
`game.tryMove` 里挂接：

```lua
if act.changed then
    level.setObjectAnim(act)      -- ★ 先登记过渡，再重建
    level.rebuildObjects()
end

    if kind == "knock" then level.spawnDust(act.animTo.c, act.animTo.r, 1.5)
```

## 5. 为什么 / 关键设计决定

1. **为什么不直接把树干画「小一点」** ——
   倒 / 立的对比要靠**多个维度同时作用**才稳。只改尺寸，在 34 px 的格子上会被抗锯齿糊掉；
   加上「亮边 vs 暗边」「竖切面 vs 横切口」「土堆」三组线索之后，**缩略图尺寸下也能读出来**。
2. **为什么代理池挂在世界容器** ——
   2.5D 的立体感全靠绘制顺序（`band + row*10 + sub`）。代理如果不进排序，
   落地那一瞬间会被前后行的地块盖住。
3. **为什么 `stand` 用「存在且为真」判立姿** ——
   `shapeOf(spec)` 里写的是 `if spec.stand then ... end`，
   所以「起点是立着的树」必须写 `stand = true`，`false` 和 `nil` 都会走躺姿。
   这条约定统一之后，`animFrom` / `animTo` 两个字段就两种写法，不容易写错。
4. **为什么不改 `world.lua` 的规则** ——
   用户要的是「对比更明显」，不是「玩法变了」。规则一动，三关最短解就得重算、
   e2e 口令就得重写、玩家手感也会变。**表现改动要能和玩法改动完全解耦**，
   所以过渡信息做成 `M.step()` 的**附加返回值**，旧调用方不读它也不受影响。

## 6. ⭐ 顺带修掉的一个真 bug（在 `_tools/test_editor_roundtrip.mjs` 里）

`_tools/test_editor_roundtrip.mjs` 原本有一行：

```js
globalThis.URL = { createObjectURL: () => '', revokeObjectURL: noop };
```

它把 Node 的 `URL` **构造器**整个换成了普通对象。Node 的文件系统垫片内部要做
`filePath instanceof URL`，一旦 `URL` 不是函数，`fs.readFileSync` 就抛
`TypeError: Right-hand side of 'instanceof' is not callable` —— **每次运行都必现**（在「全部 OK」之后崩）。

排查过程：先写最小复现脚本读一个非 ASCII 路径 → **正常**，说明不是路径编码问题；
再读测试源码定位到那一行；确认 `编辑器.html` 里 `URL` 只出现在「下载」按钮的 `click` 处理里
（本测试不会触发），于是**只补两个方法、保留构造器**：

```js
if (typeof globalThis.URL === "function" && !globalThis.URL.createObjectURL) {
    globalThis.URL.createObjectURL = () => "";
    globalThis.URL.revokeObjectURL = noop;
}
```

修完 `exit=0`，末尾正常打印「===== 往返自检：全部通过 =====」。

> 📌 这是**测试脚本自己的 bug**，与被测的 `编辑器.html` 无关，
> 但它会让「往返自检」这条防线**永远假失败**，所以必须一起修。

  木头顶多推一格，小人却原地不动，会把玩家卡在「推了但没上岛」的别扭状态。
  补上后「推」和「撞倒 → 顺势前挪」的体感一致。

> ★ **`DEFAULT_MAX_STEP = 0.25` 是这套改版的关键**：只有它 ≤ 0.25，
> 「树根 0.25 可踩 / 树干压地 0.5 不可踩」这条分界线才成立 ——
> 而这条分界线正是「撞倒 → 树干落水 → 踩过去」这条解法的支点。
>
> ★ **同一个「倒下的树」有两个高度**，按脚下是水还是陆地取：
> 漂在水上是 0.25（可踩 = 桥），压在陆地上是 0.5（跨不上 = 只能推）。
> 判定只有一处：`world.logHeightAt()`。

### 5.3 「木桩 / 立桩」概念被删掉了

老版本里 `stumps`（木桩）和 `stumpStanding`（立起的木桩）是**独立于树木**的物体。
新规则下 **立着与躺下只是同一棵树的两个状态**：

- 立着 → 存在 `state.trees`（1 格高）；
- 躺下 → 存在 `state.logs`（占一格，带 `dir` 说明躺向）。

所以 `world.lua` 里删掉了 `logIndexOf` / `logOnLand` / `logHeight` / `M.stumps`，
`step()` 里原来那套「先判能否踩上木桩，再判是否从端面推木桩」被合并进新的判定链：

```
撞树 → 能踩就踩 → 踩不上且目标格是倒下的树（正面立起 / 侧面滑一格）→ 石头 → 水 / 太高
```

三条必须如此的顺序理由（都写在 `world.step()` 的注释里）：

1. **「能踩就踩」排在「推」前面**：树干漂在水里时顶面 0.25，要直接走上去（这就是过水道）；
   压在陆地上时是 0.5，跨不上，才会落到「推」。同一个物体两种行为，差别全在脚下的水陆。
2. **「撞树」排第一**：立着的树永远 1.0 格高、永远跨不上去，所以只能撞、或者是由推倒的树干立起来。
3. **树根不算占位**（`world.isFree` 不看树根）：撞完原地留 0.25 的树根，木头可以直接盖在它上面，
   于是「推着树干滑过一处树根」是合法的。

### 5.4 关卡全部重设（`config.lua` 的 `M.LEVELS`）

三关共用同一张 22×13 地图，**岛间只隔 1 格水**（第 14 列），靠树 / 树干的位置与躺向分难度：

| 关 | 名字 | 教什么 | 最短解 | 步数 |
| --- | --- | --- | --- | --- |
| 01 | 起点草地 | **撞倒**：`(13,4)` 的树紧挨水道，朝右撞 → 树干落进 `(14,4)` | `DDDDDDDSSSDDDD` | 14 |
| 02 | 侧着推 | **侧面推**：`(11,5)` 预置南北向树干堵路，朝右推三次 → 滑进 `(14,5)` | `SDDDDDDDDDDSSDDDD` | 17 |
| 03 | 立起来的树 | **正面推**：`(12,5)` 预置东西向树干，朝右推 → 在 `(13,5)` 立起来 → 再撞倒进水道 | `SDDDDDDDDSSDDDD` | 15 |

三条口令都是 `_tools/solve_浮岛借木.py` 的 **IDA\* 搜出来的最短解**，不是手编排的；
脚本内置这三条做 `BUILTIN` 自检，并会告警「内置口令步数 ≠ 最短解步数」。

> 为什么用 IDA\* 而不是 BFS：**每推一次树干就多一个树根**，状态空间持续发散，BFS 撑不住。
> 改成「到终点的曼哈顿距离」当启发式 + 按剩余预算剪枝即可秒出。

### 4. 改了什么、为什么、怎么验证

#### 4.1 `_shared/_check_refs.py`（新增两节校验）

**为什么**：浮岛借木把「元件索引」拆成了三处同源——
`config.DEFAULT_PREFAB_*` ↔ `_tools/_sim_common.mjs` 的 `SIM_TEMPLATE_GUIDS`
↔ `_tools/qxqy_simsave.mjs` 的 `GUID_*`，
再加一份 `编辑器.html` 的 `DEFAULTS` 要跟 `config` 逐项一致。
这四份东西分散在四个文件，**手改必漂移**，所以做成自动校验。

**验证**：见 §6（这条是整批最有力的实证）。

#### 4.2 `_tools/_sim_common.mjs` / `qxqy_simsave.mjs`（模板 GUID 2 → 8 项）

**为什么**：模拟器原来只有 `rectPrefabId=2000001`、`textPrefabId=2000002` 两个自造 GUID。
真机内置模板的实际索引是 `1073741876`（容器节点）… `1073741886`（人物），
存档里要按**真机索引**建模板，模拟器才能等价复现真机行为。现在 8 项齐全：

| 真机索引 | 元件 | 模拟器键 |
| --- | --- | --- |
| `1073741876` | 容器节点 | `containerPrefabId` |
| `1073741894` | 图片·矩形（纯色底图首选） | `rectPrefabId` |
| `1073741870` | 图片（纯色底图回退） | `imagePrefabId` |
| `1073741868` | 文本框 | `textPrefabId` |
| `1073741879` | 图片·海水 | `waterPrefabId` |
| `1073741881` | 图片·草地 | `landPrefabId` |
| `1073741883` | 图片·树木 | `treePrefabId` |
| `1073741886` | 图片·人物 | `playerPrefabId` |

#### 4.3 `_tools/qxqy_mount.mjs`

**为什么**（三条独立的修复）：
1. **params 链路是断的** —— 脚本参数传不到工程里，靠 `buildParamShim` 兜底；
2. **按键注入**原来只能指定固定帧，现在支持逐键 `--key Foo@40`；帧号以引擎真实帧为准
   （默认先冻结实时钟），否则截图时机对不上；
3. **新增 `--probe-walk <帧>`**：打印控件名。这条是给「两个纯色底图模板模拟器渲染成同一张白矩形」
   准备的分辨手段 —— 只能靠控件名（`SIM_矩形` / `SIM_图片_回退`）区分，不能靠截图。

#### 4.4 新增的 4 个工具脚本

- `e2e_浮岛借木.sh`：把三关解法 + A/B + 提示 + 探针 7 轮串成一条命令，
  判据是**挂载无错**与**底图模板控件总数一致**。
- `preview_art_浮岛借木.py`：**这是本轮最重要的新增工具**。
  模拟器只代理 `100001–100006` 六个图源，画不出真美术，
  所以「素材有没有严丝合缝压在格子上」必须**离线**看。它从 `config.lua` 解析调色板 /
  `ART_FIT` / 关卡数据，用与 `level.lua` **同一套几何**渲染，输出 PNG。
  ⚠️ 改 `level.lua` 的几何后必须同步它，否则它会说假话。
- `make_grass_tile.py`：⚠️ 背景是**踩过的坑** —— AI 生成图把 `grass tile` 理解成等距菱形，
  铺到正交网格上是一片菱形格纹，调参救不回来。改为**程序化生成方形顶面**，
  并内置平铺自检（格内亮度极差 < 8，防止瓦片自带渐变变成条纹）。
- `make_compare_浮岛借木.py`：生成 A/B 对照图。
