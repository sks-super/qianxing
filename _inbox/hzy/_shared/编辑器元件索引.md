# 编辑器元件索引（真机内置模板）

> **来源**：用户在千星沙箱编辑器「客户端控件模板列表」中实测取得的元件索引。
> 这些数值由官方固定，**不可自行更改**；工程只把它当「缺省回退值」用。

> （`ClientUIImageControl`），差别只在它**自带一张矩形图元**：脚本照样用 `imageColor` 染色，

> 与「容器节点」是同一个索引。
>
> **它有两个用途，别混**：
> 1. **脚本宿主**：`game.lua` 挂在编辑器里那个容器节点上，`script.object` 就是它；
> 2. **分层容器模板**：`createContainer()` 用 `InstantiateClientUIControl(1073741876, parent)`
>    创建各工程的层级容器（**数量随工程而定**：`浮岛借木` 5 个 —— 2.5D 之后地形/物体/小人

>    容器节点不绘制图形、不需要图源，天生就是拿来组织子控件的，
>    比拿「图片」元件当父节点干净（图片元件真机没配图会画成 `?` 占位框，`alpha=0` 虽然看不见，
>    但白占一层渲染）。老存档里没有容器模板时，`createContainer()` 会自动回退用矩形元件。

## 二、纯色底图的两级回退（矩形 → 图片）

全部纯色图形（沙滩 / 木桩 / 立桩 / 树根 / 石头 / 终点旗 / HUD 底衬 / 涟漪 / 黑幕）
都是「一块被 `imageColor` 染色的图片控件」。用哪个元件当这块底图，是两级：

| 优先级 | 元件 | 索引 | 特点 |
|---|---|---|---|
| ① 首选 | **矩形** | `1073741894` | 自带矩形图元 → 染出来就是干净纯色块，**真机不需要配图** |
| ② 回退 | 图片 | `1073741870` | 官方内置、任何存档都有；但**默认不带图源**，真机会画成彩色 `?` |

判断与回退**只有一处**：`utils.instantiateRect(parent)`。
所有纯色底图的创建都必须经它（或经 `utils.createControl`），**不要自己裸调
`game.InstantiateClientUIControl`** —— 那样就绕过了回退，存档里没有「矩形」时直接建不出来。

```
utils.instantiateRect(parent)
  → 先试 state.rectPrefabId（矩形）
     └ 拿到控件 → 返回 (ctrl, 矩形索引)
  → 再试 state.imagePrefabId（图片）
     └ 拿到控件 → 返回 (ctrl, 图片索引)
  → 都拿不到 → (nil, 0)，调用方跳过（不会崩、也不会空白）
```

- 脚本参数：`rectPrefabId`（首选）/ `imagePrefabId`（回退）；
  对应 `config.DEFAULT_PREFAB_RECT` / `config.DEFAULT_PREFAB_IMAGE`。
- 为什么还要留「图片」这一级：`1073741894` 是**用户自建**的元件，
  换个存档、换个人做工程就可能不存在；而 `1073741870` 是官方内置模板，永远都在。
- 硬约束：`rectPrefabId` 若被填成 0，`game.lua` 会先把它抬回 `DEFAULT_PREFAB_IMAGE`
  （保证「必填项」始终有值），再由 `instantiateRect` 走两级。

## 三、美术素材元件（海水 / 草地 / 树木 / 人物）

这 4 个元件和「通用矩形」**分工不同**：它们里面**已经关联好美术素材**。

| 元件 | 索引 | 覆盖范围 | 尺寸 |
|---|---|---|---|
| 海水 | `1073741879` | 整屏海面底（bg 层） | 画布 + 800（溢出一圈，防边缘露底） |
| 草地 | `1073741881` | 棋盘里逐格陆地 | 1 格 × 1 格 |
| 树木 | `1073741883` | 撞断前的立树 | 1 格宽 × 2.5 格高 |
| 人物 | `1073741886` | 小人本体 | 1 格宽 × 2 格高 |

### ⚠️ 铁律：素材元件**一律不写 `imageColor`**

`imageColor` 是**乘法染色**。往自带美术的元件上写一遍颜色，素材就被乘成暗色 / 怪色。
所以 `level.lua` 对这四个槽位的控件**只设位置和尺寸，绝不碰 `imageColor`**。

代码里靠「槽位」表达这件事（`level.lua`）：

```
makeSlot(prefabId)  →  { prefab = <素材元件>, art = true }     ← 素材：不染色
rectSlot()          →  { prefab = <矩形元件>, art = false }    ← 纯色底图：按调色板染色
```

`art` 只在控件**建出来的那一刻**确定：

- 素材元件拿到了控件 → `art = true`，之后只改位置尺寸；
- 素材元件**拿不到**控件（老存档没这几种元件 / 索引写了 0 / 总开关关了）
  → 当场回退成通用矩形，`art = false`，并按 `DEFAULT_PALETTE` 染色。

所以**不会出现整片空白**：任何情况下都有一张能看的画面。

### 想退回「纯色渲染」怎么办

三档，任选：

| 做法 | 效果 |
|---|---|
| 脚本参数 `useArt = 0` | 四类一起退回通用矩形 + 调色板染色（= 加入素材前的老画面） |
| 把对应 `DEFAULT_PREFAB_*` 改成 `0` | 只退某一类 |
| 什么都不做（元件不可用） | 自动回退，行为同上 |

### 模拟器里怎么看

模拟器没有真机素材。`qxqy_simsave.mjs` 给这 4 个模板**预置了代表色**
（取自 `config.DEFAULT_PALETTE`：水 `2B8FA4` / 草 `6DB03C` / 树 `2F6B3A` / 人 `F2A03C`），
游戏又不写 `imageColor`，于是预置色原样留在控件上 →
**模拟器截图依旧有画面可比对**，搬到真机后显示的才是元件自带的美术。

> 换句话说：模拟器里看到的是「一个水色的方块」，真机上看到的是「海水美术」。
> 位置、尺寸、层级两边完全一致，只有贴图不同。

## 四、⚠️ 图片元件的「图源」（真机出现「?」缺失框时看这里）

> **先看这一句**：现在纯色底图的**首选是「矩形」元件**（自带矩形图元），正常情况下
> **不会**出现彩色 `?`。这一节只在两种情况才用得上：
> ① 存档里**没有**「矩形」元件、脚本回退到了官方「图片」元件；
> ② 你自己把 `rectPrefabId` 指到了别的图片元件上。
> 想确认到底走的哪条路：跑一次 `--probe-walk`，看快照里的控件名是
> `SIM_矩形` 还是 `SIM_图片_回退`（模拟器侧的名字，见 `qxqy_simsave.mjs`）。

**症状**：脚本加进千星奇域后，画面全是彩色的 **`?`** —— 位置、尺寸、`imageColor`
染色全都对，但每个图片控件都是缺失占位框。

**根因**：千星的图片控件，**图源是元件属性**：

- `imageSource` / `imageId` 都是**只读字段**，脚本读得到、写不了；
- 脚本只能用 `SetImage(imageSource, imageId)` 在运行时覆盖；
- 元件本身没配图 → 真机就画成缺失框 `?`（染色仍然生效，所以你看到的是**彩色的 `?`**）。

**为什么模拟器里看着一切正常**：模拟器**只代理** `100001–100006` 六种基础图元
（`100001` 矩形 / `100002` 圆 / `100003` 等腰三角 / `100004` 四角星 / `100005` 五角星 /
`100006` 圆环），其余 `imageId` 一律显示缺失框。这是**代理图形，不代表官方素材**，
真机不认这些 ID。所以「模拟器跑通」推不出「真机画面对」。

> 也就是说：模拟器里那个漂亮的纯色矩形，是模拟器拿矩形代理画出来的；
> 真机那边如果元件没配图，就是 `?`。

**两条修法（任选其一）**

| 方案 | 做法 | 适用 |
|---|---|---|
| **A. 改元件**（推荐） | 编辑器里选中那个「图片」元件 → 给它指定一张**纯白图**。配一次，整局所有格子/装饰/角色/HUD 底衬都能正常染色 | 元件是复用的，一劳永逸 |
| **B. 改脚本** | 把图库里图片的**真实 ID** 填进脚本参数 `rectImageId`，脚本会在创建每个矩形控件后调 `SetImage(Enum.ImageSource.StaticReference, id)` | 不想动元件、或同一元件要用不同图 |

`rectImageId` 为 `0`（默认）时脚本**不碰图源**，沿用元件自带配置 —— 所以不填不影响现有行为。

**注意**：图源必须在 `imageColor` **之前**设置，`SetImage` 会清掉之前的 tint。
`utils.createControl` 已按这个顺序写好，改这块时别调换。

## 五、怎么用

### 1. 编辑器里搭场景（一次性）

1. 新建「客户端控件容器」→ 它的元件索引就是 **`1073741876`**（容器节点）。
2. 把 `game.lua` 挂到这个容器节点上，其余 `.lua` 模块依次粘贴。
3. **脚本参数可以全部留空** —— 见下。
4. 「矩形」元件 `1073741894` 已经自带你需要的矩形图元，**不用再配图**。
   （只有在**没建**矩形元件、脚本回退到官方「图片」元件时，才需要给「图片」配一张纯白图，
   否则那些纯色块在真机上会变成彩色 `?` —— 见第四节。）

### 2. 脚本参数 vs 内置索引

脚本参数（`rectPrefabId` / `textPrefabId` / `fruitPrefabId` …）**优先级更高**：
只有参数没配（nil / 0 / 非数字）时，才会回退到本文件的索引。

| 脚本参数 | 回退索引 | 回退到 |
|---|---|---|
| `rectPrefabId`（浮岛借木） | `1073741894` | **矩形**（全部纯色图形的构建基础） |
| ↳ 它的回退 | `1073741870`（`DEFAULT_PREFAB_IMAGE`） | 图片（矩形拿不到控件时顶上来，见第二节） |
| `imagePrefabId`（浮岛借木） | `1073741870` | 图片（就是上面那一级回退，可单独覆盖） |
| `rectPrefabId`（浮岛方块 / TickHop） | `1073741870` | 图片（**这两个工程还没接矩形元件**，行为不变） |
| `textPrefabId`（浮岛方块 / TickHop / 浮岛借木） | `1073741868` | 文本框 |
| `containerPrefabId`（割绳子 / TickHop / 浮岛借木） | `1073741876` | 容器节点（缺失时再回退到 `rectPrefabId` / `fruitPrefabId`） |
| `waterPrefabId`（浮岛借木） | `1073741879` | 海水素材（缺失时回退矩形 + `palette.water`） |
| `landPrefabId`（浮岛借木） | `1073741881` | 草地素材（缺失时回退矩形 + `palette.land` 棋盘格） |
| `treePrefabId`（浮岛借木） | `1073741883` | 树木素材（缺失时回退矩形：树干 + 树冠） |
| `playerPrefabId`（浮岛借木） | `1073741886` | 人物素材（缺失时回退矩形：身体 + 头） |
| `useArt`（浮岛借木） | `1` | 总开关：`0` = 上面四类美术一起退回纯色矩形 |
| `fruitPrefabId`（割绳子） | `1073741870` | 图片 |
| `textboxPrefabId`（割绳子） | `1073741868` | 文本框 |

> 于是「什么都不配直接运行」也能跑起来；想换成自己的美术元件时，再往参数里填自定义索引即可。

## 六、落地位置

| 位置 | 作用 |
|---|---|
| `<游戏>/config.lua` 的 `DEFAULT_PREFAB_RECT` | 纯色底图**首选**：矩形元件 |
| `<游戏>/config.lua` 的 `DEFAULT_PREFAB_IMAGE` | 纯色底图**回退**：图片元件 |
| `<游戏>/config.lua` 的 `DEFAULT_PREFAB_*` | 其余部署常量（文本框 / 容器节点 + 4 个美术素材元件） |
| `<游戏>/config.lua` 的 `DEFAULT_USE_ART` | 素材总开关（`1` = 用素材元件） |
| `<游戏>/config.lua` 的 `DEFAULT_RECT_IMAGE_ID` | 纯色底图图源的缺省值（`0` = 不改） |
| `<游戏>/game.lua` 的 `getParamNumber(name, config.DEFAULT_PREFAB_*)` | 缺省回退 |
| `<游戏>/utils.lua` 的 `instantiateRect(parent)` | **纯色底图两级回退的唯一实现**（矩形 → 图片）。别绕过它 |
| `<游戏>/utils.lua` 的 `applyImage(ctrl, imageId)` | 运行时 `SetImage`（`imageId<=0` 时不动） |
| `<游戏>/utils.lua` 的 `createControl` | 传 `state.rectPrefabId` 时自动走两级回退；创建后补图源，**在染色之前**；`color = nil` 时不写 `imageColor`（素材元件走这条） |
| `<游戏>/level.lua` 的 `makeSlot` / `rectSlot` / `poolGet` | 视觉槽位：素材优先、失败当场回退矩形，`art` 决定要不要染色 |
| `<游戏>/game.lua` 的 `createContainer` | 优先用容器节点创建；回退分支也走 `instantiateRect` |
| `<游戏>/fadeScreen.lua` 的 `init` | 走 `instantiateRect`，再单独补图源 |
| `_tools/_sim_common.mjs` 的 `SIM_TEMPLATE_GUIDS` | 模拟器模板 guid，与真机索引**对齐同源**（含 `rectPrefabId` / `imagePrefabId` 两级） |
| `_tools/qxqy_simsave.mjs` 的 `GUID_*` / `COLOR_*` | 生成模拟器就绪存档时写入的模板 guid（纯色底图两个模板：`GUID_RECT` / `GUID_IMAGE`）与素材模板的**预置代表色** |
| `_shared/_check_refs.py` 第 7 节 | 自动校验「config ↔ 模拟器 guid」不许漂移 |

### ⚠️ 八条约定

1. `config.lua` 里的名字统一是 `DEFAULT_PREFAB_*` / `DEFAULT_RECT_IMAGE_ID`；
   `_check_refs.py` 第 6 节只做「编辑器 `DEFAULTS` → `config.DEFAULT_*`」**单向**校验，
   因此这几项**不需要**镜像进 `编辑器.html`。它们是部署常量，不是关卡设计参数，
   **不要**往 `DEFAULTS` 里塞。
2. 模拟器的模板 guid 必须与真机索引保持一致，否则会出现
   「模拟器里跑得好好的、搬进真机却要另填参数」的错位。
   改这里要同时改 `_sim_common.mjs` 与 `qxqy_simsave.mjs`，重新生成就绪存档，
   再跑 `_check_refs.py` 第 7 节确认三处没漂移。
3. 以后**新增任何绕过 `utils.createControl` 的矩形控件创建点**，都要顺手补一次
   `utils.applyImage(ctrl, state.rectImageId)`，否则那一处会在真机上留下 `?`。
4. **新增模板要挂到 `client.root.children` 才会被注册**（`registerTemplate(prefabIndex = node.guid)`）。
   容器模板必须「先取原型、后 push 模板」—— 否则 `kind==='container'` 的查找会命中模板自己，
   把模板根清空的步骤就会清错节点。
5. **自带美术的素材元件，任何地方都不要写 `imageColor`。**
   要给它加效果（淡入淡出之类）只能用别的办法，别指望用染色；
   一旦有人为了「统一配色」给素材元件补一次染色，美术就会整体变暗。
   新增素材元件的完整动作是三处：
   `config.DEFAULT_PREFAB_<名>` + `_sim_common.SIM_TEMPLATE_GUIDS` + `qxqy_simsave.GUID_<名>`
   （还要在 `qxqy_simsave.mjs` 里 `makeRectTemplate` 建一个带代表色的模板），
   最后跑 `_check_refs.py` 第 7 节确认没漂移。
6. **纯色底图只有一个入口：`utils.instantiateRect`（矩形 → 图片两级）。**
   以后新增任何创建纯色底图的地方，都要经它（或经会调用它的 `utils.createControl`），
   **不要**自己 `pcall(game.InstantiateClientUIControl, state.rectPrefabId, ...)` ——
   脚本参数里的索引、以及「存档里没有矩形元件」这件事，只有那一个函数知道怎么处理。
   离它越远，越容易在真机上建不出控件或留下 `?`。
   需要单独补图源时，再顺手补一次 `utils.applyImage(ctrl, state.rectImageId)`。
7. **改「矩形 / 图片」这两个索引要动四处**（都属于第 2 条那个三处同源体系的延伸）：
   `config.DEFAULT_PREFAB_RECT` + `config.DEFAULT_PREFAB_IMAGE`
   + `_sim_common.SIM_TEMPLATE_GUIDS` 的 `rectPrefabId` / `imagePrefabId`
   + `qxqy_simsave.mjs` 的 `GUID_RECT` / `GUID_IMAGE`（两个模板都要建，并重新生成就绪存档）。
8. **同级绘制顺序不要靠创建顺序，要显式点名**：对象池复用会打乱「池下标 ↔ 创建顺序」，
   而 `buildZOrderFix` 的启发式重排在子节点数变化时会整段翻转。
   做 **2.5D** 视角时还有一条更强的约束 —— **地形 / 物体 / 小人必须在同一个容器里**，
   否则没法用同一套 `SetAsLastSibling` 做跨池的全局排序（「近处一行压住远处一行」靠的就是它）。
   `浮岛借木` 的做法：每个控件带一个深度键 `band + row * 10 + sub`，
   由 `M.restackWorld()` 一次性按 key 升序点名，并把该容器登记进 `state.selfOrderedContainers`
   让模拟器放手。原理与三个必踩的调参坑见 `浮岛借木/README.md` §5.5。
