# 浮岛借木 · 千星奇域客户端 Lua 工程

一根木头，一座浮岛，一片海。

玩家操作一个**一格高**的小人，在群岛之间**撞树、把倒下的树干推来推去**，
用树干填补岛屿之间**一格宽**的水道，一路走到终点旗 —— 灵感与玩法原型见
《怪兽远征 / A Monster's Expedition》，关卡布局按用户提供的实机截图复刻。

**视角是 2.5D 的**（见 §5.5）：正交方形网格 + 每块陆地自带厚度侧面 + **近处一行压住远处一行**。
参考图里那点立体感不是靠旋转或投影算出来的，而是**绘制顺序**做出来的。

- **挂载位置**：客户端控件容器的「容器节点」（`script.object` 即父节点）
- **运行环境**：千星沙箱客户端 UI 脚本（Lua 5.3，无 `io` / 无 `os`）
- **零配置可跑**：不填任何脚本参数时，回退到编辑器里的「容器节点」`1073741876`、
  「矩形」`1073741894`、「图片」`1073741870`（回退用）、「文本框」`1073741868`、
  「海水」`1073741879`、「草地」`1073741881`、「树木」`1073741883`、「人物」`1073741886`

## 2. 规则

单位：**1 格**。小岛地面 = `0`；小人高 **1 格**；整棵树高 **1 格**。

### 2.1 高度模型（`config.lua` 的 `DEFAULT_H_*`）

| 物体 | 顶面高度 | 说明 |
|---|---|---|
| 草地 / 小岛 | `0` | 基准面 |
| 树根 | `0.25` | 撞倒树木后原地留下，**可踩** |
| 倒下的树 · 压陆地 | `0.5` | 半格高 —— **跨不上去，只能推** |
| 倒下的树 · 漂水面 | `0.25` | 半浸在水里，与树根同高，**可踩（就是桥）** |
| 立着的树 | `1.0` | 撞不倒就过不去；撞倒它 = 规则 1 |
| 石头 · 一格 / 两格高 | `1.0 / 2.0` | 不可移动、不可攀爬 |

> **小人每次只能向上跨 `DEFAULT_MAX_STEP = 0.25` 格（四分之一格），下落不限高度。**
> 这条 `0.25` 是整个玩法的支点：0.25 格高的树根刚好能踩上去，
> 而半格高的树干（压陆地）就跨不上了 —— 于是「推它」成了唯一选择。
>
> 同一个高度值写了两遍：`world.logHeightAt()` 按脚下是水还是陆地返回 `H_LOG_LAND` / `H_LOG_FLOAT`，
> 树干漂到水里就从「半格障碍」变成「四分之一格台阶」。

### 2.2 六条规则

1. **撞树**：小人朝**立着的树**移动 → 树朝该方向倒下，**占住前方那一格**（不是原地），
   原地留下 **0.25 格树根**。前方那格被挡住或越界时，撞不动。撞完若脚下抬升不超过 `0.25`，
   小人会**顺势往前挪一步**站到树根上。
2. **踩过去**：前方顶面 − 脚下高度 ≤ `0.25` 就能走上去。
3. **侧面推树干**：前方是倒下的树、推的方向**垂直于**它躺着的方向 → **整根滑一格**，躺向不变。
4. **正面推树干**：前方是倒下的树、推的方向**平行于**它躺着的方向 → 树干在**前方那一格原地立起来**
   （又变回一棵树，可再撞倒；也可以先绕过它）。
5. **石头**：不可移动、不可攀爬，挡住去路，得换方向。
6. **胜利**：小人所在格 == 终点格。

> 树干「站立 ↔ 躺下」是**同一棵树的两个状态**，没有独立的木桩 / 立桩概念：
> 立着 = 1 格高（`trees`），躺下 = 一个占一格的 `logs` 项（带 `dir` 说明躺向）。

### 2.3 判定优先级（`world.step()` 里的实际顺序）

```
撞树 → 能踩就踩 → 踩不上且目标格是倒下的树（正面立起 / 侧面滑一格）→ 石头 → 水 / 太高
```

三条容易踩坑、但必须如此的设计：

- **「能踩就踩」排在「推」前面**。倒下的树漂在水里时顶面只有 `0.25`，直接走上去（这就是过水道）；
  压在陆地上时是 `0.5`，跨不上，才会落到「推」那个分支。**同一个物体，两种行为**，
  差别全在脚下的水陆。
- **「撞树」排在第一步**。立着的树永远 `1.0` 格高，永远跨不上去，所以只能是撞、或者是推倒的树干立起来。
- **树根不算占位**。撞完原地留 `0.25` 的树根，木头可以直接盖在它上面（`world.isFree` 不看树根），
  所以「推着树干滑过一处树根」是合法的。

## 4. 关卡与解法

三关共用同一张 22×13 的群岛地图，**岛与岛之间只隔 1 格水**（第 `14` 列那条水道），
靠**树 / 树干的位置与躺向**改变谜题。三关是一条教学梯度：

| 关 | 名字 | 教什么 | 解法口令 | 步数 |
|---|---|---|---|---|
| 01 | 起点草地 | **撞倒**：(13,4) 的树紧挨水道，朝右撞 → 树干正好落进 `(14,4)` 水里 | `DDDDDDDSSSDDDD` | 14 |
| 02 | 侧着推 | **侧面推**：(11,5) 预置一根南北向树干堵路，朝右推三次 → 整根滑进 `(14,5)` | `SDDDDDDDDDDSSDDDD` | 17 |
| 03 | 立起来的树 | **正面推**：(12,5) 预置一根东西向树干，朝右推 → 在 `(13,5)` 立起来 → 再撞倒进水道 | `SDDDDDDDDSSDDDD` | 15 |

**解法是怎么验的**：`_tools/solve_浮岛借木.py` 是规则的 **Python 参考实现**，
用 **IDA\*** 搜出每关的**最短解**，并把三关口令作为 `BUILTIN` 回填做自检：

```bash
python _tools/solve_浮岛借木.py                 # 高度模型 + 每关概览 + 内置口令自检 + 地图字符画
python _tools/solve_浮岛借木.py --trace DDDDDDDSSSDDDD    # 逐步回放某条口令
```

> ⚠️ 改关卡数据 / 改规则后**必须重跑它**：脚本会打印「内置口令步数 ≠ 最短解步数」的告警，
> 那说明关卡已经不是你以为的那个最优解了，`_tools/e2e_浮岛借木.sh` 里的期望步数也要跟着改。
>
> 为什么是 IDA\* 不是 BFS：每推一次树干就**多一个树根**，状态空间会持续发散，BFS 撑不住；
> 用「到终点的曼哈顿距离」当启发式 + 按剩余预算剪枝即可。

**在真机同源环境里复验**：用本工作区的千星 Web 模拟器把三条口令当按键注入，逐关截图核对
（`步数 14 / 17 / 15 （已通关）`、树干落在水道那一格、小人站在终点旗上）—— 见 §7。

## 5.5 2.5D 视角是怎么做的

### 参考图的真相（别做错方向）

用户给的参考图（《怪兽远征》）看起来像等距投影，但**不是**：

- 水面网格线是**屏幕水平 / 垂直**的 → 说明是**正交网格**，不是旋转 45° 的菱形网格；
- 岛缘是**直角台阶**（横平竖直的折线）→ 没有斜边，没有投影数学。

那点立体感来自两件事：

1. **每块陆地有厚度**：顶面之下挂一条侧面（土色），再下面是落进水里的投影；
2. **近处一行压住远处一行**：行号大的（画面上更靠下 = 更近）画在后，盖住上一行的下沿。

→ 结论：**不需要旋转控件、不需要投影矩阵**，只需要一个正确的**绘制顺序**。

### 深度键（depth key）

同一容器里的所有控件按一个数值键排序，键 = `band + row * 10 + sub`：

| band | 内容 | sub 细分 |
|---|---|---|
| `0` | 水面网格线 | 竖线 0.1 / 横线 0.2 / 旧棋盘 0.3 |
| `1000` | 地块装饰（投影 / 侧面 / 沙滩描边） | 0.1 / 0.2 / 0.3 |
| `2000` | 草地顶面 | 0.5 |
| `3000` | 物体与小人 | 阴影 −0.5 / 树根 1 / 倒下的树 2 / *3 空着* / 石头 4 / 树木 5 / 旗 6 / 小人 7 |

> `sub = 3` 是**空出来的**：老版本那里是「立起来的木桩」，现在立着与躺下只是同一棵树的两个状态，
> 序号留着不动，免得以后加物体时误以为可以随便挪。

**`row` 是主序**：行号越大越靠前、越晚画。所以「近处一行压住远处一行」是自动成立的。

### 三条硬约定

1. **地形 / 物体 / 小人必须在同一个容器（`containerWorld`）里**，否则没法用同一套
   `SetAsLastSibling` 做全局排序。5 个容器是
   `containerBg` → `containerWorld` → `containerFx` → `containerHud` → `containerFade`。
2. **岛缘轮廓一律由脚本画，不依赖素材**。所以「素材路径」与「纯色路径」的**岛形逐像素同源**，
   换素材只影响顶面。地形分两趟画，顺序不能倒：
   - **装饰趟**（先整趟画完）：投影 → 侧面厚度 → 沙滩描边
   - **顶面趟**：素材立绘 / 纯色棋盘

   > ⚠️ 如果按「一格画完再画下一格」，岛内相邻格之间会**露出描边**，看起来像带缝的地砖。

3. **侧面挂在沙滩描边的下沿**，不是格子下沿。描边是顶面的一圈边、侧面是板块的厚度，
   两者上下相接才读得出「一块有厚度的地」；挂在格子下沿会被描边压掉大半。

### 调参时的三个坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 岛缘看不出厚度 | 落水投影太重，把侧面盖住了 | 调低 `tileShadowAlpha`（默认 54，别往上调） |
| 描边与侧面糊成一条浅色带 | `soil` 和 `sand` 颜色太接近 | 拉开距离（现为 `AB8B55` vs `E6D69C`） |
| 草地上出现等距横条纹 | 草地素材里有「上亮下暗」的竖向渐变，平铺后每格顶部更亮 | **瓦片内不能有自身的明暗渐变**；`_tools/make_grass_tile.py` 自带平铺自检 |

> 物件脚下的接触阴影用的是 `palette.shadowLand`（暗绿），**不是** `palette.waterShade`
> （深青蓝）—— 后者是岛缘落水的投影色，压在绿草上会变成一块突兀的蓝板。

## 6. 工程约定与静态校验

沿用本工作区既有的三条硬约定：

1. **`config.lua` 的 `DEFAULT_*` 是参数唯一真源**；`编辑器.html` 的 `DEFAULTS` 必须逐项数值一致。
2. **`state.lua` 必须显式声明所有 `state.*` 字段**（动态建字段会绕开集中约定，静态检查也会报）。
3. 图片控件要染色前必须先定图源（见 §8），文本控件用 **`fontColor`** 改字色（不是 `imageColor`）。

```bash
# 三道静态校验（看退出码，不看文案）
python _shared/_check_blocks.py  浮岛借木   # Lua 块平衡
python _shared/_check_refs.py    浮岛借木   # require / 模块函数 / state 字段 / config 常量 / DEFAULTS 同步
python _tools/check_lua_scoping.py 浮岛借木 # local「先用后声明」+ 死代码
```

当前结果：**9 个 Lua 文件 0 处块不平衡；DEFAULTS 全部与 config 一致；8 个元件索引三处同源；
0 处引用问题；0 处「先用后声明」。**

### 为什么还要一道 `check_lua_scoping.py`

Lua 的 `local` **从声明那一行起才可见**。把 `local PLAYER_BODY_RATIO = 0.94` 写在文件底部，
而上面的函数先用了它，Lua **不报错** —— 它把这个名字当**全局变量**读，值是 `nil`。
2026-09-30 就踩过一次：`level.lua` 静默读到 nil，前两道校验全绿，
只有真跑模拟器才炸出 `attempt to perform arithmetic on a nil value (global 'PLAYER_BODY_RATIO')`。

于是补了这道专门检查（声明来源认 `local` / 函数形参 / `for` 变量；引用排除 `p.h` 这类字段访问
和 `{ h = 1 }` 这类表键）。回归样本在 `_tools/check_lua_scoping.py` 的 docstring 里。

## 8. 三个必须知道的千星坑

1. **图片控件的图源是「元件属性」**：`imageSource` / `imageId` 都是**只读**字段，脚本只能用
   `SetImage(source, id)` 在运行时覆盖。元件没配图时真机会把控件画成缺失占位框「?」
   （`imageColor` 的染色仍然生效），而模拟器里看着正常。
   → **本工程已经不靠「图片」当纯色底了**：首选是「矩形」元件 `1073741894`，它自带矩形图元，
   真机开箱就是一块干净纯色。只有**回退**到官方「图片」元件 `1073741870` 时才会碰到这个坑，
   那时才需要：给「图片」元件配一张**纯白图**（配一次全局生效），或把图库里的真实图片 ID
   填进脚本参数 `rectImageId`。
   ★ 本工程的可视对象都是「一块被染色的纯色矩形」，所以底图只要是实心矩形就行 ——
   矩形元件正合适。
   ★ 想知道当前走的是哪条路：`--probe-walk` 看控件名（`SIM_矩形` / `SIM_图片_回退`），
   或直接 `--params '{"rectPrefabId":999999}'` 压测回退路径。

2. **两格高的石头会「盖住」上方那一格**。它高 2 格 = 视觉上填满上方格子的体积，
   但规则上只占自己那一格（`heightAt` 只看所在格）。若上方是草地，玩家会看到
   「石头挡路，但其实能走过去」的错觉。
   → `编辑器.html` 的结构自检会直接报这个错；正确摆法是让上方那格**是水**
   （像 `(16,3)` 两格高石头贴着右岛北岸那样，看起来就是一道悬崖）。

3. **`imageColor` 是乘法染色，自带美术的素材元件绝不能写。**
   引擎的同级「有序索引」是 0 = **最先绘制 = 最底层**，索引越大越靠上；
   而**创建顺序**就是默认的推入顺序，所以「后建的控件盖在先建的上」在真机上天然成立。
   ⚠️ 但**控件池会复用**，于是「池下标 ↔ 创建顺序」的对应关系会被打乱 ——
   实测出现过「树干盖住树冠、石头 / 树干的顶面被自己的侧面压住」。
   → `level.lua` 的 `M.restackWorld()` 在每次内容变化后，把 **5 个对象池 + 小人的三件套**
   收集到一起，按**深度键升序 = 由底到顶**显式点名一遍（`SetAsLastSibling`）：

   | 由底到顶 | 内容 |
   |---|---|
   | 网格线 | 水面细网格 / 旧水下棋盘 |
   | 地块装饰 | 落水投影 → 侧面厚度 → 沙滩描边 |
   | 草地顶面 | 素材立绘 / 纯色棋盘 |
   | 物体 | 接触阴影 → 树根 → 倒下的树 → 石头 → 树木 → 终点旗 → 小人 |

   每个控件带一个 `key = band + row * 10 + sub`，于是「同一行内由下到上」与
   「跨行时近处压远处」**由同一次排序同时得到**（见 §5.5）。

   `containerWorld` 在 `state.selfOrderedContainers` 里登记，模拟器的 z 序修正会**跳过**它
   （它那套「按创建序重排」在子节点数反复变化时会把整段顺序翻来翻去，朝向取决于翻转次数的奇偶）。

   > ⚠️ 小人换行之后（`M.beginPlayerMove`）必须**再调一次** `M.restackWorld()` ——
   > 小人的深度键里含行号，换了行它就可能从「挡住树」变成「被树挡住」。

## 9. 编辑器用法

浏览器直接打开 `编辑器.html`（无需服务器）：

- 左侧工具栏：草地 / 海水 / 树木 / **倒下的树** / 树根 / 石头·1格 / 石头·2格 / 出生点 / 终点旗 / 擦除
  （也可用数字键 `1`–`0` 切换）。草地与海水按住拖动可连续刷。
- **倒下的树要定「躺向」**：先点它所在的那一格，**再点相邻的另一格** ——
  两次点击的连线方向就是它的 `dir`（`W/S/A/D`），只允许水平或竖直。`Esc` 取消。
- 右侧「结构自检」实时检查：出生点 / 终点是否在陆地上、树干 `dir` 是否合法、
  两格高石头上方是不是陆地、物体与出生点 / 终点是否重叠等。
  （树干全在水上时会给一条「可当桥」的提示。）
- **导出**：生成 `M.LEVELS` 片段（可复制，也可下载 `浮岛借木.levels.lua`），落盘一行命令：

```bash
node _tools/apply_levels.mjs 浮岛借木.levels.lua --game 浮岛借木          # 写入 + 自动跑两道静态校验
node _tools/apply_levels.mjs 浮岛借木.levels.lua --game 浮岛借木 --dry    # 只看 diff 摘要
```

- **导入**：粘贴 `M.LEVELS` 片段即可反向读回（导出 → 导入 已做往返无损校验）：

```bash
node _tools/test_editor_roundtrip.mjs    # 导出→导入往返 + config.lua ↔ 编辑器内置关卡逐项比对
```

> ⚠️ 导出的表头注释里**不要**出现「`M.LEVELS` + 等号 + 左花括号」这种字面写法：
> `apply_levels.mjs` 是按大括号配平找片段的，会先命中注释里的假片段。编辑器已按这个约束写好注释。
>
> ⚠️ 编辑器（以及 `solve_浮岛借木.py`、`preview_art_浮岛借木.py`）解析 `M.LEVELS` 时都用
> **花括号配对扫描**，不用惰性正则 —— `trees = { },` 这种空表会把惰性正则一路吞到后面某个 `},`。
>
> ⚠️ 编辑器的预览画的是「纯色」那一套（等价于 `useArt = 0`），**几何与 `level.lua` 逐项镜像**
> —— 岛缘描边 / 厚度侧面 / 落水投影 / 脚线 / 水面网格线都在，只是不渲染美术贴图。
> 它的用途是**对齐网格与摆位置**；模拟器与真机按素材元件渲染（见 §7）。

## 10. 已知限制 / 可以继续加

- **视野是固定的 1280×720 逻辑画布**：格子边长按「HUD 条下沿 ↔ 消息栏上沿」之间的可用区域自动算，
  再夹到 `cell_min..cell_max`。更大的地图不在当前设计里。
- **2.5D 是「画出来的」而不是「算出来的」**：没有摄像机、没有投影矩阵，立体感全靠深度键排序
  + 每块地的厚度侧面。好处是零成本、和网格命中测试天然对齐；代价是**只能俯视这一个角度**，
  想做真正的斜视角就得换成旋转/投影方案（那时 `cellAt` 命中测试也要跟着改）。
- **没有撤销与步数上限**：`R` 直接重开本关。
- **小人只有 1 格高、最多跨 1/4 格**：所以石头（1 格）永远爬不上去，只能绕；
  这个上限是刻意的，它让「树根 0.25 可踩 / 树干 0.5 不可踩」这条分界线成立。
- **树干只能推一格**：一次推 = 一个动作 = 一步，可以连推（第 02 关就是连推三次）。
  想做「一推到底」得改 `world.step()` 的 ③ 分支。
- **没有存档 / 关卡解锁**：三关靠 `T` / `P` 直接切换，`signal.lua` 里已留好出站上报
  （`撞倒树木` / `推滑树干` / `树干立起` / `到达终点` / `关卡胜利`），接服务器进度只需在 `resolveWin()` 里补一步。
- **提示文本只读**：`DEFAULT_HINT_WRAP = 26` 是折行宽度，多条提示各占一行。
