# 信号协议 · 瓦雷莎的果园救急（客户端 ↔ 节点图）

> 客户端只做 UI；**3D 果园棋盘、点击翻转、是否全部还原、进度存档都在服务器节点图里**。
> 两边唯一的对接面是 `signal.lua`。改信号名只动该文件顶部那 5 个常量。

---

## 一、总览（5 条信号）

| # | 方向 | 信号名 | 参数（按顺序） | 时机 |
|---|---|---|---|---|
| ① | 服 → 客 | **`服客进入关卡`** | `AddInt` 关卡序号（第一关 = 1） | 节点图把这一片果园摆好了 |
| ② | 服 → 客 | **`服客关卡胜利`** | `AddInt` 关卡序号（第一关 = 1） | 3D 端判定「全部是水果」 |
| ③ | 服 → 客 | **`服客进入选关`** | 无参数 | 要求客户端回果园地图。★ **这是回地图的唯一途径**：游玩界面已无「回果园」按钮 |
| ④ | 服 → 客 | **`服客同步存档信息`** | `AddInt` **已通关的最新关卡序号**（1 基；`0` = 一片都没通关） | 进游戏 / 重连时**先发这一条** |
| ⑤ | 客 → 服 | **`客服关卡参数`** | `AddInt` 关卡序号（第一关 = 1）<br>`AddInt` 最小步数<br>`AddIntList` 点位序列<br>`AddIntList` 状态数组（30 项，`1` / `-1`） | 选关进入 / 下一关 / 上一关 / 重玩 |

> 命名读法：**服客 = 服务器 → 客户端**，**客服 = 客户端 → 服务器**。
> 参数类型顺序必须逐字一致，中文名不能带空格。

### ⑤「客服关卡参数」的触发点

四个入口发的是**同一条信号、同一份报文**（服务端只认参数，不认来路）：

| 入口 | 客户端函数 |
|---|---|
| 选关页点果实 / 按空格进入 | `enterLevel(idx)` |
| 结算面板「下一片 →」/ 键盘 `→` | `nextLevel()` → `enterLevel` |
| 结算面板「← 上一片」/ 键盘 `←` | `prevLevel()` → `enterLevel` |
| 结算面板「重玩这片」/ 键盘 `R` / 游玩中 `R` | `replayLevel()` |

#### ★ 教程关会延后到「教程关闭之后」才发

前 5 关（本局第一次进）会先弹教学卡。**这时客户端不发信号**，把关卡号存在
`state.pendingLevelParams`，等玩家关掉教程、真正露出游玩界面的那一帧
（`OnUpdate` 里的 `flushLevelParams()`）才发一条。

| 情况 | 发送时机 |
|---|---|
| 教程关、本局第一次进 | **关闭教程之后**（点「关闭/知道了」、按 `L`、按空格翻到末页都算） |
| 非教程关（第 6 片起） | 当场发 |
| 重玩（不再弹教程） | 当场发 |
| 教程还没关就回果园 | **不发**（`setScreen` 离开 `play` 时会丢弃待发值） |

对节点图**没有额外要求**：仍然是「收到参数 → 摆盘 → 回 `服客进入关卡`」，
只是这条请求会比以前晚到几十秒。`服客进入关卡` 迟迟不来客户端也不会卡死
（4 秒兜底只是用来收起「正在摆果园…」提示，计时从真正发出那一刻才起算）。

## 二、点位序列（必须先对齐）

棋盘 **5 行 × 6 列 = 30 个点位**，点位序列里每项是 **0 基一维下标**：

```
idx = 行 * 6 + 列          -- 行 0..4 从上往下，列 0..5 从左往右
                           -- idx 0..29，0 基
```

```
列 →   0    1    2    3    4    5
行 0 [  0    1    2    3    4    5 ]
行 1 [  6    7    8    9   10   11 ]
行 2 [ 12   13   14   15   16   17 ]
行 3 [ 18   19   20   21   22   23 ]
行 4 [ 24   25   26   27   28   29 ]
```

例：第 0 行第 0 列 = `0`；第 1 行第 1 列 = `1*6+1 = 7`。

节点图侧建议**用同一套编号摆方块**（第 idx 个方块就按这个表生成），
这样「客户端发的下标」和「3D 里点的方块」天然一一对应，不需要换算表。

> 需要 1 基行列时用 `puzzle.row1Of(idx)` / `puzzle.col1Of(idx)`。

## 三、`点位序列` 的语义（关键）

它不是「初始是果汁的点位」，而是**解法序列**：

```
初始盘面 = 全水果
for idx in 点位序列:
    翻转(idx 及其上下左右)          -- 水果 ↔ 果汁
```

玩家再把序列里的点位**各踩一次**，就一定回到「全水果」。

为什么可以直接把解法当数据用：**5×6 的点灯棋盘满秩（核空间维数 = 0）**，
每个盘面的解唯一且必为最优解，`最小步数 = #点位序列`。
（`_gen_levels.py` 生成、`_verify_levels.mjs` 换一套 JS 实现独立复算，50 关全部通过。）

节点图摆盘伪代码（**用状态数组直接摆，最省事**）：

```
收到「客服关卡参数」(levelIndex, minSteps, flips, states) →
    1) 清空 / 重置棋盘
    2) for idx = 0..29:
           states[idx] == 1  → 这格摆水果
           states[idx] == -1 → 这格摆果汁
    3) 按 levelIndex 布置 3D 场景（相机、装饰、计时），minSteps 可用于 UI 提示
    4) 全部就绪 → 回发「服客进入关卡」(levelIndex)
```

> 也可以照旧用点位序列自己反推（第 1 步重置全水果、第 2 步逐个翻转 flips），
> 两种摆法结果**逐格相同**；客户端已经把这串状态算好，直接照抄不会有偏差。

## 四、`状态数组` 的语义

第 4 参，长度固定 **30**，列表序号 `0..29` 就是 `idx = 行 * 6 + 列`：

| 值 | 含义 |
|---|---|
| `1` | 水果（这一格开局就是好的） |
| `-1` | 果汁（这一格开局是坏的，需要被翻回来） |

它记录的是**初始游玩棋盘**（不是终局、不是解法）：

```
状态数组 = 从「全水果」出发，依次踩点位序列里每个 idx 之后得到的盘面
```

因为同一个点位踩两次等于没踩，所以玩家**再照点位序列各踩一次就一定回到全水果**
（= 通关）。节点图要判定「全部是水果」时，直接数 3D 端的状态即可。

- 合法性自检（客户端每次发信号前会算一遍，`_verify_levels.mjs` 也会独立复算）：
  `1` 与 `-1` 都不会是全场 —— 全水果等于不用玩，全果汁也不可能由解法反推出。
- 若节点图的整数列表塞不进负数，把 `-1` 换成 `0` 即可（客户端只发 `1 / -1`，
  这个替换在节点图侧做；要客户端直接发 `0` 就改 `puzzle.initStatesFromFlips` 末尾映射）。

## 五、时序

### ① 开局 / 重连：先同步存档，再进关

```
客户端 OnStart（首屏 = 果园地图，光标停在第 1 片）
  └─ 节点图：发「服客同步存档信息」(已通关最新关卡 = 6)
       └─ 客户端：清掉本地进度 → 按「1..6 全部通关」重建（亮三颗金星、苹果转亮）
            · 解锁上限 = 6 + LOCK_AHEAD(1) = 7（第 7 片起可进，前 5 片教程关也一样逐关解锁）
            · 选关光标自动对齐到第 7 片（地图平滑滑过去）
            · 之后节点图再发「服客进入关卡」/ 让玩家自己选，都不会错位
```

> ★ 这条信号是**覆盖式**的：服务器给什么就是什么（回档也能正确回退）。
> 存档的唯一真相在服务器，客户端不参与持久化。
> 前 5 关是教程关，**解锁规则和后面 45 关完全一样**：一开始只有第 1 片可进，
> 通关第 N 片才解锁第 N+1 片。
>
> ★★ **这条信号还决定「谁该看教程」**（客户端不落盘，只能看它）：
> - 首屏序章：客户端最多等 `DEFAULT_PROLOGUE_WAIT`（0.6 s）这一条。
>   收到且 `N > 0` → **序章不弹**；收到且 `N = 0` → 弹序章；一直收不到 → 按新玩家弹。
> - 本课教程：`state.clearedLevels[N]` 为真的关卡，**重进不再自动弹本课**
>   （玩家早就打过了）。所以节点图**越早发越好** —— 发晚了老玩家会看到序章闪一下再被收掉。
>
> ★★ **协议只有一个整数**（`已通关最新关卡序号`）。通关是一条直线 —— 想进第 2 片
> 必须先通关第 1 片 —— 所以「已通关到第 N 片」就等价于「1..N 全通关」，
> 不必再传通关列表；解锁上限由客户端用 `N + DEFAULT_MAP_LOCK_AHEAD` 算。
> `0` 表示一片都没通关（客户端仍只开放第 1 片）。
> **旧协议的第 2 参（通关列表）已被移除**：节点图若还发，客户端会打印一条
> `警告：…还在发旧协议…` 并忽略它。

### ② 一次完整进关

```
玩家点果实 13
  └─ 客户端：转场盖屏（水果绽放 / 果带横扫 / 三条果带，按关卡轮流）
       └─ 盖满那一刻（onPeak）：
            · 切到游玩层（收掉果园背景，露出 3D）
            · HUD 显示「小龙正在摆果园…」
            · 发「客服关卡参数」(13, 7, {…点位}, {…状态，30 项})
            · 若是教程关且没看过 → 摊开这一课的教学卡
       └─ 节点图：照状态数组摆出盘面（或用点位序列自己反推，结果一致）
            └─ 发「服客进入关卡」(13)
                 └─ 客户端：清掉「正在摆果园…」，可以操作
                      └─ 玩家踩点位（3D 端自己处理翻转）
                           └─ 节点图：全部是水果 → 发「服客关卡胜利」(13)
                                └─ 客户端：记通关 + 三星 → 播结算演出
                                     （← 上一片 / 重玩这片 / 下一片 → / 回果园地图）
```

> 客户端有 **4 秒超时兜底**：`服客进入关卡` 一直不来，也会把「正在摆果园…」
> 清掉，避免卡在提示上（棋盘仍然由节点图控制）。
>
> 星级：协议里「服客关卡胜利」只带关卡序号，**星级由客户端记**（当前固定 3 星）。

## 六、客户端侧的健壮性处理

`signal.getIntParam` / `getIntListParam` / `getStringParam` 同时兼容：

| 形态 | 例子 |
|---|---|
| 整包即标量 | `params = 12` |
| Lua 数组 | `params = {12, 3}` |
| 数字字符串 | `params = {"12"}` |
| userdata | 带 `GetInt()` / `Count` + `Get(i)` / `GetIntList()` 的包装 |

所以节点图无论怎么打包参数，客户端都不会读崩。

## 七、进度 / 存档

存档（解锁到第几片、通了哪些片）**只记在服务器**，客户端不落盘：

| 数据 | 客户端字段 | 来源 |
|---|---|---|
| 已通关的关卡 | `state.clearedLevels` | 「服客同步存档信息」那**唯一一个整数**（已通关最新 = N ⇒ 1..N 全通关）；本局通关时也会即时写入 |
| 星级 | `state.levelStars` | 协议里没有星级 → 同步时一律满星 3；本局通关也记 3 |
| 解锁上限 | `state.mapUnlockHint` → `state.mapUnlockMax` | 同步时由 `N + DEFAULT_MAP_LOCK_AHEAD` 算出；本局通关时按「最大通关号 + 1」即时推进 |

- 收到 `服客同步存档信息` 时客户端**整体覆盖**本地进度，并把光标挪到「刚解锁的那一片」。
- 本局通关（`服客关卡胜利`）时客户端会先把本地进度往前走一格，让 UI 立刻有反馈；
  下次同步会被服务器数据覆盖，两端不会长期漂移。
- 想按步数评星：在 `game.lua` 的 `onServerWin` 里把 `local stars = 3` 换成按步数算，
  或在协议里给这条信号加第 2 个参数（加法，不破坏现有节点图）。

## 八、接入检查清单

- [ ] 5 条信号名与 `signal.lua` 顶部常量**逐字一致**（含中文，不能有空格）。
- [ ] ④ 只有**一个 `AddInt`**：已通关的最新关卡序号（1 基，`0` = 一片都没通关）。
      ★ 不要再塞通关列表；塞了客户端会打警告并忽略。
- [ ] ④ 在**进游戏 / 重连时先发一次**（否则客户端只会从「只有第 1 片可进」开始，
      而且老玩家会被序章多拦一次）。
- [ ] ④ 要发给**每个玩家**（含 `0` = 新玩家）：不发的话客户端只能按「新玩家」处理。
- [ ] ⑤ 的参数顺序是 `关卡序号（1 基）→ 最小步数 → 点位序列 → 状态数组`，一个都不能少。
- [ ] 状态数组长度 = 30，取值只有 `1`（水果）/ `-1`（果汁），序号 `0..29` = `行*6+列`。
- [ ] 点位编号按「行×6+列、0 基」对齐。
- [ ] 点位序列按「解法序列」使用（不是初始果汁列表）。
- [ ] 判定由服务器做：**3D 端数完所有点位都是水果**再发 `服客关卡胜利`。
- [ ] 重玩时不改关卡序号，只重置盘面。
