# 瓦雷莎的果园救急 · 千星沙箱客户端工程

> **独立工程**：从「点灯迷题（5×6）」那套 **客户端 UI + 服务器节点图信号** 方案拆出来，
> 换皮成「果园救急」，并把选关重做成**横向长图地图**、教程重做成**逐关一课**。
> 与 `点灯迷题/`（旧 3D 版）、`点灯迷题2D/`（纯客户端 2D 版）**互不依赖**，可单独导入沙箱。

## 一、玩法与世界观

小龙来果园帮忙，一脚一个「十字」，把码好的水果踩成了果汁：

- 棋盘 **5 行 × 6 列 = 30 个点位**；
- 踩一个点位（玩家在 3D 里点它）→ **它自己 + 上下左右**一起翻：水果 ↔ 果汁；
- 边上的点位只翻 **4 格**，角上的只翻 **3 格**；
- 同一个点位踩两次等于没踩；两个点位的十字重叠时，重叠格被翻两次 = 白翻；
- **把每一格都还原成水果**，这片果园就救回来了。

> 数学上就是 5×6 Lights Out，但叙事、文案、选关、教学全部按果园重写。

## 四、★ 选关：横向长图地图

参考「开心消消乐」的关卡地图（果实挂在藤蔓上），改成**横着的一条土路**：

```
🍎──01──🍊──02──🍎──03── … ──🍎──50
```

- **50 片果园**沿蜿蜒土路排开，节点就是一颗果实，显示编号；
- **苹果下方固定三颗星**（用户要求，三档一眼分清）：
  | 状态 | 苹果 | 三颗星 | 能不能进 |
  |---|---|---|---|
  | **已通关** | **红色**（熟了，`fruit`） | **亮黄** `star` | 能 |
  | **已解锁 · 未通关** | **青翠绿**（`ok` 混金，和旧版一致） | 暗金 `starDim` | 能 |
  | **未解锁** | 灰绿暗淡（`locked` 混影） | **黑色** `starOff` | 不能 |
  - ★ 光标选中的待挑战节点用「**同色加白**」提亮（不用橙红，否则和「已通关的红苹果」撞色），
    外加金圈 + 心跳；未解锁节点不提亮，保持暗淡。
  - 通关一关 = 这一关亮星 + **下一片自动解锁**（解锁到「最大通关号 + 1」）。
  - ★ **前 5 关教程关也逐关解锁**：一开局只有第 1 片可进，通关第 1 片才解锁第 2 片，以此类推。
    跨会话的进度来自服务器信号 `服客同步存档信息`（见 `信号协议.md`）。
  - ★ 星一律用 **alpha 255 的实色**，不用低透明度：半透明星会淡到看不见，
    玩家会以为「没画星星」而不是「这关没通」。
  - ★ 光标高亮**只作用于已解锁的节点**：划到未解锁的 10 号时它仍保持暗淡，
    「当前选中」只靠外面的金圈表达 —— 否则橙色一染，看着像能进。
  - ★ 「进入果园」按钮会跟着变：未解锁时文案变「第 10 片 · 未解锁」并整块转灰。
- 当前这片 = **金圈** + 果实轻微心跳
- **小龙**站在当前果园上方：会扇翅膀、甩尾巴、眨眼，换关时**飞过去**（弹簧跟随）；
- **拖拽**：按住地图任意处横拖，跟手；松手按惯性预测落点，**吸附到最近的果园**；
- **箭头 / ← →**：换一片并把长图平移过去（到头时箭头变淡，按方向键会晃一下给反馈）；

### ★ 背景是怎么拼的（`scene.lua` + `map.lua` 装饰，只用基础图元）

从下到上：天空底 → 天空更深一层 → 太阳（三层光晕 + 8 根慢转光芒）→ 云朵 →
远山（两排扁椭圆）→ 田垄 → 中景带 → 近景带 → 草垛 → 两团柔光 → 风的线条。

| 元素 | 怎么拼 | 要点 |
|---|---|---|
| 太阳 | 圆环色圆 + 奶油内芯 + 8 根细椭圆光芒（装进容器整体 `setRotationZ` 慢转）+ 三层同心光晕 | 光晕必须三层：两层会看出一个硬边圆盘。坐标 `x` 为负才是画面左侧 |
| 云朵 | 5 个**同色不透明**圆叠出蓬松轮廓（底部一层奶油暗面） | **不能用半透明**：一块云内部会露出一圈圈圆盘轮廓 |
| 远山 | 两排扁椭圆，山脚压在 `groundTop`（由 `DEFAULT_SCENE_GROUND_H` 反推） | 早期用旋转 45° 方块 → 山尖浮在天空中间 |
| 地面 | 三层**超宽扁椭圆**（远浅 / 中 / 近深），分界按 `-ch*0.26 / -ch*0.40` 算 | 矩形上沿是一条笔直横线，像地板缝；按 `gh` 算则 900p 下近景被压到屏外 |
| 果树 | 根部投影椭圆 + 树干矩形 + 三层圆树冠 + 苹果（圆果身 + 高光 + 果梗 + 叶） | 只挂苹果/梨，**不挂葡萄**（早期挂过，太怪） |
| 风车 | 木杆 + 自转容器 + 4 片三角叶片 + 奶油轮毂 | 叶片要「尖端朝外再斜 32°、沿切向错开」，摆正会拼成一颗四角星 |
| 小草 | 投影 + 4~5 片细长三角叶 | 每帧按 `sin(t*2.1+phase)` 摆，片数越大摆幅越大 |
| 小花 | 5 瓣圆 + 花心 + 茎 | — |

> **布局自适应**：间距 / 节点尺寸 / 字号全部乘 `k = clamp(min(画布宽/800, 画布高/600), 0.85, 2.2)`，
> 1280×720 与 1600×900 都排得开。地图带宽由「顶部标题区 22% / 底部操作区 20%」反推。

### ★ 吉祥物「小果龙」是怎么拼的（`mascot.lua` + `_gen_mascot.py`）

参考图 → **96×96 纯矩形拼图**，**1428 个矩形控件**（+1 个容器），不依赖任何图片资源。

```bash
# 重新生成（改精度 / 换参考图都走这一条）
python _gen_mascot.py --grid 96 --colors 32 --tau 0 --dark 4.5 --min-area 4 --cell 1.15 --write
```

| 步骤 | 做法 | 为什么 |
|---|---|---|
| 去白底 | 从四角 `floodfill` 泛洪，不是按颜色抠 | 角色身上有大片白色（面罩 / 绷带 / 衣服），按颜色抠会一起抠掉 |
| 内缩 2px | 对 alpha 做 4 邻域腐蚀 | JPEG 边缘有灰白毛边，不内缩会在剪影外面留一圈脏白 |
| 量化 | median-cut → 32 色 | 保留粉 / 薄荷 / 奶白 / 金 / 黑五种关键色 |
| 降采样 | 96×96，每格取**加权众数**（深色像素 ×4.5） | ★ 10px 宽的黑描边在 12px 的格里常常输给周围大色块 → 轮廓断成虚线；加权后描边才连得起来 |
| 去碎点 | 面积 < 4 的同色连通块并进邻居众数，**黑色永不参与** | 四成控件都是 1 格噪点；但黑描边不能动，一动轮廓就碎 |
| 拟合成控件 | 每色做「最大矩形贪心覆盖」 | 精确无缝（`verify=True`，矩形重绘 == 点阵），平均 1 个控件盖 6.5 格 |
| 动画 | 一帧只动**一个容器** | 1500+ 控件全是死的，不参与每帧计算；换关只做一次平移 |

> **控件预算**：96×96 ≈ 1400 个控件；64×64 ≈ 900；48×48 ≈ 500（`--grid` 一个参数切）。
> 真机若嫌重，优先降 `--grid`，不要动 `--dark`（描边会碎）。

### ★ 拖拽是怎么实现的（引擎没有 ScrollView）

| 环节 | 做法 |
|---|---|
| 拖动 | 铺一条覆盖地图带的**光标检测区域**，`CursorDown→CursorDrag→CursorUp` 记录位移 |
| 平移 | 只改 `mapWorld`（长图容器）的 `SetAnchoredPosition`，一帧一次调用 |
| 惯性 | 由最后一段位移估速度 → 预测落点 `scroll + v / friction` |
| 吸附 | 预测落点最近的果园 → 0.26s `outCubic` 平移过去 |
| 点击 vs 拖拽 | 累计位移 ≤ 10px 算点击，否则算拖拽（阈值 `DEFAULT_MAP_DRAG_THRESHOLD`） |
| 点哪一片 | 真机走果实自带的命中区；若某引擎把整块拖动区判在上面，则退化为「按坐标找最近的节点」（三种坐标约定自动校准） |

### ★ 界面转场（`transition.lua`）

只有两种，都用「先盖住 → 切屏 → 再揭开」的结构：

| 形态 | 用在哪 | 时间轴 |
|---|---|---|
| `fade` 黑幕 | 重玩 / 关卡之间换片 | 0.14 + 0.02 + 0.16 s |
| `split` 天地撕开 | 选关 ↔ 游玩 | 见下 |

**进入果园（`mode = "open"`，0.42 s）**

```
板子已在屏上合拢（上半天空 + 下半地面，正好盖满）
  → 第 0 帧就切屏（3D 在板后渲染）
  → 天空板向上移出屏幕、地面板向下移出屏幕
  → 果园从中间那道裂缝里「长」出来
```

**返回选关（`mode = "close"`，0.24 + 0.04 + 0.16 = 0.44 s）**

```
天空从上方移入、地面从下方移入（easeOutCubic：冲进来、贴住时慢慢停）
  → 合拢的瞬间切屏到选关
  → 两块板整体淡出，露出选关地图
```

两块板都是**风格化的天地**，不是截图：三段天光 + 三团云 + 远丘 / 近丘 + 远处树点；
受光草坡 + 小草 + 落果 + 石子。配色直接取 `DEFAULT_PALETTE` 的
`sky / hill / grass / leaf / soil`，和选关背景同族，所以压上去、以及最后淡出都不刺眼。

| 关键点 | 说明 |
|---|---|
| 为什么用「板」而不是切背景 | 引擎没法把 `containerScene` 切成上下两半，只能额外画两块同色系的板来扮演「天空 / 地面」 |
| 一帧只动一个容器 | 每块板只有一个 `setPos` + 一个 `setScaleXY`；子控件全是死的，不吃帧 |
| 中途轻微拉长 | `scaleY = 1 + 0.035·sin(πk)`，像被抽走时被带了一下，比纯平移有质感（合拢时同理，1.03） |
| 缓动 | 分开用 `easeInOutCubic`（无硬拐点才「丝滑」）、合拢用 `easeOutCubic`（有「啪」地合上） |
| 淡出 | 逐控件 `setColor(ctrl, 原色, a)`；构造时把 `(句柄, 颜色)` 记进 `list` |
| ★ 图元必须画在板内 | 容器 `enableMask = false`（不裁剪），溢出会盖到屏幕另一半 |
| ★ `OVER` 别给太大 | 两块板在屏幕中线的重叠量，给到 44px 时合拢后两条「撕裂边」会互相盖住；现在 8px |

调参只动 `config.lua`：`DEFAULT_TRANS_SPLIT_OPEN` / `_MERGE` / `_FADE`。

| 首屏 · 服务器存档 `已通关最新 > 0` | **不弹序章**（也不点亮「进入果园」引导） |
| 首屏 · 存档 `= 0` / 一直收不到存档 | 弹序章（当成新玩家） |
| 首屏 · 存档来得比序章还晚 | 序章被当场收掉（`guideKind` 先摘掉，所以不会误触发按钮引导） |
| 已通关的关卡重进 | **不弹本课教程**（`state.clearedLevels[idx]` 为真就跳过） |
| 未通关的教程关（1–5） | 照弹，本局只看一次（`state.lessonSeen[idx]`） |

> ★ 客户端不落盘，「是不是老玩家」只能看服务器那条 `服客同步存档信息`：
> 所以 `OnStart` **不立刻弹序章**，而是挂 `state.prologueDelay = DEFAULT_PROLOGUE_WAIT`
> （默认 0.6 s）；`OnUpdate` 里一收到存档（`state.saveSynced`）或等到超时，
> 就调一次 `openPrologueIfNew()` 定下来 —— 老玩家不会看到序章闪一下。
> 判定函数与入口在 `game.lua` 的 `openPrologueIfNew` / `enterLevel`（`showLesson` 那三行）。

> ★ 这 5 关的解锁规则和后面 45 关**完全一样**：一开局只有第 1 片可进，
> 通关第 1 片才解锁第 2 片……（早先「前 5 片永远可进」的保底已删除）。
> 跨会话的进度由服务器 `服客同步存档信息` 灌入，见 `信号协议.md`。

### 三种打开方式（`guide.lua`）

| 入口 | 调用 | 摊开的内容 |
|---|---|---|
| 地图首屏自动弹 | `guide.openPrologue()` | 只有序章 2 页；`state.prologueSeen` 表示**本局已处理过这件事**（弹了 / 认定老玩家跳过），只决策一次。★ 只由 `game.openPrologueIfNew()` 调，且存档 `已通关最新 > 0` 时不调。★ 这是唯一把 `guideKind` 设成 `"prologue"` 的入口 —— 关掉它才会置 `state.prologueGuidePending`，由 `game.lua` 下一帧调 `map.guideEnter(true)` 点亮「进入果园」 |
| 进第 N 关自动弹 | `guide.openLevelLessons(N)` | 第 1..N 课，停在**第 N 课第 1 页**，可往前翻看之前的课 |
| 地图「教程」按钮 / `H` `T` | `guide.openHandbook(N)` | **序章 + 第 1..N 课**，从第 1 页开始（N = 已解锁最远的一课，所以不会剧透后面）。★ `guideKind` 是 `"tutorial"`，关掉**不会**触发按钮引导 |

`guide.openTutorial(from, upto)` 保留为兼容入口（= 整叠拼到第 `upto` 课、从第 `from` 课第一页开始）。

### 一页长什么样

固定结构：标题 + 页码 + 一张真画出来的 5×6 示意图 + 一行图注 + **两行正文** + 按钮。

- ★ **字数是硬约束**：文本框 `adaptiveFontSize = false`（不会自动缩），正文框宽 580px / 字号 18，
  超过约 **30 字就会被裁**；图注 15 号，约 34 字。新增文案请先数字数。
- 一页只讲一件事。`config.lua` 里 `M.PROLOGUE.pages` / `M.LESSONS[i].pages` 都是这个结构：

```lua
{
    title   = "第 1 课 · 点一格，撞五格",     -- ≤ 16 字
    lines   = { "点蓝框那一格，小龙就跳过去撞一下。",
                "被撞的格子连着上下左右，五格一起翻。" },   -- 两行，各 ≤ 30 字
    caption = "蓝框 = 让你点的格子 · 一下撞五格",              -- ≤ 34 字
    art     = { rings = { { 4, 2 } } },                        -- 见下
}
```

- **示意图三种写法**：
  | 字段 | 含义 |
  |---|---|
  | `art.rings = {{行,列},…}` | 「这一页要你点的点位」，会套**亮蓝色矩形环框**，并参与盘面推算 |
  | `art.flips = {{行,列},…}` | 只参与**盘面推算**、不画框（用于「先看清果汁长什么样」这种页） |
  | `art.map = { "....o.", … }` | 直接写盘面：`.` 水果（黄）/ `o` 果汁（红）/ 其它字符不画。**只给非解谜的示意页用**（★ 目前没有页在用，能力保留） |
- **★★ 盘面不手写，由蓝框现算**：`guide.lua` 的 `deriveArt()` 按「被十字覆盖的奇偶」推盘面 ——
  **奇数次 = 翻过 = 红**（果汁），**偶数次（含被两个十字同时覆盖）= 原样 = 黄**（水果）。
  前 5 课的 rings 就是各关真实解，所以示意图 == 该关进关时的真实盘面。
  （手写盘面时漏了「重叠处要变回去」，用户指出过；现在这条路彻底堵死。）
- `_verify_levels.mjs` 独立复算两件事：① 这一课所有页的 rings 并集 == 该关解序列；
  ② 由 rings 推出的盘面 == `boardOf(flips)`（该关真实盘面）。任一条不成立直接报错。
- **凹槽跟着内容收缩**：如果某页写了 `art.map` 且盘面比 5×6 小（比如只有一行方格），
  按满槽画会空一大片，所以 `renderArt()` 会按内容留 `pad` 收一收（最小不低于 3 行 / 3 列的观感尺寸）。
  ★ 现在所有页都由 `deriveArt()` 推出满 5×6 盘面，所以凹槽永远是满尺寸 ——
  这条机制是给「以后真要用 `art.map` 写的示意页」留的。

> 版面按「真机文本框最小高度 36px」反推：面板 640×470、正文两行间距 34，
> 1280×720 与 1600×900 都不会挤在一起（面板整层按 `uiScale` 放大）。
>
> ★ **示意图格子不再写死 44**：`computeArtLayout()` 先按「凹槽可用空间 ÷ 行列数」反推边长，
> 再由格子反推凹槽尺寸，四边固定留 `pad`（≥ 圆角半径 2px 以上）的边距。
> 之前的写法是「格子 44 + gap 8 写死、凹槽固定 360×256」，网格高 252 只比凹槽矮 2px，
> **小于圆角半径 14 → 四角方格压在圆弧上，看起来就是「方格超出圆角矩形」**；
> 而且 gap 又乘了一次 `uiScale`（`containerGuide` 整层已被它缩放过），大画布上会真溢出。
> 现在 1280 下实测：格子 43.2×43.2（36×1.2），四边边距均 20.4px。
>
> ★ **示意图两色（用户指定）**：`pal.guideFruit`（`F5B21F` 黄）= 水果、
> `pal.guideJuice`（`DA3B2B` 红）= 果汁。**故意不复用 `pal.fruit` / `pal.juice`**：
> 那两个键在选关苹果、粒子、结算里另有语义，混用会让两边越改越乱。

引导层长什么样（`map.lua` 的 `buildHUD` 末尾建好，`state.mapGuideRoot` 一个容器装完）：

| 元素 | 做法 | 为什么这样做 |
|---|---|---|
| 光圈 | 内外两条框，各 4 根细条（横条宽 = 框宽、竖条高 = 框高 − 2×厚，**互不相交**） | 相交处会被盖两次 → 颜色更深，一眼看出是「拼的」；细条框也不会像色板糊住按钮 |
| 呼吸 | 内圈 alpha 140↔230 呼吸；外圈**一边放大 1→1.11 一边 alpha 230→0**，周期 `DEFAULT_MAP_GUIDE_PULSE` | 单帧写 8 次 `setColor` + 2 次 `setScale`，不新建控件，不吃帧 |
| 气泡 | 深色外沿（`accent` 混暗）+ 浅色牌面（`panel`）两块**不透明**圆角块 + 文字「点这里开始救援」 | 圆角块 alpha 必须 255（半透明会露十字接缝），层次只能靠两块实色叠 |
| 三角 | `trianglePrefabId` 画一个 22×12 的三角，转 180° 指向下方按钮，`sin` 上下轻跳 3px | ★ 别用 `↓` 字符：本工程只保证 `← → ↑ √ ★ ◆ · ×` 不出豆腐块 |
| 亮起瞬间 | 在按钮位置撒一把果汁粒子（`fx.spawn`） | 余光也能注意到右下角 |

> 可调参数：`DEFAULT_MAP_GUIDE_PAD`（光圈外扩）/ `_PULSE`（呼吸周期）/
> `_TEXT_SIZE` / `_BUBBLE_W` / `_BUBBLE_H`。★ 气泡高别低于 36（真机文本框最小高度）。
>
> ★ 引导层**不进** `map.allNodes()`：它的显隐只由 `guideEnter` 控制，
> 否则「地图收起又回来」会让一条过期引导重新冒出来（`_verify_ui.mjs` ④ 有回归项）。
>
> ★ 底部提示条**不参与**引导：它永远写回 `MAP_HINT`（操作方法），
> 引导文案只放在气泡里 —— 见过的坑是「临时文案把操作方法永久顶掉」。

## 七、装配到沙箱

### A. 必做

1. **导出干净的导入包**（别用模拟器存档里的脚本）：

   ```bash
   python 瓦雷莎的果园救急/_export_sandbox.py
   ```

   把 `_sandbox/default_import_file/` 下 **17 个 `.lua`** 整个目录导入沙箱
   （`require` 写的是 `default_import_file/xxx`，目录名不能改）。

2. **挂脚本**：`game.lua` 挂到「客户端控件容器」的**容器节点**上（代码读 `script.object`）。

3. **脚本参数**：

   | 参数 | 必填 | 元件类型 | 用途 |
   |---|---|---|---|
   | `rectPrefabId` | **是** | 纯白图片 | 面板 / 果实 / 土路 / 按钮 / 粒子全部用它染色 |
   | `cursorPrefabId` | **是** | **光标检测区域** | 地图拖拽与所有点击。**不配 → 鼠标完全失效** |
   | `textPrefabId` | 否 | 文本 | 不填只有色块没有字 |
   | `containerPrefabId` | 建议 | 容器 | 配了就用真容器当父节点（模拟器命中测试只下钻真容器） |
   | `circlePrefabId` | 强烈建议 | 圆形图片 | 云朵 / 果实 / 太阳 / 圆丘 / 圆角矩形的四角（**不配 → 全变方块**） |
   | `ringPrefabId` | 否 | 圆环图片 | 地图金圈（不配 → 退回四根细条方框） |
   | `trianglePrefabId` | 否 | 三角形图片 | 风车叶片 / 小草（不配 → 退回圆形再退回矩形） |
   | `star4PrefabId` / `star5PrefabId` | 否 | 四角星 / 五角星 | 牌面装饰星（不配 → 退回圆形） |
   | `clickAudioId` / `openAudioId` / `winAudioId` | 否 | 音效 | 点击 / 进关 / 通关 |
   | `dragAudioId` | 否 | 音效 | **拖动果园地图**（起拖 + 每跨过一片各一声）。不配则自动复用 `clickAudioId` |

   - **形状参数都可以不配**：`utils` 里每个形状函数都有退化兜底（圆形→矩形、
     三角形→圆形→矩形），只是画面会变方，逻辑与排版一律不受影响。
   - 圆角矩形是 `utils.roundRect / roundBox` 用「一横一竖两条矩形 + 四角圆」
     拼的（9 宫格），只用矩形 + 圆形两种模板就成立；
     **圆形模板没配时四角会是方块，看着像没切圆角**。
   - 矩形模板要**纯白**、**不带遮罩**；
   - 文本模板需支持 `text / fontSize / fontColor / bgColor`（客户端会主动把 `bgColor` 置透明）；
   - 光标检测区域底图留空或全透明即可。

4. **节点图实现 5 条信号**（见 `信号协议.md`），信号名必须逐字一致：

   | 方向 | 信号名 | 参数 |
   |---|---|---|
   | 服 → 客 | `服客进入关卡` | 关卡序号（整数） |
   | 服 → 客 | `服客关卡胜利` | 关卡序号（整数） |
   | 服 → 客 | `服客进入选关` | 无 —— ★ **回地图的唯一途径**（游玩界面没有任何返回按钮） |
   | 服 → 客 | `服客同步存档信息` | **已通关的最新关卡序号**（整数，1 基；`0` = 一片都没通关）。★ 只有这一个整数，不再传通关列表 |
   | 客 → 服 | `客服关卡参数` | 关卡序号（整数，1 基）、最小步数（整数）、点位序列（整数列表，0 基，`行*6+列`）、状态数组（整数列表，30 项，`1` = 水果 / `-1` = 果汁） |

   > ★ `客服关卡参数` 的第 4 参「状态数组」= **初始游玩棋盘**的全部 30 格（序号 0..29 即
   > `行*6+列`）。节点图可以直接照它摆盘，不必自己反推；第 3 参「点位序列」是这一关的解法。

   > ★★ `客服关卡参数` 的**发送时机**：教程关（前 5 关，且本局还没看过本课）进关时
   > **先不发**，等玩家关掉教程、真正露出游玩界面那一帧才发（`game.lua` 的
   > `pendingLevelParams` + `flushLevelParams`）。其余情况（非教程关 / 重玩 / 上下片）照旧当场发。
   > 这样服务器不会在玩家读教程时就把盘摆好、动画还放完了 —— 玩家一关教程就是成品。
   > 对节点图没有额外要求：它只要「收到参数 → 摆盘 → 回 `服客进入关卡`」即可，
   > 只是这条请求会比以前晚到几十秒。

   > ★ `服客同步存档信息` 要在**进游戏 / 重连时先发一次**：客户端收到后整体覆盖本地进度
   > （已通关最新 = N ⇒ 1..N 片全部亮了），解锁上限 = `N + LOCK_AHEAD`，
   > 选关光标对齐到「刚解锁的那一片」。★ 旧协议的第 2 参（通关列表）已移除，
   > 节点图若还发，客户端会打一条警告并忽略。

## 九、踩过的坑（本工程已处理）

1. **★ 同级叠放必须显式 `raise()`**：真机「后建在上」、模拟器「先建在上」。
   `utils.createControl / createContainer / createText / createHit` **建完就 `SetAsLastSibling()`**，
   所以模块只要按「底图 → 文字 → 命中区」的创建顺序写，两端都对。
   （漏掉时的表现：整屏只剩最先建的那块底色，草坡、文字、按钮全被盖住。）
2. **★ 容器尺寸不能是 1×1**：模拟器的命中测试按「锚点 + 尺寸」逐层算矩形，
   1×1 的父容器会让所有子控件的命中矩形退化到原点 → 点哪都不中。
   `utils.createContainer` 一律按画布尺寸创建。
3. **★ 纯装饰必须 `raycastTarget = false`**：土路石子 / 果树 / 果实底图如果吃射线，
   会把拖拽与点击一起吞掉。`map.lua` 的 `rect()` 统一 `utils.noRay()`。
4. **★ 游玩期必须收掉背景层**：果园背景是盖满画布的**不透明**底色，
   不收会把节点图摆出来的 3D 果园整片盖住（`scene.setVisible(name ~= "play")`）。
5. **★ 文本框最小高度 36px**：真机上盒子太矮一个字都不画（模拟器照画）。
   `utils.createText` 统一兜到 `MIN_TEXT_H`，布局按兜高后的盒子排。
6. **★ 命中区要比目标大一圈**：果实命中区 92（节点 66），否则指缝点不中。
7. **★ 居中面板整层缩放**：结算 / 教学卡两层由 `uiScale` 整体 `SetLocalScale`，
   层内 `fx.spawn` 的坐标与粒子尺寸都要乘 `utils.uiScale()`，否则果汁会在原地爆。
8. **★★ 圆角矩形（9 宫格）的 alpha 只能给 255**：横条 / 竖条 / 四角圆会互相重叠，
   半透明时重叠处被盖两次会更实 → 露出「十字接缝」。需要淡入请走
   「遮罩淡入 + 面板 `setBoxSize` 缩放」，投影要用「预混色 + 255」代替透明度
   （`utils.mixHex(pal.overlay, pal.shadow, 0.42)`）。
9. **★ 云朵必须用同色不透明圆叠**：半透明的圆一叠，一块云内部就露出一圈圈圆盘轮廓。
10. **★ `roundRect` 的返回值一定要存下来**：早期「用完就扔」，`setVisible(false)`
    时没人管它 → 进关后头顶还挂着一块奶油牌（`state.mapHeadBandEdge` / `mapFootBand`）。
11. **★★ 回调里别调「不存在的全局函数」**：`hud.setActions{ onGuide = function() openGuide() end }`
    里的 `openGuide` 从来就没定义过（本文件只有 `local openTutorial(fromFirst)`）。
    结果：进关后点 HUD「教程」→ 光标回调抛 `attempt to call a nil value (global 'openGuide')`
    → 回调中断、教程不弹，客户端还会**闪一下屏**。地图上那个「教程」按钮走的是
    `onTutorial`（对了），所以只有游玩期点按钮会坏，很容易误判成「按钮点不中」。
    **静态校验抓不到这类错**（`_check_refs.py` 只查 `M.xxx` / `state.xxx` / `config.XXX`），
    改完事件回调务必在模拟器里真点一遍。
    > 补充（当前版本）：游玩 HUD 已按需求删掉全部按钮，这条坑本身不复现了，
    > 但「回调里打错函数名会被 pcall 静默吞掉」这个教训仍然成立（`utils.*` 内部大量 pcall）。
    同理，`roundBox` 返回的 `{ root, parts }` 要整组登记进显隐列表，
    位移 / 缩放一律作用在 `.root` 上（直接传给 `utils.setPos` 会被 pcall 静默吞掉）。
11. **★ 装饰要从 i=1 等比铺满整张长图**：写 `decoX(i + 5, …)` 之类的偏移，
    会让可视窗口（停在第 1 片果园）里一个新装饰都看不到。错开各类装饰用小数相位。
