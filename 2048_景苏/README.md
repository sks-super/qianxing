## 二、功能清单（对照需求）

### 核心玩法
- 4×4 棋盘，Lua table 存 16 格；方块是**对象数组**，每个方块有终身不变的 `id`（平移动画靠它认人）。
- 开局随机 2 个数字；新数字 **90% 出 2、10% 出 4**（`DEFAULT_SPAWN_2_RATIO` 可调）。
- 上/下/左/右移动；相同数字碰撞合并、分数累加（合并值就是得分）。
- 每次**有效移动**后在空位生成一个新数字；纹丝不动的移动不生成、不扣分。
- 无空位且相邻无同值 → 判负；达到 `DEFAULT_WIN_VALUE`（2048）→ 判胜，可「继续游戏」继续堆。
- 分数与最高分常驻显示；**最高分走平台存档持久化**（见第六节）。

### UI
- 4×4 网格用 **16 个纯色矩形控件**拼成，每格独立控制显示（空格底板 + 数字方块两层）。
- 分数、最高分各一个**矩形框 + 两段文本框**（小标题在上、数值在下）。
- 方向操作三条路都通：**WASD / ↑↓←→ 键盘**、**屏幕方向键（脚本自绘）**、**鼠标按住拖动或手指滑动**。
- 功能按钮三个：**重新开始 / 撤销一步（记录开局到现在每一步，默认留 64 步）/ 继续游戏**。
- 结算界面是**本工程原创版式**，不复用旧项目样式：棋盘缩成「相片」飞向屏幕中右 →
  四周长出**拍立得相框**（上/左/右窄边 + 下方宽留白，留白里写「第 N 步 · 最大 X」）→
  左侧滑入信息面板（得分滚动、最高分、最大方块、步数）→ 按钮依次弹出。

### 动效（全部由 `anim.lua` 逐帧驱动，不用引擎 Tween）
| 需求 | 实现 | 参数 |
| --- | --- | --- |
| 方块平滑平移 | 逐帧 `SetAnchoredPosition` | `DEFAULT_ANIM_MOVE_TIME = 0.12`（落在需求的 100–150ms） |
| 新方块从 0 放大 | `0 → 1.12 → 1` 两段回弹 | `ANIM_SPAWN_TIME` / `ANIM_SPAWN_OVERSHOOT` |
| 合并弹性碰撞感 | 先放大到 1.18 再 `pulse` 回弹到 1 | `ANIM_MERGE_TIME` / `ANIM_MERGE_SCALE` |
| 合并粒子迸溅 | 12 个小矩形从格心炸开，带重力、自转、缩小、淡出 | `FX_PARTICLE_*` |
| 「+分数」飘字 | 文本框上升 + 放大 + 淡出 | `FX_FLOAT_*` |
| 分数变化 | 数字**滚动**到新值 + 数值框**弹跳** | `ANIM_SCORE_TIME` / `ANIM_SCORE_POP` |
| **连按跟手**：输入锁只覆盖平移段 | 平移 0.12s 一结束就解锁（`onSettled`），合并弹跳 / 新方块弹出在后台并行播 | `ANIM_MOVE_TIME` |
| **连击加速** | 两次有效操作间隔 < 0.55s → 平移压到 0.10s | `COMBO_WINDOW` / `ANIM_MOVE_TIME_FAST` |
| **输入缓冲** | 锁着的时候按方向只留**最后一个**，落定瞬间立刻兑现（扔早留晚） | `INPUT_BUFFER` |
| **解锁看门狗** | 万一解锁回调被谁清掉，超时强制放行，绝不让输入永久锁死 | `SETTLE_GUARD` |
| 结算：棋盘定格缩小飞到中右 | 整层 `SetLocalScale` / `SetLocalRotation` / `SetAnchoredPosition` | `SETTLE_BOARD_TIME` / `PHOTO_SCALE` / `PHOTO_TILT` |
| 结算：从屏幕左侧滑入信息 | 整组容器从 `x - 760` 滑到目标位（`outBack` 轻微过冲） | `SETTLE_INFO_*` |
| 结算：分数数字滚动增长 | `anim.value(0, 最终分, …)` | `SETTLE_COUNT_TIME` |
| 结算：按钮依次出现 | 每个按钮延后 160ms 从 0 弹到 1 | `SETTLE_BTN_DELAY` / `SETTLE_BTN_TIME` |

 ├─ fx.lua                    粒子迸溅 + 飘字

## 四、在千星沙箱里怎么装配

1. **建容器**：新建一个引用「客户端控件容器」的元件实例，把它放在场景里。
   （`game.lua` 要挂在这个控件树的**容器节点**上。）
2. **备三个模板元件**（脚本参数要用它们的索引）：

   | 参数名 | 元件类型 | 用途 | 必填 |
   | --- | --- | --- | --- |
   | `rectPrefabId` | 纯色矩形（图片控件） | 背景、棋盘底板、空格、方块、**按钮底图** | ★ 必填 |
   | `textPrefabId` | 文本框 | 数字、分数、**按钮文字**、提示 | ★ 必填 |
   | `cursorPrefabId` | 光标检测区域 | **所有可点区域**（方向键、功能按钮、结算按钮、滑动面） | ★ 必填 |
   | `buttonPrefabId` | 预设按钮 | *（可选，本作已不需要）* | — |

   > **按钮是怎么做出来的**：不是「预设按钮」，而是脚本自绘的**三层结构** ——
   > 图片底（`rectPrefabId`） + 文字（`textPrefabId`） + 命中的光标检测区域（`cursorPrefabId`）。
   > 这样配色、按下反馈、禁用态全由脚本控制，**不需要在沙箱里准备按钮模板**。
   >
   > ★ 为什么不再用「预设按钮」：它要靠脚本参数指定模板，**没配时实例化直接返回 nil**；
   > 旧写法把按钮文字也建在 `if 按钮 then` 里面，于是**按钮和文字一起消失**，
   > 还不报错，只留一句「点不动」的警告 —— 极难定位。
   >
   > ★ `AddCursorEventListener` 只对「预设按钮」和「光标检测区域」有效。
   > 图片控件上挂这个监听会被 `pcall` 静默吞掉 → 「画得出来但点不动」。
   > 所以可点区域一律用**光标检测区域**，外观自己用图片 + 文本画。

3. **导入脚本**：把本目录下 14 个 `.lua` 全部导入到 `default_import_file/`（根目录，不要建子目录）。
4. **挂脚本 + 填参数**：把 `game.lua` 挂到第 1 步的容器节点上，按上表填元件索引；音效 ID 不填就是静音。

   | 参数 | 触发时机 |
   | --- | --- |
   | `moveAudioId` | 方块平移 |
   | `mergeAudioId` | 方块合并 |
   | `spawnAudioId` | 新方块出现 |
   | `undoAudioId` | 撤销一步 |
   | `winAudioId` | 达成 2048 |
   | `failAudioId` | 无路可走 |
   | `clickAudioId` | 按钮点击 |

5. **试玩**：进入关卡即可。首次入场会有一层黑幕掩护，方块逐个「弹」出来。

## 五、层级结构（从下到上）

```
容器节点（game.lua 挂这里）
├─ containerBg        ① 背景
├─ containerBoard     ② 棋盘根 ★ 结算时对它整体缩放/旋转/位移
│   ├─ containerBoardBg   ②-a 底板 + 16 个空格
│   └─ containerTile      ②-b 方块（SetAsLastSibling 压在底板上）
├─ containerFx        ③ 粒子 / 飘字
├─ containerHud       ④ 滑动面 + 分数 + 方向键 + 功能按钮
├─ containerMenu      ⑤ 结算遮罩 + 相框 + containerInfo（信息面板）
└─ containerFade      ⑥ 黑幕（永远最顶）
```

**结算时的层级变化**：`containerMenu` 里的遮罩要压住背景与 HUD，但又不能让遮罩盖住「相片」，
所以结算开始时会**把 `containerBoard` 抬到 `containerMenu` 之上**（黑幕仍在最顶），
关闭结算时按同一张表还原。重排只用 `SetAsFirstSibling` / `SetAsLastSibling`
（这两个在真机与模拟器里效果一致），**绝不用 `SetSiblingIndex(i)`**——
模拟器里它实际插到 `len-1-i`。

## 六、最高分持久化：服务器侧要做什么

客户端**不能写**服务器变量，只能「读」+「发信号请服务器写」。所以：

| 方向 | 名字 | 载荷 | 服务端要做的事 |
| --- | --- | --- | --- |
| 客户端 → 服务器 | `保存最高分` | 1 个整型（新纪录） | 把它写进全局自定义变量 `2048最高分` |
| 服务器 → 客户端 | （读）`2048最高分` | — | 客户端启动时读；变量变化时会自动刷新显示 |
| 服务器 → 客户端 | `进入游戏` | 无 | 客户端收到后重开一局 |

客户端另外会发出这些**纯事件**信号（信号名 `客户端事件`，载荷是事件名字符串），
供服务端做统计/成就/埋点：`开始游戏`、`重新开始`、`撤销一步`、`继续游戏`、`达成2048`、`游戏失败`。

名字都在 `config.lua` 里：

```lua
M.DEFAULT_HIGHSCORE_SYNC   = 1          -- 0 = 不做任何网络读写，最高分只活在本次会话
M.DEFAULT_HIGHSCORE_VAR    = "2048最高分"
M.DEFAULT_HIGHSCORE_SIGNAL = "保存最高分"
```

读取时会依次尝试 `PlayerSelf → AvatarSelf → Level` 三个作用域，取第一个读到的数字，
所以变量挂在玩家上或关卡上都能兜住。

## 七、改参数

1. **只改 `config.lua`**。`DEFAULT_*` 是唯一真源，脚本里不写魔法数字。
2. 想让可视化编辑器同步：打开 `编辑器.html`（它内置的 `DEFAULTS` 必须与 `config.lua` 逐项一致），
   拖到满意后点「生成 config.lua 片段」，整段替换过去。
3. 编辑器底部还有两个**成品**可以点：

   - **版式自检**：把「真机才会暴露」的问题算出来——
     右列文字盒是否重叠（文本框最小高度按 36px 算）、是否越出 720 画布、
     棋盘是否压到右列、结算相框与信息面板是否打架、平移时长是否落在 100–150ms、
     连击时长是否比常规还慢 / 看门狗会不会误抢正常解锁（v004 新增）。

   可用「连按手感」相关参数一览（都在 `config.lua`）：

   | 参数 | 默认 | 作用 |
   | --- | --- | --- |
   | `DEFAULT_ANIM_MOVE_TIME` | 0.12 | 常规平移时长（需求 100–150ms） |
   | `DEFAULT_ANIM_MOVE_TIME_FAST` | 0.10 | 连击时的平移时长（别再往下调，会看不出位移） |
   | `DEFAULT_COMBO_WINDOW` | 0.55 | 两次有效操作间隔小于它算连击 |
   | `DEFAULT_INPUT_BUFFER` | 1 | 1 = 动画中按键只留最后一个并自动兑现 / 0 = 丢弃 |
   | `DEFAULT_SETTLE_GUARD` | 0.45 | 解锁看门狗宽限：平移后这么久还没解锁就强制放行 |
   | `DEFAULT_ANIM_INPUT_LOCK_EXTRA` | 0 | **已废弃**，仅为旧存档兼容保留 |
   - **生成脚本参数表**：列出要填进沙箱脚本参数的东西。

4. 改完跑一次静态校验（在工作区根）：

   ```bash
   python _shared/_check_blocks.py 2048_景苏     # Lua 块平衡
   python _shared/_check_refs.py   2048_景苏     # require / 模块函数 / state / config / DEFAULTS 同步
   ```

   **看退出码，不看文案**。退出码 0 = 通过。

## 八、真机 vs 模拟器（踩过的坑，全在本工程里根治了）

| 现象 | 原因 | 本工程的解法 |
| --- | --- | --- |
| 文本框变成实心色块，盖住下面的东西 | 不设 `bgColor` 会带出预制体底色（模拟器忽略该字段，本地看不出来） | 所有文本统一走 `utils.setTextBgTransparent()` |
| **矮盒子里的字一个字都不画** | 文本框有**最小高度**（实测 56/54/30 正常，26/22 全空白） | `utils.MIN_TEXT_H = 36` 兜高 + 显式 `adaptiveFontSize = false`；版式按兜高后的盒高排 |
| **大字号在真机上完全空白**（控件在、位置对、一个字都没有） | 还有第二道门槛：**盒高必须 ≥ 字号 × 行高系数（≈1.45）**，不够就不画。标题 62 号字 / 76 高、分数数值 34 号字 / 46 高，都差一点 → 空白 | `utils.textBoxHeight()` 双门槛兜高（`MIN_TEXT_H` 与 `字号 × 1.45` 取大）。★ 这也解释了「为什么 20 号字 / 36 高、44 号字 / 104 高都正常」 |
| 容器里的子控件整片消失 | 底图预制体带遮罩，容器只有 1×1 → 子控件被裁掉 | 建容器时显式 `enableMask = false` |
| 方块/文字上下层反了 | 真机按**创建顺序**（后创建在上），**模拟器渲染相反** | 关键层用 `SetAsLastSibling()` 显式提层（两引擎一致）；容器重排只走 `SetAsFirstSibling`/`SetAsLastSibling` |
| 按钮画得出来但点不动 | 图片控件没有光标事件能力，`pcall` 静默失败 | 可点区域一律用**光标检测区域**（`utils.createHit(..., true)`） |
| **按钮和文字一起消失** | 按钮是把「文字」建在 `if 按钮 then` 里的，按钮实例化失败（如 `buttonPrefabId` 没配）→ 文字也不建 | 自绘按钮：底图 / 文字 / 命中区**各建各的**，谁也不绑在谁身上（`utils.createButton`） |
| **只有文字、没有按钮底** | 底图是容器里最后一个创建的，模拟器「先创建在上」→ 被先建的面板底板盖住 | 底图创建后立刻 `raise`，再依次 `raise` 文字与命中区（顺序 base → label → hit） |
| 命中区变成一块色块压在按钮上 | 光标检测区域的预制体可能自带底色 | `createHit` 里显式 `imageColor = 透明` |
| 组合字变豆腐块 | 中文字体缺字形 | 方向键只用 `↑ ↓ ← →`；新符号先跑 `_tools/glyph_check.mjs` |

### 引擎行为：两个容易「想当然搞错」的点（本工程实测结论）

| 结论 | 说明 |
| --- | --- |
| **容器的 `SetLocalScale` 是生效的，并且会连带缩放子控件** | 引擎侧 `play-renderer.js` 用 PIXI 的 `setFromMatrix` 装配节点容器，PIXI 的父变换天然传给子节点。所以「整层缩放做自适应」这条路是通的（本作的 `containerScene` 就靠它把 1280×720 设计坐标映射到任意画布，PC 上 k=1.25）。 |
| **`SetSiblingIndex(i)` 在模拟器里是反的** | 实际插到数组下标 `len-1-i`。只能只用 `SetAsLastSibling()`（提层）/ `SetAsFirstSibling()`（沉层），这两个在两引擎里效果一致。 |

> ⚠️ 工作区提供的离线渲染器 `_tools/render_scene.mjs` 早先**只累加 tx/ty、不累加父级缩放**，
> 导致「设了 0.5 倍缩放，离线图里还是原尺寸」，一度被误判成「模拟器不支持容器缩放」。
> 现已改为完整仿射累积。**离线图与实际不符时，先怀疑渲染器，再看引擎源码**。

### 动画系统：三个「不报错但全都不动」的坑（v002 修）

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| **动画只有第一段能动，后面全部不动**（方块永远停在缩放 0，看起来像「方块没画出来」） | `anim.update` 里先遍历、再 `items = keep` 覆盖。而「链式补间」（delay 回调 / onDone 里再 `anim.tween`）正是在回调里新建补间 → 新增的那条被覆盖丢掉 | 改成**按开帧数量推进 + 就地压缩**，见 `anim.lua` 的 `M.update`。★ 任何「回调里再起动画」的时序系统都要防这一手 |
| 粒子 / 「+N」飘字出现在**离合并格两格远**的地方 | 棋盘用「棋盘中心」当原点，而 `containerFx` / `containerHud` 挂在场景原点，两套坐标系差一个 `(BOARD_CX, BOARD_CY)` | 统一走 `utils.boardToScene()` 显式换算 |
| 结算整屏发灰、相框变灰白、面板文字发闷 | `containerMenu` 内部的遮罩只 `sink` 了一次；之后每新建一个子控件，相对顺序都会变，遮罩就跑到相框/面板之上去了 | 子控件全部建完后用 `menu.layersMenu()` **一次性重排整层**（`sink`/`raise` 只解决「当时」的顺序） |

> 通用规律：**`SetAsLastSibling` / `SetAsFirstSibling` 只改「调用那一刻」的相对顺序，
> 之后再创建同级控件就会失效。** 凡是有「底图 + 覆盖物」的同层组合，
> 要么让覆盖物最后创建，要么在**所有**兄弟都建完之后统一重排一次。

### 输入手感：连按 WASD 为什么不跟手（v004 修）

**症状**：按住方向键连续推，第二次以后要等整套动画（~0.32s）播完才动，长按像在排队。

**原因**：输入锁卡在「整套动画」的收尾上 —— 平移、合并弹跳、新方块弹出三段串起来
才解锁，而其中真正必须等的只有平移。

**做法（四件事配合）**：

| 措施 | 代码位置 | 说明 |
| --- | --- | --- |
| 输入锁只覆盖**平移段** | `view.playAction` 的 `onSettled` | 平移一结束就回调 = 解锁，合并/新方块在后台并行播 |
| **拆 tag**：`TAG_MOVE` / `TAG_FX` / `TAG_TICK` | `view.lua` 顶部 | 下一次动作只清 `TAG_MOVE`，装饰动画不会被掐断 |
| **输入缓冲**：只留最后一个方向 | `game.lua` 的 `state.pendingDir` | 扔早留晚：连按时永远执行最新意图，而不是逐条补播 |
| **连击加速** + **看门狗** | `DEFAULT_ANIM_MOVE_TIME_FAST` / `DEFAULT_SETTLE_GUARD` | 0.55s 内连推就把平移压到 100ms；解锁超时则强制放行 |

> ★★ **最凶的那个坑**：解锁回调（`onSettled`）原本和装饰动画共用一个 tag，
> 而 `view.syncWithPop()`（开场、撤销、重开都会走）里有 `anim.clear(TAG_FX)`。
> 开场黑幕 `fadeIn` 是 0.18s —— 玩家在这 0.18s 内按一下方向键，那条「平移结束就解锁」
> 的延时补间就被 onPeak 清掉了，**`state.inputReady` 永远是 false，整个游戏再也动不了，且不报任何错**。
> → 关键时序回调必须单独一个 tag（`TAG_TICK`），只有 `doReset` / `undo` 的
> `clearAll()` 能清它，而那两处会手动把 `inputReady` 置回 true。再加上看门狗兜底。

**验证脚本**（不用真机就能复现）：`_tools/_probe_combo.mjs` 把调试探针注入存档的
`game.lua`，在无头模拟器里每 4 帧按一次方向键，共 N 次，画面上直接打出
「按了几次 / 成了几次 / 解锁回调触发几次 / 有没有残留补间」。判定标准：

```
P(调用) == A(收到 onSettled) == S(onSettled 真的跑了) == st(有效移动步数)
dl(新建补间) == df(已触发补间)          ← 相等 = 没有任何补间泄漏
rdy=true  pnd=nil  err=-               ← 结束后必须处于「可输入、无残留」
```

实测 v004：连按 200 次 → `P200 A200 S200 D200 dl1182 df1182 st200`，零丢弃、零泄漏。

更多细节见工作区根的 **《开发经验与避坑手册.md》**。

## 九、版本留档（每个版本都能在模拟器里选中试玩）

```bash
# 每做完一次小修改，留一版（会做两件事：源码快照 + 生成一份可试玩存档）
node _tools/version_snapshot.mjs --game 2048_景苏 --title "本次改了什么"
node _tools/version_snapshot.mjs --game 2048_景苏 --list                 # 看台账
node _tools/version_snapshot.mjs --game 2048_景苏 --title "x" --no-save  # 只存源码

# 回滚到某版（会先把当前代码备份到 _history/_before_restore_<时间戳>/）
node _tools/version_restore.mjs --game 2048_景苏 --version v001
```

- 源码快照：`_history/vNNN_<关键字>/`（含 `NOTE.md`）
- 版本台账：`_history/INDEX.md`、`_history/versions.json`
- 可试玩存档：`_simulator/2048_versions/vNNN.web.save.json`
  → 双击工作区根的 `启动千星模拟器.bat`，在**「工作区存档」下拉**里就能看到
  `2048 · v001 · …` 这样的条目，逐版选中试玩，等于一套可视化版本回放。

  目前已留档：

  | 版本 | 标题 | 存档名 |
  | --- | --- | --- |
  | v001 | 棋盘·移动·合并·结算首版 | `2048 · v001 · 棋盘·移动·合并·结算首版` |
  | v002 | 链式补间与结算修复（当前） | `2048 · v002 · 链式补间与结算修复` |

> 首次生成试玩存档需要一份模拟器就绪存档（`_simulator/sim-ready.save.json`），
> 工具会自动补齐；补齐过程需要十几秒，属正常。
>
> ★★ 存档里的脚本**不等于**交付脚本（会被追加模拟器专属补丁），
> 所以交付/对比一律用工程源文件，别从 `_simulator/` 里往外拷。
>
> ★★ **改完源码一定要重新生成存档再去看画面**：存档里存的是「生成那一刻的源码副本」，
> 不重跑就渲染，看到的是旧代码 —— 排查时极易被它带偏（本项目就被坑过一轮）。
> 另外 `qxqy_websave.mjs` / `version_snapshot.mjs` 需要显式指定工作区：
> `export QXQY_WORKSPACE="<工作区绝对路径>"`。

## 十、已知边界与后续可做

- **撤销栈**默认留最近 64 步（`DEFAULT_UNDO_DEPTH`）。真正「开局到现在每一步」在
  超长局里会吃内存，所以设了上限——想要无限撤销就把它调大。
- **按钮全部自绘**（图片底 + 文本 + 光标检测区域），所以外观、按下态、禁用态都在
  `config.DEFAULT_PALETTE` 里调（`btn` / `btnDown` / `btnText` / `accent` / `accentText` /
  `dpadBg` / `dpadBgDown`）。需要圆角或描边时，把 `createButton` 里的底图换成对应的图片元件即可。
- **排行榜 / 云端存档**不在本作范围：目前只做「最高分」单值持久化。
- 若要做**主题切换**（换一套配色），`utils.palette()/pal()` 已经是唯一取色入口，
  把 `config.DEFAULT_PALETTE` 换成按主题查表即可，其余代码不用动。
