## 模拟器「点不动」彻底打通（真因：挂载节点矩形退化成一个点）

### 排查路径（每步都有实测，不是猜）
1. 场景 dump：164 个节点里 **cursor 类型 0 个** → 但这是假象，`scene.nodes` 不输出 cursor。
2. Lua 探针在 `script.object` 下直接建一个 cursor 控件 → **正中心能点中**，偏一点就不行。
3. 回读 `GetSizeDelta()` / `GetAnchoredPosition()`：设成 4000×4000 也读回 4000 → 尺寸写入是成功的。
4. 读 renderer 命中测试 `cn()`：
   ```
   m = Ae(父矩形, 本控件)      // 本控件在父坐标系里的矩形
   v = 逆矩阵(父世界矩阵 × 本控件变换) 作用于点
   if v 不在 m 内 → return null   // ← 关键：不再下钻子节点
   if 是容器 → 继续下钻
   ```
   ⇒ **只要任一层祖先的矩形不含该点，整棵子树都点不到。**
5. 挂载节点（server-container 实例）默认 `anchorMin=anchorMax=0.5`、`size=0`
   → 矩形 = 中心一个点 ⇒ 只有正中心能命中。**这与坐标映射无关。**

### 修法
`_tools/_sim_common.mjs` 的 `buildCursorShim()`：在引擎 `OnStart` **之前**
把 `script.object` 改成铺满画布（`SetAnchorMin(0,0)`、`SetAnchorMax(1,1)`、`SetSizeDelta(0,0)`、
`SetAnchoredPosition(0,0)`）。中心不变 → 既有排版零影响。

### 顺带
- `点灯迷题2D/view.lua`：格子命中区从 `cs` 改成 `cs + gap`（46→51），
  正好铺满 51 间距，消除「点在缝里没反应」。
- **`pointer` 注入坐标是「y 从上往下增」**（此前一直按 y 向上算，导致大量误判为"点不中"）。

### 实测
8×8 棋盘逐格点击：`(1,1)(1,8)(4,4)(5,5)(2,7)(7,2)` 全部命中，步数逐个 +1；
纵向扫描 124~527（画布坐标，y 向下）连续可点，覆盖整块棋盘。

### 附带发现（工具层）
- `qxqy_websave` 的 `buildParamShim` 兜底表已含 `cursorPrefabId` / `containerPrefabId`。
- 编辑器会话槽上限 8：反复跑探针会 `Editor session limit reached` → **重启 server.js** 即可。
- 端口被占时新 server 直接 `EADDRINUSE` 退出 —— 先 `netstat` 找 PID 再 `taskkill //PID x //T //F`。

### ★★ 层叠顺序的真因（这次从引擎源码里挖出来了，比记忆里的说法更准）
`beyond-simulator-web/dist/server.js` 的绘制遍历：
```js
for (const arr of byParent.values()) arr.sort((s,u)=> B(s.z) - B(u.z));  // 升序
function walk(id, m){ const arr = byParent.get(id)||[];
  for (let i = arr.length-1; i>=0; i--) { draw(arr[i]); walk(arr[i].id); }  // 再倒着画
}
```
⇒ **z 大的先画 = 在下层**。而 z 就是同级创建序号（越大越晚创建）。
⇒ **"后创建在上"在模拟器里是反的**；真机才是后创建在上。
⇒ `SetAsLastSibling()` = `SetSiblingIndex(len-1)`，而模拟器的 `SetSiblingIndex(i)` 实际插到
   `len-1-i` → 插到 0 = 最上层。所以 **`utils.raise()` 按「下→上」顺序连续调用，两个引擎都对齐**
   （真机逐个挪到末位，模拟器逐个挪到首位，最终相对顺序一致）。

**表现**：点灯迷题2D 通关面板里底板 `edge`（最先建、z 最小）画在最后 → 把彩图整片盖住，
只剩一块深蓝（用户截图就是这个）。修法：`doFinale` 里建完所有元素后按
`edge → paperC → 四块 → colorLayer → flash → titleC` 逐个 `utils.raise()`。

**推论**：以后凡是「同一父节点下元素重叠」的地方，都必须显式 raise 定序，
不能指望创建顺序（`createButton` 里早就有这套写法，可作为范例）。
另：`_tools/_finale_shots.mjs` 预览必须按 **z 降序**画才和引擎一致；
之前改成升序反而把背景画到最上面，误判了好几次。

## 翻页 v2：改成「条带法卷页」（用户给了 Canvas 2D 参考实现）

### 做法（book.lua）
- **纸面按 40 条竖带拆开**：`sheetPaper()` 现在建 40 个 strip 容器（每条含纸面 + 首条的
  书脊 / 末条的页口），登记进 `pageMeta.sheets`。
- **页内容按元素登记**：`rect/C/T/place` 四个包装器在 `recordOn=true` 时把
  `{c, x, y, w, hex, text}` 记到 `pageMeta.elems`。为此把 4 块 8×8 象限**拍平**成
  页面直属子节点（不再套 box 容器），否则 150px 的 box 只能整块压缩、卷不动。
- `curlPage(meta, foldX)` 每帧：θ = (x - foldX) / R
  - 纸带：`scaleX = cosθ`，`x' = foldX + R·sinθ`，`y' = -R(1-cosθ)·0.22`，
    颜色按 θ 从纸色渐变到深棕，θ<0.45 再加一道提亮（纸卷高光）
  - 内容：同一条曲线；θ ≥ 60° 直接隐藏（纸一卷起来就看不见正面了）
- 参数：`NS=40`（≈22px 一条）、`CURL_R=0.26·BOOK_W`、`CURL_DY=0.22`、`DUR=0.8s`、
  缓动 `inOutCubic`。前进=旧页从右缘卷到左边；后退=新页从卷曲状态展开。

### 四个必须记住的坑
1. **θ≥90° 的纸背不要画**：2D 里画出来就是一大片近黑，把整页糊住。直接 `setVisible(false)`。
2. **卷起的纸带要 `raise`，落回平面要 `sink`**：纸带比内容先创建（在下层），
   不 raise 的话「被卷走的格子」会画在纸卷上面，糊成一团。用 `sh.up` 标记只在切换时动一次。
3. **文字元素必须存 hex 字符串**：`T()` 原来收的是 `utils.hexToColor()` 的 Color 对象，
   卷页结束用 `setTextColor` 复原时取不回原色 → 文字变半透明幽灵。改成传 "3B2E22" 这种字符串。
4. **大块装饰要标 `chrome`**（图片外框）：整块刚性压缩会跟逐格压缩的格子错位，
   翻页期间直接隐藏最干净。另外把图片内层白底删了（和纸色几乎一样，留着就是一块卷不动的板）。

### 顺带
- 到头（封面/最后一页）的箭头改成**整组隐藏**，只 `setButtonEnabled(false)` 会留一个没有箭头的灰方块。
- 预览渲染器已能正确累乘父级 scale/rotation，条带卷页的形变在离线帧里是可信的。

## 翻页 v3 + 通关演出回画册（2026-10-19 下午）

### 翻页丝滑化的三个关键点
1. **按「条带左右边缘」各自的 θ 算，而不是条心**：
   `nl = foldX + R·sin(θL)`、`nr = foldX + R·sin(θR)`、宽 = nr-nl、位置 = (nl+nr)/2。
   相邻两条的边界严格重合，曲面连续 → 台阶感消失（只按条心算必出锯齿）。
2. **每帧只做必要的写入**：纸带记 `sh.shade`（阴影量化到 26 档，变了才 setColor）、
   `sh.vis`（可见性变了才 setVisible）；元素记 `e.lastA`（alpha 变化 > 10 才改色）。
   旧实现每帧对 300+ 元素无条件 setVisible/setColor，是卡顿主因。
3. **尾段提前销毁旧页**：`p > 0.94` 时 `destroy(oldPage)`（此时页面已全空），
   不要留到 `onDone` 一次性销毁几百个控件 —— 那一下就是「翻到最左侧卡一下」的真凶。
   翻页时长 0.80 → **0.54s**。

### 通关演出 → 画册（`finaleToBook`）
顺序：彩图副本（`art.artRects` 重画，非复用面板控件）从面板中心 → 书页图片位（`book.PIC`）
→ 扇形蒙版合拢（20 片扇叶，宽 = 2R·tan(π/N)·1.35，从中心放射 `pos = dir·R·s`、`scale = s`）
→ 蒙版全盖的瞬间销毁面板 + `book.showPage(章节, grey=true)` → 扇开 → `book.celebrate()`。

### ② 末尾卡顿的两个真因
1. **一次性销毁整页**：`onDone` 里 `destroy(oldPage)` 会一瞬间销毁 40 条纸带 + 300 多元素 + 命中区。

   `clearPage()` 也走同一条队列（showPage / 换页都不再一次性销毁）。
2. **最后一帧突变**：折线贴到左边缘时残留几片纸边会「啪」地消失。加了
   **末尾 150px 渐隐**：`fade = (foldX + W/2) / 150`，纸带 alpha 与内容 alpha 都乘它，
   `fade <= 0.012` 才真正隐藏。这样最后一小段是淡出的。
