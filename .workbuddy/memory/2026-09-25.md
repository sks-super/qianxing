## 三、TickHop 工程实现

### 模块划分
`game.lua`(入口/容器/输入/信号) · `config.lua`(参数真源 + LEVELS) · `state.lua` · `timeSystem.lua`(时间内核) · `level.lua`(关卡构建与平台刷新) · `physics.lua`(玩家 AABB 运动碰撞) · `utils.lua` · `audio.lua` · `signal.lua` · `fadeScreen.lua` · `编辑器.html` · `README.md` · `实现方案.md`

### 核心设计
- **时间系统**：`now` 递减到 0；`tick = floor(now)`；平台 `tick == 当前tick`（或 `tick == -1` 永驻）时为实体，否则虚化且不可碰撞；只改颜色 alpha 不销毁重建。支持 `add`（加时，可复活计时）、`reverse`（流向翻转）、`setRunning`（暂停）。
- **黑幕期间不扣时**：关卡在 `fadeScreen.onPeak` 重建后立即 `setRunning(false)` + `state.pendingStart = true`，等黑幕散尽（`fadeScreen.active == false`）再启动计时。
- **物理**：分轴 AABB 解算（先 X 后 Y），含土狼时间、跳跃缓冲、可变跳跃高度、下落重力倍率、物理子步长。
- **容器**：7 层 bg → platform → goal → pickup → player → hud → fade。
- **坐标系**：原点画布中心，Y 向上为正，所有对象用中心点坐标，编辑器与运行时同一套。
- **输入**：键盘 A/D/←/→ + 空格/W/↑；触屏自动创建虚拟按钮（`◀ ▶` + 「跳」），与键盘写入同一状态。
- **道具**：`type = "time"` 加时 / `"reverse"` 时间反转，`level.checkPickup()` 判定、game 施效。
- **示例关卡**：3 关（教学常驻平台 / 交替踏点 / 加时与反转）。

### 编辑器（`编辑器.html`）
单文件零依赖，三栏布局（工具栏 / Canvas / 属性面板）。
特色功能：**秒数预览滑块** —— 拖动即可看到任意秒数下哪些平台亮起，直接用于验证「时间窗可行性」；这也是 TickHop 关卡设计最核心的辅助。
支持导入/导出 Lua，导出的 `M.LEVELS` 格式与 `config.lua` 手写数据逐字节同构。

## 二、关键机制（决定了怎么把我们的 Lua 灌进去）

1. 运行时是 Lua 5.3（fengari），全局：`print printerr typeof require Color Enum game script query`。
2. 模块**不是从磁盘自动读**，而是来自存档脚本表的 `path` + `source`；
   `require("default_import_file/<path>")` 解析，注册时自动加别名。
3. **本项目用裸 require（`require("config")`）→ 注册 path 必须写裸文件名** `config.lua`，
   带 `TickHop/` 前缀会 `failed to load script 'config'`。
4. 生命周期：chunk → `OnInit` → `OnEnable` → `OnStart` → 每帧 `OnUpdate(dt)`，与本工程写法一致。
5. 只有客户端控件可挂脚本（`controlAsset:"client"`）；空工程挂到 `n1`(container) 即可。

# 第二轮：把上面两个缺口补齐，TickHop 在模拟器里跑通完整玩法

（重新启动模拟试玩时做的；结论修正了本文第四节的两条判断）

## 六、缺口 1 解决：脚本参数兜底（不改工程源码）

- 断链位置三处：`studio` 的 `addScript` 丢弃 `op.params` → `compileProject` 不带 `params`
  → `mountSpecScripts` 不转发；`script:GetParam()` 恒 `nil`，工程「必填参数没配」的校验
  直接把整局挡在 `OnStart` 之外。
- ❌ 覆写 `script.GetParam` 不可行：`script` 带 `Script` metatable，禁止写同名字段
  （`cannot set GetParam, no such field`）。
- ✅ 可行做法：工程的 `getParamNumber` 是脚本环境里的**普通全局函数**，在入口脚本**末尾**
  追加覆盖即可（`OnStart` 由引擎在 chunk 执行完后才调用，覆盖已生效）。
- 落地为 `qxqy_mount.mjs --params '<json>'` / `--preset sim`，只注入模拟器，`.lua` 未动。

## 七、缺口 2 解决：模拟器就绪存档（补 prefab 模板）

- 模拟器 prefab 注册规则：`registerTemplate(prefabIndex = node.guid)`，取自 **client 工程 `root.children`**。
- `qxqy_simsave.mjs` 在存档里补两个模板节点：
  `guid=2000001` image（`imageId: 100001` = `rect` 原语，可被 `imageColor` 染色）→ `rectPrefabId`；
  `guid=2000002` textbox → `textPrefabId`。
- 原型节点**克隆存档里已有的** image / textbox（保证 `giaRaw`、`transformByPlatform` 合法），
  再清空模板根 `n1` 装饰子节点、清空脚本表由挂载驱动重灌。

## 八、⚠️ 关键发现：模拟器宿主截图渲染器 z 序反置

- **现象**：逻辑完全正确（黑幕 6 帧渐入 → 建关 → 12 帧渐出 → 计时启动，逐帧时间线正常），
  但截图只剩一片背景色。
- **根因**（以已安装 bundle `dist/index.js` 为准，与仓库源码可能不同版本）：
  - `Rs` 收集时 `z` = 节点在父 `children` **数组中的下标**；
  - `Bs` 按 **z 降序**入队绘制（`for(s=c.length-1;s>=0;s-=1)`），`Us` 顺序绘制 → **下标越小越靠上**；
  - 而 `children` 是按创建顺序 `push`，且 `GetSiblingIndex()` 返回 `len-1-数组下标`、
    `SetSiblingIndex(t)` 实际插到 `len-1-t`（即内部约定「数组下标 0 = 最上层」）。
  - 后果：工程里**第一个创建的背景容器被画到最顶层**，盖住平台/玩家/HUD；
    默认工程脚手架（下标更小）反而露在外面，极具误导性。
- **对照实验**：`_px.mjs` 采样 frame12 整屏 `#111114`，正是工程背景色 `0xFF111114`。
- **规避**：`--fix-zorder <帧>` 把 7 个容器依次 `SetAsFirstSibling()` 送到数组末尾
  （因为 SetSiblingIndex 语义是反的），绘制顺序变成 `bg→platform→goal→pickup→player→hud→fade`；
  顺带隐藏默认工程脚手架。**工程源码未改**。
- `beyond-simulator-web/dist/worker.js` 是同一份 bundle → **Web 编辑器试玩预览也是同样的反置**。

## 七、Web 试玩根因定位与修复（2026-09-25 结案）

**症状**：浏览器试玩画面只有默认脚手架（「文本」/蓝色「预设按钮」/「★」图片），游戏内容全无。

**排查结论**（推翻上面第六节的猜测——client 工程其实导入成功了，

1. 切到 client 工程看树，`n1(Lua实例化面板) + tsRect(2000001) + tsText(2000002)` 齐全，
   `game.lua` 的 `mounted=true` —— 导入没问题。
2. 真正的机关在 `studio/index.js`：
   - `playStart` = `startPlay(projects.server, { templatesProject: projects.client, ... })`
     → **场景根取自 server 工程，client 只当可实例化模板库**；
     场景根 = `clientRoot(server)` = server.root(server-container) 下第一个 container，**即 server 的 n1**。
   - `resolveScriptTarget(script)`：`controlAsset` 为**空**时回落到 `findControlTarget()`，
     按 `[server, client]` 顺序查 → **先命中 server**；一旦显式指定 `client-control-template`，
     就挂到 client 的模板根上——**模板根永不被实例化，脚本静默不执行**。
3. 所以 `qxqy_websave.mjs` 里写的 `controlAsset: 'client'` 是致命错误；
   而 MCP 的 `op.controlAsset='client'` 反倒因为不等于任何常量被判成空值，歪打正着走通了。
   （这解释了「MCP 能跑、Web 不能跑」的全部差异。）

- `qxqy_websave.mjs`：入口脚本 `controlId` = **server 场景根 id**、`controlAsset` = `SERVER_ASSET`；

## 十、第五轮：亮起态标签被平台本体盖住（真凶）＋ MEMORY.md 瘦身（2026-09-25）

### 1) 上一轮「反色已完成」的结论是错的
- 现象：像素探针报告亮起态有 360 个深色像素，于是判定「数字已显示」。
  **但那 360 px 是平台上下边缘之外的背景**（采样区域取 60×28，平台本体只有 22 高）。
  只看「最暗/最亮对比度」会被背景骗到。
- 真凶：`containerPlatform` 的子节点是 `[本体1, 本体2, 标签]`（创建顺序 push）。
  真机里后创建的在上面，工程代码是对的；但模拟器 z 序反置后**标签被压在两个本体下面**——
  熄灭态本体 alpha=40 能透出来，**亮起态本体 alpha=255 把数字完全盖住**。
- 修法：给 `_sim_common.mjs` 的 `buildZOrderFix` 加一段——**每帧幂等**地对每个
  `state.platforms[i].label` 调 `SetAsLastSibling()`。必须每帧：平台是黑幕散尽后才建的，
  只在修正帧（第 3 帧）做时 `state.platforms` 还是空的（日志「提升标签=0」暴露了这点）。

### 2) 兄弟顺序 API 的真相（重要）
```js
// client/lua-runtime/src/scene.js
SetSiblingIndex(index){ const arr=this._parent.children, i=arr.indexOf(this), max=arr.length-1;
                        arr.splice(i,1); arr.splice(max-index, 0, this) }   // 实际插到 len-1-index
SetAsFirstSibling(){ return this.SetSiblingIndex(0) }               // 数组末尾 = 最底
SetAsLastSibling(){ return this.SetSiblingIndex(len-1) }            // 数组下标 0 = 最顶
```
即 **`SetSiblingIndex` 是反的，但两个便捷方法的效果与真机一致**。
踩过的坑：一开始对标签用了 `SetAsFirstSibling()`，等于把它推到最底层，
日志显示「提升到顶层: 1 个」但画面纹丝不动 —— 改成 `SetAsLastSibling()` 才对。
结论：**只用 First/Last 两个便捷方法，不要自己算索引**。

**需求**：缺「选关」与「通关提示（胜利 UI + 下一关按钮）」。

### 1) 设计：一批控件扛三态
`menu.lua`（556 行）**一次性**建好全部控件并挂 `containerMenu`，之后只改文字 + `SetActive`，
**切换零分配**。三态共用同一套「遮罩 + 面板 + 标题 + 副标题 + 网格/数值区 + 底部提示 + 按钮行」：

| 模式 | 触发 | 网格区 | 底部按钮 |
|---|---|---|---|
| `select` | 按 `L` | 关卡卡片（`√` 通关标记、光标高亮 `accent`） | `继续游戏` + `重玩本关` |
| `win` | 到达终点（`AUTO_WIN=1`） | 剩余时间大字 | `重玩本关` + `下一关 ▶`（末关→`返回选关`） |
| `fail` | 时间耗尽 / 掉出关卡 | 失败原因 | `重玩本关` + `返回选关` |

`select` 在 `gameWon or gameFailed` 时不提供「继续游戏」（否则回到已结束画面）。

### 2) 分页与光标
`gridLayout()` 由 `COLS × ROWS` 推 `perPage / pages`；卡片按索引线性排入，左右两侧 `◀ ▶`
方形箭头（44×44）翻页，页码并入底部提示文本。
`state.menuCursor` **存可玩关序号而非页内下标**，跨页时 `moveCursor` 自动 `setPage`，
「光标所在关」与「当前页」永远自洽，无需额外同步逻辑。

### 3) 暂停语义（关键）
`M.open()` 置 `state.paused = true`；`game.OnUpdate` 首行：

```lua
if state.paused then level.updateTimerDisplay(); fadeScreen.update(dt); return end
```

→ **冻玩法**（计时/物理/拾取/结束判定全不跑）但**黑幕与 HUD 仍推进**，
避免面板期间黑幕卡死、倒计时文本冻在错值。

### 4) 输入分流三类（`bindKeys` 重构）
- `bindPair`：玩法键，`menuOpen` 或 `keysEnabled` 假 → `return false`
- `bindMenuKey`：`←` `→` 移光标、`空格/W` 确认，**仅 `menuOpen` 时响应**
- `bindGlobal`：`R`/`T`/`P`/`L`，**绕过 `keysEnabled`**
  ★ `L` 必须绕开总开关——面板打开时 `keysEnabled=false`，否则**关不掉面板**。
  `R`/`T` 在 select 面板打开时让位给面板按钮；`P` 任意面板打开时不响应。

### 5) 依赖解耦
`menu.lua` **不 require `game`**（避免 `game→menu→game` 循环），改由 `OnStart` 注入：
`menu.setActions({ onSelect=loadLevel, onReload=reloadLevel, onNext=nextLevel })`。

### 6) 第 8 层容器
`bg→platform→goal→pickup→player→hud→**menu**→fade`：面板压 HUD、在黑幕之下。
面板内部三层：遮罩（alpha 215 压暗画面）→ 面板底 → 文字/卡片/按钮。

### 7) 参数（`config.lua` + `编辑器.html` DEFAULTS 同步，共 21 项）
`MENU_OVERLAY_ALPHA=215 / PANEL_W=600 / PANEL_H=420 / TITLE_SIZE=44 / TEXT_SIZE=24 /
HINT_SIZE=18 / BTN_W=200 / BTN_H=60 / BTN_GAP=24 / CARD_W=150 / CARD_H=62 /
CARD_GAP_X=18 / CARD_GAP_Y=16 / CARD_TEXT_SIZE=20 / COLS=3 / ROWS=2 /
PAGE_BTN_W=44 / PAGE_BTN_H=44 / INPUT_ENABLED=1 / AUTO_WIN=1`
配色追加：`overlay=08080C / panel=1E1E28 / card=2A2A36 / panelText=F2F2F2 /
accent=5BC8F5 / accentText=0A0A10 / dim=8A8A9A / clear=7AD6A0`。
撤销一处过度设计：`menuPageText` 文本节点（页码并入底部提示后删除），state 声明同步清理。

## ★★ 两个收尾时发现的真问题（都已修）

### A) `containerHud` 内部也反置 → 触屏按钮只剩空方块

`createTouchButton` 是「**先建底图矩形、再建标签文本**」（标签用裸 `utils.createText`，**未存引用**）。
真机后建的在上面 ⇒ 文字可见；模拟器反置后**标签被自己的底图压住**，`← → 跳 关` 全变成一个空方块。
之前只修了平台标签与菜单，**漏了 HUD** —— 因为早期验证只看「关卡提示文本在不在」，没注意按钮。

修法（`_sim_common.mjs` 的 `buildZOrderFix`，每帧幂等）：
`containerHud:GetChildren()` 里**所有 `text` 非空的控件**一律 `SetAsLastSibling()`。
`text` 是**属性字段**（不是 getter），图片控件读它会进 `pcall` 的 error 分支 → 安全跳过。
HUD 内没有任何控件需要盖住文字，所以无脑提升即可。

> **规律总结**：真机「后创建的在上面」，模拟器整个反过来。凡「底图 + 覆盖其上的文字」
> 的两节点组合都要显式提升文字。新增覆盖式 UI 时先想这条。

### B) 中文字体缺 `◀ ▶ ✓` → 真机会渲染成豆腐块（**这个会影响真机，不只是模拟器**）

我在界面上用了 `◀ ▶`（翻页箭头 / 触屏按钮）、`下一关 ▶`、`✓`（通关标记）。
实测发现**雅黑 / 宋体 / 黑体都没有这三个字形**，会画成豆腐块。

检测方法（写进 `_tools/glyph_check.mjs`，**可靠**）：
把候选字与**私用区码位**（`U+E000`，任何字体都无字形）在同一字体下各渲染一张位图，
**逐像素比对**——完全相同即为缺字。
（先试过「比宽度」，不可靠：SimSun 的 notdef 宽 40，而 `→` 也是 40，会把好字形误判成缺字。）

实测结果：
- **缺**：`◀`(25C0) `▶`(25B6) `✓`(2713)
- **有**：`←`(2190) `→`(2192) `↑`(2191) `√`(221A) `★`(2605) `◆`(25C6) `·`(B7) `×`(D7)

已全部替换：触屏按钮与翻页箭头 `◀ ▶`→`← →`；`下一关 ▶`→`下一关 →`；通关标记 `✓`→`√`。
（`★` 只出现在 `.lua` 注释里，注释不渲染，无需处理。）

### C) 新增 `render_scene.mjs` 的 `cleared` 场景
「通关第01关 → `T` 下一关 → `L` 开选关」，用于核对卡片上的通关标记。
渲染确认：`第01关 √`（绿色 `clear` 色）+ `第02关` 光标高亮 + 副标题「共 3 关 · 已通关 1 关」。

### D) 工具链踩坑（给自己）
**同一文件的多处修改不要在同一批并行下发**：并行 Edit 之间会互相覆盖，
出现「工具报成功、磁盘没变」的静默失败（本次 README 与 menu.lua 各中招一次）。
→ 改完必须 `grep`/`sed -n` 复核，别信返回值。

## ★ 新发现：模拟器 z 序反置**不只发生在容器之间，容器内部同样反置**

此前只知道「7 个容器之间要 `--fix-zorder`」。这次做面板才发现**每个容器内部子节点也被反置**：

- 面板里**最先创建的遮罩被画到最顶层**，盖住整个面板；
- 卡片文字被**自己的底色**压住 → 亮起态 alpha=255 完全看不见文字。
- （与之前平台容器里「标签被压在本体下面」是同一个病。）

**修法**（在 `_tools/_sim_common.mjs` 的 `buildZOrderFix`，**每帧幂等**执行）：
- `__lift()`（`SetAsLastSibling`）→ 卡片/按钮/箭头 label + `menuTitle/Subtitle/Footer`
- `__sink()`（`SetAsFirstSibling`）→ `menuPanel`，**再** `menuOverlay`
  ★ **先面板后遮罩**：遮罩要盖住游戏画面，但**不能**盖住面板。
- 每帧做而非一次：平台/菜单建得比容器晚，只做一次不够。

这是**模拟器专属修正，工程源文件未动**（真机不反置）。

## ★ `_tools/render_scene.mjs`（新增，把 `scene.nodes` 渲染成 PNG 核对布局）两个坑
1. 节点 `matrix.tx/ty` 是**相对父节点**的偏移 → 必须写 `absOf(n)` 沿 `parent` 链**累加**，
   再 `W/2+x, H/2-y`（世界 Y 向上为正）。初版直接读 `tx/ty`，所有控件叠在世界原点。
2. 图片控件色值字段是 **`imageColor`**，不是 `color`（所有 image 节点的 `color` 都是 0）→ 初版色块全不显示。
   文本控件才是 `fontColor`。

**隐藏控件（`SetActive(false)`）不出现在 `scene.nodes` 里** → 验证显隐只能靠「文本有无」，
不能靠节点是否存在。像素采样（沿 x=640 竖扫 `menu_select.png`）确认面板底 `#1e1e28` 跨 y≈150~570、
卡片 `#2a2a36`、底部按钮 `#464653/#818191`，层级正确（遮罩在面板之下）。
