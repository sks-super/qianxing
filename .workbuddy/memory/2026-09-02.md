# 2026-09-02

## 需求：修复「服务器发送『进入关卡』信号后关卡未加载」

### 根因分析（改动前）
1. **容器创建写在 `OnStart` 内部**，`doLoadLevel` 若在容器就绪前被调用（或容器被销毁/未创建成功），后续所有物件挂载都会拿不到父节点 → 关卡静默不显示。
2. **`signal.register` 失败被静默吞掉**：注册不成功时没有任何报错，服务器信号来了也不会触发。
3. **参数解析脆弱**：只认 `signalParams[1]` 是 number，若服务器下发的是 userdata（需 `GetInt(i)` 取值）或字符串数字，直接走 else 分支打印一句「参数异常」，关卡不加载。
4. **`fadeScreen.start` 无返回值、无日志**：黑幕控件创建失败时走 `opts.onPeak()` 直切，但如果过渡本身不推进，`onPeak` 永不被调用 → 关卡永久停在「排程了但没加载」。
5. `OnStart` 首关加载失败时 `return`，未启用 `OnUpdate` → 连兜底逻辑都不跑。

### 修复内容
**config.lua**
- 新增 `M.DEBUG_LOG = true`（调试日志总开关，上线可关）。
- 新增 `M.LEVEL_LOAD_FALLBACK_TIME = 1.0`（黑幕过渡超时兜底秒数）。

**utils.lua**
- 新增 `utils.dlog(tag, msg)` / `utils.dlogerr(tag, msg)`：统一前缀 `[DBG][tag]` / `[ERR][tag]`，受 `config.DEBUG_LOG` 控制（`dlogerr` 始终输出）。
- 新增 `utils.dumpParams(params)`：安全转储信号参数/userdata（全程 pcall，不因未知类型抛错）。

**signal.lua**（重写）
- 日志源改用 `config` 叶子模块，**避免 utils ↔ signal 循环 require**（utils 已 require signal）。
- `signal.register` 返回布尔值；注册前置检查全程 pcall（`type(script.RegisterServerSignalHandler)` 在 userdata 上直接索引可能抛错）。
- 新增 `signal.getParamInt(params, index)`：稳健取整数，兼容数组表 `[1]`/`[0]`、裸数字、数字字符串、userdata 的 `GetInt/GetInt32/GetNumber/GetFloat/GetValue/ToNumber`；每个 getter 用 pcall 包裹。

**fadeScreen.lua**
- `M.init()` / `M.start()` 加日志；`start` 返回是否成功排程；onPeak 触发时打日志。

**game.lua**
- 新增模块级 `createContainer()` + `ensureContainers()`：8 个层级容器（rope/board/world/candy/target/text/blade/fade）可在任何时候检查并补建，返回 `(全部就绪?, 缺失列表)`。
- 新增 `runLoadLevel`（= `protectedRunLoadLevel`）：pcall 包裹 `doLoadLevel`，失败时打印 `失败阶段=[currentLoadStage]` 与错误。
- `doLoadLevel` 全程用 `currentLoadStage` 标记阶段：准备 / 写入关卡参数 / 容器检查 / 清理拖尾 / 创建糖果 / 挂载蛋糕像素 / 创建绳子 / 创建目标 / 创建星星 / 创建泡泡 / 创建尖刺 / 创建文本框 / 创建木板 / 刷新显示与初始化物理。

## 四次修复（实验 A 日志分析）：轮询刷屏淹没真实事件 + 信号仍未送达

### 实验 A 日志揭示（用户贴 16:50 与 17:02 两段全量日志）
1. **整个日志（含实验 A 发送窗口）中 `[RAW][进入关卡] 回调被触发` 一次都没有** → 服务器「测试/进入关卡*」信号依旧未送达 handler；启动时 17 个监听（进入关卡 + 0..15 + 测试）全部注册成功，但引擎从未回调。
2. **海量 `[RAW][customVar] 变量变化回调触发 ... 读取到 nil` 是本地轮询自嗨，不是服务器事件**：
   - `OnUpdate` 中每 0.2s 的兜底轮询会直接调用 `onCustomLevelChanged`，而该函数**首行无条件打印 `[RAW]`**，读到 nil 后又打一行 `[ERR]` → 5 次/秒 × 3 行 = 日志墙，把真正的服务器事件完全淹没，还制造出「服务器变量改了但读不到值」的假象。
   - 实测 server 从未设置 CURRENT_LEVEL 时，这段日志几乎全是轮询噪音。

### 修复内容（继续叠加，未回退既有内容）
**game.lua `onCustomLevelChanged` 增加来源区分**
- 函数签名加第 3 参 `source`：`"handler"`（引擎 RegisterCustomVariableChangedHandler 真回调）vs `"poll"`（OnUpdate 每 0.2s 轮询）。
- **只有 `source="handler"` 才打印 `[RAW]`**；`source="poll"` 读取到 nil 时**完全静默**（nil=服务器从未设置，属正常态），读到有效数字且变化才打 `[DBG][customVar] 从自定义变量加载关卡: 来源=poll ...`。
- 重复关卡号去重分支不再刷日志。
- `OnUpdate` 轮询调用点传入 `"poll"` 作为第 3 参。
- 效果：下轮日志不再被刷屏；一旦服务器真改 CURRENT_LEVEL，只会出现**一行** `[RAW][customVar]`（handler 来源）+ 加载日志，可一锤定音地区分「引擎真回调了」与「本地轮询读到」。

## 第二步（17:30 执行）：重写「进入关卡」信号监听与响应逻辑（无新增调试）

### 设计原则
- 按用户原始描述实现：信号名 = `进入关卡`，参数为**整数关卡序号**（1 起始，兼容 0 起始自动 +1）。
- 不重加「测试」诊断信号、0..15 后缀批量注册、自定义变量轮询兜底（这些是第一轮调试叠加的复杂度，已确认是环境无存活服务器导致不触发，不是代码需要）。
- 全程无任何 `[DBG]/[RAW]/[ERR]` 调试打印，仅保留注册失败时的 printerr（与既有错误风格一致）。

### 改动明细
**signal.lua（在出站能力基础上新增入站工具）**
- `M.register(name, handler)`：包装 `script:RegisterServerSignalHandler(name, handler)`，前置检查 `name` 非空 + `handler` 为函数，全程 pcall，返回布尔。
- `M.getIntParam(params, index)`：从信号参数数组取第 index 个整数，兼容：整包即数字 / 数组 `{[1]=n}` / 数字字符串 / 包裹 userdata（pcall 调 `GetInt()`/`GetNumber()`）。取不到返回 nil。

**game.lua**
- 新增 `local function onEnterLevel(name, params)`：用 `signal.getIntParam(params, 1)` 取关卡序号 → 越界则尝试 idx+1（兼容 0 起始）→ `loadLevel(idx)`。参数非法直接 return（静默忽略）。
- `OnStart` 在 L 键绑定之后调用 `signal.register("进入关卡", onEnterLevel)`，注册失败 `printerr`。

### API 依据（Lua 客户端 UI 脚本 API.md）
- `script:RegisterServerSignalHandler(signalName, callback)`，回调签名 `(signalName, signalParams: any[])` —— 与实现一致。
