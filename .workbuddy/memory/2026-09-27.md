**★ 新的沙箱怪癖：git 写 `refs/remotes/**` 被静默吞掉**
- 现象：`git fetch origin` 打印 `* [new branch] main -> origin/main`、`git update-ref` 退出码 0，
  但 `.git/refs/remotes/origin/` 压根没被创建，`show-ref` 也看不到；git 还会顺手删掉变空的
  `refs/remotes/origin` 目录 → `git status` 显示 `## main...origin/main [gone]`，`git pull` 会失败。
- 对照实验（已排除仓库损坏）：① `git branch probe-br` 正常写 `refs/heads/probe-br` 并持久化；
  ② 在 `.git` 下建任意普通目录/文件（含 `refs/remotes/origin/probe`）都能持久化；
  ③ **手工写 loose ref 后 git 读得到** —— `show-ref` 列出，`status -sb` 恢复 `## main...origin/main`。
- 结论：**只有 git 自己经 `.lock`+rename 写 `refs/remotes/**` 这一条路径被环境吞掉**，
  与仓库本身无关，用户本机与队友机器不会复现。应急修法：手工写 loose ref。
- 处置：已手工写入 `.git/refs/remotes/origin/main` = `41bdd0c`，仓库回到健康态。
- 提交与推送：`41bdd0c docs: 新增队友接入指南…`（5 files, +641/−200），
