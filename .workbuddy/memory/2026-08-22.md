# 2026-08-22 工作日志

## 新增：蛋糕像素画替代糖果黄色矩形
- 用户提供一张 JPG 蛋糕图片（1440×1920，白色背景），要求转成 60×60 像素画并替代游戏中原来的黄色糖果矩形。
- 新增生成脚本 `_gen_cake.py` → `蛋糕.lua`：
  - 白色背景剔除（近白像素视为透明）；
  - 等比 contain 缩放并居中到 60×60；
  - 64 色中位切分调色板量化（无抖动）+ alpha 硬二值化；
  - 输出格式与 `等待投喂.lua` 一致：`GRID=60`，`PALETTE`（54 色），`FRAMES={单帧}`，1338 个矩形。
- 新增 `objectUI.createPixelObject(parent, anim, cx, cy, w, h, opts)`：
  - 把像素矩形作为子控件挂到调用方指定的容器节点下；
  - 像素坐标相对于父容器中心；
  - 调用方每帧只移动父容器，整组像素一起跟随，降低负载；
  - 同步更新 `update`/`setPosition`/`setVisible`/`destroy` 以处理 `kind="pixelObject"`。
- 修改 `rope.lua` 的 `createCandyNode`：不再创建黄色矩形，而是创建透明容器控件（alpha=0），作为蛋糕像素画的父级。
- 修改 `game.lua`：
  - `require("蛋糕")`；
  - 关卡重置时先 `objectUI.destroy(state.candyNode.cakeUI)` 再隐藏糖果容器；
  - 创建糖果后，用 `objectUI.createPixelObject(state.candyNode.ctrl, cake, 0, 0, candySize, candySize, {prefabId=fruitPrefabId, block=1})` 挂载蛋糕像素画。
- 移动机制：物理/拖拽/绳子模块继续调用 `state.candyNode.ctrl:SetAnchoredPosition(x, y)` 移动糖果容器，子像素控件自动跟随，无需逐帧更新 1338 个控件位置。
- 当前蛋糕显示尺寸 = 糖果直径 `config.CANDY_RADIUS*2 = 36`，与原版黄色矩形大小一致；60×60 为数据网格分辨率。

## 修复：绳子遮挡蛋糕（层级问题）
- 现象：绳子（含 dots、固定点、连接后样条线段）盖住蛋糕。
- 根因：所有对象挂在 `state.parent` 下，同级「后创建显示在上层」；糖果容器在 `loadLevel` 最先创建，绳子及其 render 每帧动态新建的样条线段都在其后 → 遮挡蛋糕。
- 关键 API：`objectUI` 用 `game.InstantiateClientUIControl(ctrlId, parent)`（第二参 parent）把蛋糕像素子控件挂到糖果容器下；`utils.createControl` 第一参是模板 ID 且写死 parent=`state.parent`。
- 修复（`game.lua`）：每帧 `rope.updateRopeNodesAll()` 之后调用 `state.candyNode.ctrl:SetAsLastSibling()`，把糖果容器（含蛋糕）移到父节点末位；并在 `loadLevel` 末尾 `updateRopeNodesAll()` 后也调一次防加载瞬间遮挡。API 文档「层级与可见性」有 `SetAsLastSibling`。
- 副作用：蛋糕会显示在所有同级对象（含小怪兽 target、星星）之上，通常无碍。若需「只盖绳子不盖其他」，进阶方案是建 `ropeLayer` 容器（在糖果前创建）收纳所有绳子控件。已在使用说明第十节记录。

## 新增：泡泡改用用户自制泡泡模板（bubblePrefabId）
- 需求：游戏中的泡泡改为使用用户自制的「泡泡模板」元件，模板 ID 从 game 脚本变量读取并记录在 config 中。
- `config.lua`：新增顶层记录字段 `M.bubblePrefabId = 0`。
- `game.lua` `OnStart`：新增 `state.bubblePrefabId = getParamNumber("bubblePrefabId", 0)`，并写回 `config.bubblePrefabId`（即"记录在 config 中"）；未配置时打印回退提示，不报错。
- `game.lua` 泡泡创建：优先用 `config.bubblePrefabId`（回退 `state.fruitPrefabId`）；改用 `utils.createControl(bubblePrefabId, ..., nil)` —— 不再强制蓝色半透明染色（`color=nil`），让泡泡模板自身外观生效。
- 遵循 README「不猜测 ID」：模板 ID 不写死，由用户在编辑器里配置脚本变量 `bubblePrefabId` 填入其自制模板元件 ID。
- 物理/点击破泡逻辑（physics.lua、utils.lua）只移动/隐藏 `bubble.ctrl`，无需改动。

## 重构：分层容器架构（每类物件独立层级，泡泡位于蛋糕之上）
- 需求：用「绳子/泡泡分层容器」方案，让每类物件（绳子/绳桩/蛋糕/人物/泡泡/星星/尖刺）各占一个层级，方便控制遮挡；泡泡须位于蛋糕之上。
- `config.lua`：新增 `M.LAYER_ORDER`（由底到顶：rope/fixed/spike/target/candy/star/bubble），集中控制层级顺序，改顺序即可调遮挡。
- `utils.lua`：`createLayer()` 建透明全屏分层容器（填满画布、alpha=0，中心与父级对齐，子控件坐标与直接挂 state.parent 一致）；`createControl` 增加可选第 7 参 `parent`（默认 state.parent）。
- `rope.lua`：`createRopeNode` 增加 `parent` 参数（默认 state.layers.rope）；固定点→`state.layers.fixed`，中间节点→`state.layers.rope`；`createCandyNode` 糖果容器→`state.layers.candy`；虚线圆点→`state.layers.rope`。
- `render.lua`：样条线段→`state.layers.rope`。
- `game.lua`：
  - `loadLevel` 开头整体销毁旧 `state.layers`（再销毁其下所有子控件），修复旧版每关重载只隐藏不销毁的控件泄漏；随后按 `LAYER_ORDER` 建层。
  - 目标（等待投喂+吞食）挂 `state.layers.target`；星星→`star`、泡泡→`bubble`、尖刺→`spike` 层。
  - 移除两处 `SetAsLastSibling`（loadLevel 末尾、OnUpdate），层级改由层容器顺序固定。
- `objectUI.lua` 不引用 state.parent，只用传入 parent，挂分层容器安全。
- 使用说明第十节已改写为分层容器方案说明。
- 注意：层级顺序里 `candy` 在 `target` 之上，保留原「糖果进入怪兽嘴」观感；若想怪兽盖住蛋糕，把 LAYER_ORDER 里 candy/target 顺序对调即可。

## 修复：蛋糕中心锚点偏右 + 新增像素脚本 HTML 编辑器
- 现象：蛋糕在糖果节点上显示时，其中心锚点略微偏右（视觉中心不在糖果节点上）。
- 根因：数据格式此前无中心锚点概念，运行时 `objectUI` 默认把像素网格正中（GRID/2）当作物件中心；而蛋糕画面 bbox 为 `x[6,52] / y[1,59]`，bbox 中心≈(29,30)，比网格中心(30,30)左偏 1 格 → 锚点相对画面偏右。
- 数据格式新增可选字段 `M.ANCHOR_X` / `M.ANCHOR_Y`（连续网格坐标，1-based，缺省 GRID/2）。
- `objectUI.lua`：`createPixelSequence` 与 `setPosition` 改用 `anchorX/anchorY`（默认 GRID/2）计算 `offX/offY`，向后兼容；并在实例表记录 `anchorX/anchorY`。
- `蛋糕.lua`：新增 `M.ANCHOR_X = 29`、`M.ANCHOR_Y = 30`，使蛋糕 bbox 中心对齐糖果节点。
- 新增 `像素编辑器.html`（单文件）：
  - 导入/导出 千星 Lua 像素脚本（解析兼容 `[n]={r,g,b}` 与数组两种调色板写法；导出用「同行相邻同色矩形合并」压缩，与原始风格一致；已用 5 个现有脚本做解析↔导出往返校验，像素数完全守恒）。
  - 画布涂改：铅笔/橡皮/吸管/油漆桶；调色板增/删色。
  - 调整中心：拖拽画布上 🎯 十字、数值输入、或「自动居中」（取全部帧 bbox 中心）。
  - 增删行列：左/右插列、上/下插行、删左/右列、删上/下行；删列/行时裁剪跨越边界的合并矩形，不误删整块；另有整体平移（↑↓←→）。
  - 帧管理：复制当前帧/空白帧/删除帧/多帧播放预览；Ctrl+Z 撤销。
  - 注意：编辑器用 `file://` 直接打开时「导入」请用文件选择/拖拽（浏览器禁止 file:// 的 fetch 本地文件）。
