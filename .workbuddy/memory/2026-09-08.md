## 切割交互的手机触屏适配（按设备分流，只动切割输入）

### 需求（用户收敛后）
- 用 `game.GetDevice()` 判断设备；只对**切割功能**做单指/鼠标分流适配：键鼠维持轮询原逻辑，触屏启用「单指切割锁 + 事件驱动坐标」。其余功能（戳泡泡/切关等）由服务器信号完成，本次不碰。

### 引擎事实（核对 API.md / miliastra_lib 桩）
- 引擎无独立触摸 API：**鼠标与触屏统一为 Cursor 事件**（`CursorDown/Up/Drag/Click`），回调收 `CursorEventData`（`touchId` 触点ID / `GetUIPos()` / `GetPressUIPos()` / `GetUIPosDelta()`）。
- `game.GetDevice()`：`Enum.Device.KeyboardAndMouse / Mobile / MobileController / Controller`。
- `game.GetCursorUIPos()` 是单点"系统光标"，手机无悬停时可能取不到；多指时可能跟到非切割手指 → 触屏不能依赖它做切割坐标。
- 现有 `checkCut(prev,cur)` 按线段判交、泡泡命中圈 1.5×radius≈42px——手机基础可跑，无需改。

### 改动明细
**state.lua**（交互状态区）
- `M.deviceIsTouch`（触屏标志）、`M.activeTouchId`（当前切割手指触点ID，nil=空闲）、`M.curUX/curUY`（当前活动点 UI 坐标，初始 nil）。

**utils.lua**
- 顶部私有 `eventTouchId(data)` / `eventUIPos(data)`：pcall 安全读 CursorEventData（touchId 字段、GetUIPos→GetPressUIPos 兜底），最后兜底 `game.GetCursorUIPos()`。
- `M.onMouseDown(data)`：触屏下 `activeTouchId~=nil` 时忽略新触点（单指锁），否则记录该触点；坐标取事件数据（空则回滚锁并 return）。
- 新增 `M.onCursorDrag(data)`：`isMouseDown` 时按锁定触点校验后把事件坐标写入 `curUX/curUY`（触屏切割跟随源）。
- `M.onMouseUp(data)`：触屏下抬起触点 ≠ 切割手指则忽略，相等才释放锁并结束。
- `checkBubblePop` / `updateDragging`：坐标源由 `game.GetCursorUIPos()` 改为 `state.curUX/curUY`。

**game.lua**
- OnStart（canvas 获取后）：`pcall(game.GetDevice)` 判断 `deviceIsTouch = dev==Mobile or dev==MobileController`（取不到按键鼠处理，PC 行为不变）。
- OnStart：DropArea 追加注册 `CursorDrag → utils.onCursorDrag`。
- OnUpdate 刀光/切割段重写：非触屏每帧 `GetCursorUIPos` 刷新 `curUX/curUY`（保留 hover 语义）；触屏不轮询。`spawn` 时用活动点坐标割绳；非 spawn 一律 `updateTrail(0/cur,dt,false)` 只推淡出（原代码此路径在 `if ux and uy` 内，手机无坐标时会被跳过——已修复保证淡出持续）。

### 风险与后续（给用户）
- 触屏切割坐标依赖引擎按触点持续发 `CursorDrag`；若真机实测发现 Drag 事件不触发（手指滑动无切割反应），需回退为 OnUpdate 轮询并在 Down 里用 touchId 过滤，或改用官方移动端文档另行核对。
- `deviceIsTouch` 采用 `dev==Enum.Device.Mobile/MobileController` 精确比较；若真机 `GetDevice()` 返回的枚举与常量比较失败（返回 userdata 且不同引用），需改为字符串/整数匹配。
- DropArea 是否全屏铺满、是否拦截底层角色操控，属编辑器配置，代码侧未处理。
