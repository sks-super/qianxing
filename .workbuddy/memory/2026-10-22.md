## 新游戏：怪兽远征（千星 Lua 伪 3D，参考 MExp / A Monster's Expedition）

### ★★ 伪 3D 的真正做法（MExp 的答案，非常关键）
MExp 根本不是 3D：世界 = **岛图 + 高度图 + 属性图** 三张二维表 + 一张实体表。
`DTIL` 画一格时：
1. `screenY = camZ - height*2 + tileY`（高度直接换算成**屏幕上移量**）
2. **在顶面下面补墙**：`while B < A`（A = 自己高度，B = 前景邻居高度）
   → 柱子厚度 = 自己比**前景（屏幕下方那格）**高出来的部分
3. 画顶面；四周邻居更低就补描边
4. 该格实体按**高度排序**画

⇒ 只要「高度→Y 偏移」+「只补前景方向的墙」+「从远到近画」，矩形也能做出厚度。
这和浮岛借木的 `DEFAULT_TILE_SIDE_RATIO` 是同一套思路（它按「前景是水才露侧面」简化了）。

### 本工程实现
- `render.cellPos(c,r,h)`：`y = ((rows+1)/2 - r)*T + h*STEP`
- `render.drawCell`：`wallH = (h - hFront) * STEP`，`hFront = -1`（水/越界）
- 绘制顺序：行 r 从 1（最远）到 rows；行内先地块后物体；每个图元建完 `raise`
- 相机：地图能整屏放下 → 固定居中（留 HUD）；放不下 → 跟随 + 夹边界

### 玩法映射
走四邻；目标格有木头且后面空 → 推一格（落水变桥）；推不动且木头能站 → 踩上去；
高度差 ≤1 可迈；走到灯塔（F）通关。3 关 ASCII 地图，图例 `. , ' ~ # T t - | @ F`。

### 踩到的两个真机坑（已修）

### ★★ MEXPWORL.8xv 格式（实测校正过的）
- TI 变量文件头：8B magic + 42B 注释 + 2B 总长 + [2B 头长 13][2B 数据长][1B 类型 0x15][8B 名 MEXPWORL] → 数据从偏移 74 起。
- 数据开头 5 个 **2B 指针**：IMAP / IDAT / HMAP / OMAP / STRS（MELSAV.LARC 里就是 `{Y+0}`…`{Y+8}`）。
- 每张图 = `2B 宽高 + W*H 字节`，寻址 `y*MW + x + 2`（MEWORL.GHAT）→ **行优先**。
- IMAP：0 = 水，1.. = 岛号；HMAP：高度；OMAP 位：0 梯子 / 1 水 / 2 树桩 / 3 岩石。
- IDAT：`1B 岛数 + 2B 指针表 + 岛块`；岛块 = `1B 实体数 + 3B 复活点 + initial/back/forward/空 + N*8B 实体`；
  实体 8B = `type,x,y,island,id,z,e1,e2`；type 0 玩家 /1 立木 /2 树立木 /3 横木 /4 竖木 /5 横筏 /6 竖筏 /7 雪人 /8 告示牌。
- **各块的绝对位置在不同世界里不一样**，靠指针 + 内容相关性定位：
  OMAP 判据 = `(byte & 2) != 0` 恰好等于 `imap == 0`（水位），实测吻合度 1.00。

## 通读 MExp 源码后的设计总结（`怪兽远征/MExp_设计总结.md`）

用户叫停改代码，要求先把项目读懂。已通读 doc/ 下 21 个模块注释版 + format/ 三份格式文档。

### 核心结论
**三张二维图（IMAP 岛 / HMAP 高度 / OMAP 属性）+ 一张实体表 + 一个移动队列**，
不是 3D、也不是平台跳跃。96×64 单色屏靠「高度→y 偏移 + 只补前景墙 + 远到近」读出 2.5D。

### 几个关键数字/结构（以后照抄用）
- L1 768B：0-99 全局变量（EM/CE/EP/UN、SF、IM/ID/HM/OM/ST、MW/MH、CX/CY/CZ、CP、撤销、队列），
  100-767 = 栈（向下）+ 移动队列（向上）对向生长。
- 实体记录 **8 字节**：类型/X/Y/岛号/实体号/**Z 高度**/额外1/额外2。
- 碰撞类型 `GECT` 按**方向**变化：横着推竖木→3、竖着推横木→4；滚木=2、筏=5、不可动=6。
- 交互动作查表 `GDB1EITA/EITB`（碰撞类型 × 是否水上 × 上/下）：0停 1走 2推 3推完走 4推不动就爬 5连走两格 6拒绝 7交互。
- 移动结果：0成功 1阻挡 2被推挡 3队列顺延 4拒绝。
- `MVEN` 递归负责"成不成立"，`MVEF/MVET` 每帧执行一批动作 → **连锁是逐帧播的**，逻辑与动画同构。
- 撤销是**增量 delta**（6B/单元 + 2400B 环形表），单步移动压成 5B 特例。
- 按岛重置 `RSTI`：删该岛实体 → 按 IDAT 原始表重建 → 玩家放回复活点；CLEAR 重置当前岛，`+/−` 跳前后岛。
- 渲染：12×8 视口、`camZ = 玩家Z`、`y = camZ - 高度*2 + tileY`、墙按 4 个半单位一层补、
  实体用 `GSEH` 按高度排序画。
- 精灵表 `Pic1SENT`（16 个实体）/`Pic1STIL`（4 地面 + 4 墙 + 3 杂项），1-bit、每个 16B。

- EITA/EITB 的**列语义**仍是我按表形状推的（目标类别 + 水上偏移 4），未逐格验证。
- 掉下/爬升的 2px 视觉位移用了简化；`ERUD` 抬升已接。
- 还有 cliffs / foothills / lake 三个世界没解析出来。

## ★★ 推不倒立木的真因：EITA/EITB 的 nibble 拆错了

现象：立木（t=1/2）推不动，横木能推。

真因：`nib{}` 里的每个 **hex 字符本身就是一个 nibble**（0..15），
我却把每个字符又拆成了高低两个 4bit → 表被撑成 32 列、整体错位，
`interact()` 取到的值几乎全是 0（= "停"）。

修正：
1. `tables.js` 重新生成：每个 hex 字符 → 一个数，16 个字符 = **两行 × 8 列**；
   EITA / EITB 各 **14 行**（7 种碰撞类型 × 水/陆）。
2. `interact(actorColl, target, onWater, above)`：
   **行 = actorColl*2 + (目标在水上?1:0)**，**列 = 目标类别**
   （玩家0 / 立木1 / 躺木2 / 筏3 / 其它4）。

验证：立木 `t1@2` 被推 → `t3@3`（倒下）+ 玩家前进 ✓；横木侧推、竖推都正常。
8 个世界 200 步回归全通过，foothills-2 能跨 3 座岛。

## ★ 修「树推不动」的三个叠加错误

用户报：islands 一直往右走，被树拦住推不动。实测后挖出三个错：

1. **数值表 MEAH/CCLL/ENTH/ERUD 也被双拆了**：`11101000` 生成成了 16 个值 →
   `MEAH[0]=0`（玩家爬升上限 0）→ 任何高度差都过不去。改成「每个 hex 字符 = 一个值」。
2. **实体 z 的语义**：MExp 里实体 z = **地面 + 1 个半单位**（重生点 z=2 对应地面 1）。
   我原来是 `base + z`（把 z 当相对量）→ 树所在格算出 5 米高，永远爬不上。
   改为 `standZ = max(base, z - 1)`，玩家走动时把 z 记成 `standZ + 1`。
3. **木头不能推进水**：MVEN 里我直接 `if (onWaterT) return 4`，把立木也挡住了。
   实际只有**玩家**不能进水，木头可以（落水漂浮 = 搭桥的核心）。
   改为 `if (isLog(e)) moveTo(); else return 4`。

验证（islands 起点往右走）：
```
step1-3 player 3→5,z=2
step4  res=0  player=(6,29) z=3   ← 树被推倒并落进水里 t3@7
```
（第 5 步之后 res=2 是「推水上那根木头但推不动」，属正常阻挡。）
