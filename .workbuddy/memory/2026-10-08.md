# 2026-10-08 工作日志

## 任务：真机导入报 `failed to load script 'config'`

用户把 TickHop 导入实际千星运行环境后启动报：

```
failed to load script 'config'
stack traceback:
	default_import_file/game: in main chunk
```

### 根因（不是代码写错，是**注册路径**问题）

去上游运行时源码里查实（`_tools/miliastra-beyond-simulator/client/lua-runtime/src/runtime.js`）：

```js
registerScriptFile(path, source) {
  const key = this.normalizeRequirePath(path)          // 去 .lua、\ 归一
  this.scriptFiles.set(key, source)
  // DSH 导入文件统一放在虚拟 default_import_file 根下，避免与运行时内建模块混名。
  // 保留裸路径是旧存档兼容层；新脚本应显式 require("default_import_file/<映射路径>")。
  if (!key.startsWith('default_import_file/')) {
    this.requireAliases.set(`default_import_file/${key}`, key)
  }
}
```

`luaRequire` 里是 `path = requireAliases.get(requested) || requested`。所以：

| 注册路径 | `require("config")` | `require("default_import_file/config")` |
|---|---|---|
| 裸名 `config.lua`（本工具链的写法） | ✅ | ✅（靠别名） |
| `default_import_file/config.lua`（**编辑器「导入文件」的写法**） | ❌ | ✅ |

→ **带前缀的写法在两种注册方式下都成立**，这是唯一两边都安全的写法。

### 改动
- 三个游戏的 `require` 全部改写为 `require("default_import_file/<模块名>")`：
  TickHop 25 处（7 文件）、割绳子 36 处、浮岛借木 19 处，共 80 处。
- `_shared/_check_refs.py`：require 检查改为**按路径最后一段**比对磁盘 `.lua`
  （否则会误报 `default_import_file/config.lua 不存在`，而且**会静默失效**掉「模块调用是否已定义」那一节 ——
  因为 `mod_funcs` 的 key 是裸模块名）。改完三个游戏 blocks/refs 全 0。
- `_tools/qxqy_websave.mjs` / `qxqy_mount.mjs`：把「必须用裸名」的过时注释改成别名机制说明
  （**注册仍写裸名**，靠别名兼容带前缀的 require）。
- 文档：根 `README.md`（三游戏共同约定）、`TickHop/README.md` §二（详细说明框）、
  `TickHop/实现方案.md` §8.2、`_tools/README.md`（新增「脚本注册路径与 require」对照表）。

### 验证（两种注册方式都实测过）
1. 裸名注册（工具链默认）→ `dev_open.mjs --restart` 重建存档 → `qxqy_webcheck` ✅
2. **真机同构**：新建 `_simulator/TickHop.realenv.save.json`，把每个脚本 path 都加上
   `default_import_file/` 前缀 → `qxqy_webcheck --archive …--frames 60` ✅
   （倒计时文本正常渲染，无 `failed to load script`）
3. 三游戏静态校验：`_check_blocks` / `_check_refs` 全 exit 0。

### 教训
- 遇到 `failed to load script 'X'` **先看 traceback 里 chunk 名的前缀** —— 它就是注册路径，
  比读代码猜快得多。
- 改 require 写法时**必须同步改校验器**，否则校验器不是报假警就是**静默不再检查**（更危险）。
- 历史记忆里其实早有这条（2026-09-25：「本项目用裸 require → 注册 path 必须写裸文件名」），
  但当时只解决了模拟器侧、没意识到真机导入是另一种注册方式 → 这次把两侧统一到带前缀写法。

## 追加：真机导入后平台秒数「被盖住」→ 两层容器 + 组件分组

### 用户给的规则（长期遵守）
> 只聚焦当前在做的游戏，**不要改其他游戏的文件**，防止版本变更引发错误。
（上一轮我顺手改了 割绳子/浮岛借木 的 require，已记下不再如此。）

### 排查到的真机根因（三条，都是「没显式声明 → 继承预制体默认值」）
1. **文本框 `bgColor`**：API 文档确认 `ClientUITextBoxControl` 有独立的 `bgColor`（背景色）字段。
   工程从来没设过它，只设了**文本框并不存在**的 `imageColor`（被 pcall 静默吞掉）→
   真机上大号 HUD 文本框（倒计时 420×100 / 提示 460×46 / 消息 1160×56）渲染成实心色块，
   **把下面的平台秒数整个盖住**。模拟器忽略该字段，所以本地怎么看都正常 ——
   完美解释「模拟器对、真机错」。
2. **容器 `enableMask`**：底图预制体若带遮罩、而容器只有 1×1，子控件会被整片裁掉。已显式关掉。
3. **叠放顺序**：API 文档 `SetSiblingIndex`「数值越大通常越靠后、显示越靠上」⇒ 真机按**创建顺序**叠放；
   模拟器渲染顺序**相反**。`SetAsLastSibling()` 是唯一两引擎效果一致的提层手段。

### 改动（只动 TickHop）
- **两层容器**：第一层按物品类型（原 8 个），第二层在每个图层内按组件类型分——
  `containerPlatform{Image,Text}`、`containerGoalImage`、`containerPickupImage`、
  `containerPlayer{Image,Overlay}`、`containerHud{Image,Text}`。
  **图片组先生成、文字组后生成**是硬性约定；`raiseOverlayLayers()`（建容器后 + 每次建关后）
  用 `SetAsLastSibling()` 兜底。
- `utils.setTextBgTransparent()`：`createText` 里把 `bgColor` 置为全透明。
- `createContainer(parent)`：支持建子容器；显式 `enableMask = false`。
- 物件全部改挂第二层：平台矩形/门/道具/玩家身体 → `*Image`；秒数/眼睛/HUD 文本 → `*Text`/`Overlay`。
- **顺手修老 bug**：`level.clear()` 漏收背景 → 换一关就多叠一张铺满屏幕的大矩形（实测
  `containerBg` 曾挂 3 个子节点，修完回到 1 个）。

### 验证
- `_check_blocks` / `_check_refs` 均 exit 0。
- 重建存档 + `qxqy_webcheck` 通过。
- **容器树实测**（`_simulator/_probe_tree.mjs`）：根 → 8 个一层容器；
  `containerPlatform`(id=3) → 图片组 id=10（10 块平台）+ 文字组 id=11（2 个秒数）；
  `containerHud`(id=7) → 图片组 id=16（4 个按钮底）+ 文字组 id=17（7 段文本）；
  `containerPlayer`(id=6) → 身体 id=14 + 眼睛 id=15；两组的父容器相同、组不同 ✓。
- ⚠️ 真机侧的最终确认仍需用户重新导入一次（模拟器无法覆盖 bgColor/enableMask 行为差异）。
