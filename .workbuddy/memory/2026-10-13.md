### 结论 / 事实（可直接复用）

  Python 生成器与 Node 独立实现各复算一遍，均确认。
- `flips` 语义（对外契约）：**在「全灭盘面」上依次按下 flips 的每一格 → 得到该关初始盘面**。
  节点图摆盘就按这个推演；玩家把 flips 各按一次必全灭。
- 难度曲线：`1 2 3 4 5 | 5 5 5 | 6×6 | 7×7 | 8×6 | 9×6 | 10×7 | 11×6 | 12×4`（共 50 关，上限 12）。
- 数据三处同步链（必须按序跑，否则漂移）：
  `_gen_levels.py --write config.lua --json _levels.json` → `_sync_editor_levels.py` → `_verify_levels.mjs`。

## ★★ 同轮发现并修掉：`dev_open.mjs` 的「同步子进程不可用」缺陷

排查上面那个 bug 时顺手发现，`dev_open.mjs` 的第 2、3 步**一直**在报失败：
「键盘映射补丁失败」「生成浏览器试玩就绪存档失败（exit null）」。因为两处都是**优雅降级**
（打警告后继续），脚本照常跑完，所以**后果极隐蔽**：**改了 Lua 但试玩页看到的还是旧代码**。

### 根因
- **本环境下 Node 的「同步」子进程 API（`spawnSync` / `execSync`）一律抛 `EBUSY`** ——
  连 `spawnSync('cmd.exe', ['/c', 'echo', 'hi'])` 都失败；而**异步 `spawn` / `execFile` 完全正常**。
- 已排除工具沙箱：`dangerouslyDisableSandbox` 重跑同样 EBUSY；换 `git.exe` / `python.exe` / `cmd.exe`
  也都 EBUSY → 是**同步 API 本身**的问题，与具体 exe、cwd（含中文与否）都无关。
- 这也解释了为什么 `qxqy_mount.mjs` 一直正常 —— 它用的是异步 `spawn`。

### 修法（`_tools/dev_open.mjs`）
- 顶部 `import { spawn, execFile }` + `const run = promisify(execFile)`，新增统一
  `capture(cmd, args)` 返回 `{code, text}`（吞掉异常、带 32MB maxBuffer、windowsHide）。
- `ensureKeyPatch` / `runNode` / `ensureArchive` / `killPort` 全部改 `async`，main 里补 `await`。
- `killPort` 原来是 `execSync('netstat ...')` + `execSync('taskkill ...')` → 改 `capture`。
- 文件头加了醒目警告：**不要改回 `spawnSync` / `execSync`**。
- ★ 顺带修：`newestMtime` 现在跳过**下划线开头**的目录 —— 否则新加的 `_sandbox/`（里面是 .lua 副本）
  会让「Lua 有改动」永远为真 → **每次启动都白重建存档**。

### 验证
`node _tools/dev_open.mjs --game 点灯迷题 --rebuild` → **五步全 ✅**（此前第 2、3 步必红）；
再跑一次（不 `--rebuild`）正确显示「试玩存档：（最新）」。存档复检：12 个脚本 / 11 个与源文件
字节一致 / `game.lua` 579 行 / `SIM_ZFIX` 与 `containerPlayer` 残留 0。

## 点灯迷题 · 真机「按钮点不动 + 文字被遮」根治 + 夏日化改造（用户报障后的大改）

### 用户的四条诉求

### ★★ 点不动的真正根因（值得永久记住）
`AddCursorEventListener` **只挂在 `ClientUIPresetButtonControl`（预设按钮）与
`ClientUICursorEventAreaControl`（光标检测区域）上**；`ClientUIImageControl` **没有**这个 API。
旧代码把点击绑在图片控件上、又用 `pcall` 包着 → **调用失败被静默吞掉** → 「按钮画得出来、就是点不动」。
→ 新增脚本参数 **`cursorPrefabId`（必填）** + `utils.createHit()` 工厂，所有可点区域改走「光标检测区域」。
`createHit` 里**每个属性一个 `pcall`**（不再整块包），并且**先**把 `imageColor` 置全透明
—— 否则点击区会变成白块盖住文字（这个是在模拟器截图里才发现的：卡片文字全是白色方块）。

### ★ 文字被遮的根因
旧结构是「一层容器 + 层内再分 `XxxImage` / `XxxText` 子容器」，真机按创建顺序叠 + 子容器各自 z 序 →
文字被后建的色块压住。→ 照 TickHop 改成**一层一个容器、容器内不再套子容器**，
层级纯靠创建顺序，且每个组件固定「底图 → 文字 → 点击区」的创建次序。

- 对真机截图逐像素对账：**卡片内部是一整块纯色、一个文字像素都没有**。
  不是 z 序、不是遮罩。
- 同一套代码真机表现：文本框高 **56 / 54 / 30 px 正常显示**，**26 / 22 px 完全空白**
  （卡片关卡名 / 难度行 / 页脚）。文本框预制体有个下限，低于它整段文字都不绘制。
  **模拟器照画不误 → 又一个「模拟器对、真机错」。**
- 修复：`utils.createText` 把盒子高度兜到 **`MIN_TEXT_H = 36`**，并显式
  `adaptiveFontSize = false`（预制体若开自适应，矮盒子会把字号缩到画不出来）。
- ★ 由此推出的硬结论：**卡片高度不是「好看就行」** —— 底边至少要容得下两行 36px 文本框，
  故 `CARD_MIN_H = 84`。`MIN_TEXT_H` 已暴露为 `utils.MIN_TEXT_H` 供布局模块反推。

### 自适应尺寸（v2，`menu.lua` 重写 ~631 行）
- 面板 = 画布 × `RATIO`（`MAX` 封顶）；`k` = 面板高 / `DEFAULT_SELECT_PANEL_H(500)`，夹 0.8~2.4。
- **卡片尺寸不再写死**：`卡片高 = (可用高 - 行距) / 行数`，
  可用高 = 面板高 × (1 - `GRID_TOP_RATIO` - `GRID_BOTTOM_RATIO`)；
  **矮于 `CARD_PREF_H(96)` 就少一行（不低于 3 行），再低于 `CARD_MIN_H(84)` 继续减；
  窄于 `CARD_MIN_W(110)` 就少一列。**
- 结果：1280×720 与 1600×900 **都是 5×3 = 15 关/页（4 页）**；
  卡片分别 156.9×104.2 / 177.3×123.2。800×600 兜底画布退成 4 列×3 行。
- 教程 / 结算用容器整层 `SetLocalScale(k)`（居中面板，缩放不跑偏）；
  **HUD 贴边布局不能整层缩放**（会被推出屏外）。
- 新增 `_simulator/diag/layout_check.py`：**离线复算 6 种画布的布局**，直接报「越界/重叠」。
