## 织卷修复师：服务器信号 + 结算倒计时

### 查 API 的结论（重要）
客户端文档（Lua 客户端 UI 脚本 API.md / miliastra_lib.lua / 客户端脚本指南 docx）里
**都没有**「退出游戏 / 结算 / 成就」这类客户端函数，只有：
- `game.ServerSignal(name)` → `:AddBoolList / AddInt / AddBool ...` → `:SendSignal()`
- `script:RegisterServerSignalHandler(name, cb)`（cb 收 `(name, params[])`）

⇒ 这些能力全部由**服务器脚本**落地，客户端只收发信号（用户已确认「让我在服务器处理」）。

### 新增 signal.lua（第 15 个 Lua 文件）
| 信号 | 方向 | 参数 |
|---|---|---|
| 客服存档信息 | C→S | bool 列表（7 大关 × 4 块 = 28，true = 已通关） |
| 服客存档信息 | S→C | 同上；进游戏下发，收到后写回 state.chapterDone 并 book.refresh() |
| 客服关卡结算 | C→S | bool 胜利 / bool 逃跑合法 |
| 客服成就达成 | C→S | int 大关号（服务器算：成就序号 = 大关号 + 1，计数 +10，目标 = 发送者） |

- 每小块通关 `pushSave()`；大关 4/4 再发一次存档 + 一次成就（state.achDone 防重复）。
- 所有发送都包在 pcall 里：模拟器没有 game.ServerSignal 也不会报错。

### 结算（客户端表现 + 规则）
- HUD 右上角「结算 1:30」按钮：state.playTime 每帧累加，hud.setSettle(sec, ready) 只在整数秒变化时刷。
- 满 90 秒 → 按钮变「结算 ✓」（accent 底），点击直接 doSettle(true)（胜利 + 合法）。
- 不满 90 秒 → 弹确认框（containerFade 层，560×260 面板 + 继续游玩/确认结算），
  确认后 doSettle(false)（不记通关，发 win=false / legal=false）。
- doSettle 发信号 → 收起 HUD/棋盘 → 翻回画册当前页。
- 结算页（通关演出）里按钮组包含 settleBtn，会一起隐藏。

## ★★ 真机报「请设置脚本参数 rectPrefabId」= 参数 API 名字写错了

现象：编辑器里 12 个脚本变量都填好了（rectPrefabId/textPrefabId/.../winAudioId），
真机仍报「请设置脚本参数 rectPrefabId（纯色矩形 / 图片控件）」。

真因：`getParamNumber` 里写的是 **`script:GetParamValue(name)`**，
而千星客户端的接口是 **`script:GetParam(name)`**（见 _shared/Lua 客户端 UI 脚本 API.md 第 124 行）。
`GetParamValue` 只有模拟器认，包在 pcall 里 → 真机静默返回 nil → 参数全是 0。

对照：本仓库其余所有游戏（2048_景苏 / TickHop / 割绳子 / 浮岛借木 / 点灯迷题 /
瓦雷莎的果园救急）用的都是 `script:GetParam(name)`，只有 点灯迷题2D 是错的（新建时抄错）。

修法：以 `GetParam` 为准，旧名 `GetParamValue` 作为兜底（模拟器两种都能跑）：
```lua
local v = nil
local ok = pcall(function() v = script:GetParam(name) end)
if not ok or v == nil then pcall(function() v = script:GetParamValue(name) end) end
```

顺带：编辑器里音频变量叫 `openAudioId`（没有 flipAudioId），
所以 `flipAudioId <= 0` 时回退用 `openAudioId`，翻牌音效才不会静音。

## 音效三件套接线（click / open / win）

用户只给了三个音效，要求：
- `clickAudioId` 覆盖**所有按钮**（选关书签、翻页箭头、封面按钮、教程翻页、底部四个、结算按钮、弹窗按钮）
- `openAudioId` = 进入关卡
- `winAudioId` = 胜利（星星触发那一刻）

做法：
1. **统一点击音放在 `utils.onClick()`**（所有 `createButton` 都走它）：
   ```lua
   target:AddCursorEventListener(CursorClick, function()
       if type(btn) == "table" and btn.enabled == false then return end
       audio.playClick(); fn()
   end)
   ```
   ★ 这样新加按钮自动有声音，不用每处手写。
2. 书页四块的命中区不是按钮（`utils.onCursor`），单独补 `audio.playClick()`。
3. `audio.init` 之前**根本没传 open**（只有 click/flip/win/star）→ 补 `open = state.openAudioId`；
   `enterPiece` 开头 `audio.playOpen()`。
4. 去掉重复音：book 的 `M.open / turnTo / setPage`、guide 的 `setPage`、
   `doSettle` 里原来的 playClick 都删掉（按钮已经播过，否则双响）。
5. **不要把 playStar 回退到 win**：finale 有 7 声、celebrate 有 14 声星星，
   回退会连播十几声胜利音。改成：小块通关 `playWin`（星星出现那一刻）、
   大关合拢 `playWin`、回画册 celebrate 开头 `playWin` 一次；star 未配置就静默。
6. `flipAudioId` 未配置时回退用 `openAudioId`（编辑器里只有 openAudioId）。

## 结算按钮：改成常驻 + 倒计时全局不重置

用户反馈两点：按钮要**始终**在右上角；倒计时**不许**每次进关卡重置。

- 新增常驻浮层容器 `state.containerTop`（层级在 containerBook 之后、containerGuide 之前），
  结算按钮从 HUD 挪到这里 → 画册页上也看得见，教程遮罩仍会盖住它。
- 按钮与倒计时逻辑从 hud 搬到 game.lua：`buildSettleBtn()` / `refreshSettle()`
  （hud.setSettle 删除，setButtonsVisible 列表里也去掉）。
- 计时：`state.playTime` 在 OnUpdate 里**无条件累加**（只在 settling 时停），
  `startPiece` 里不再重置；`settleSec` 缓存的整数秒变化时才刷文本。
- 点击：phase 为 play / book 都允许；≥90s 直接结算，否则弹确认框。
- ★ 顺序坑：`buildSettleBtn` 的 onClick 闭包引用后面才定义的 `showSettleConfirm`，
  Lua 会当成全局 → 必须先 `local showSettleConfirm` 前置声明再赋值。

## 16×16 轮廓归一化 + 钥匙/宝箱重画

用户反馈：书页上的轮廓图没居中、也没撑到接近棋盘大小；钥匙看不出是钥匙，宝箱被横向拉长。

### 归一化（art.lua）
`art.parse(pic, noNormalize)` 新增前置步骤 `normalize()`：
1. 扫墨迹 bbox；
2. 若 `w*2<=16 且 h*2<=16` → 整数倍放大 2（最近邻复制，不糊）；
3. 按 bbox 居中（`ox=(16-nw)/2`、`oy=(16-nh)/2`）铺回 16×16。
手画草图普遍只占 10~12 格且偏一角，这一步之后从「偏在左上、显得小」变成「居中、占满」。
- **猫猫 `noNormalize = true`**：它的 16 线稿和 64 彩图是配对关系，挪 1 格会让上色前后错位。
- 调用方统一改成 `art.parse(ch.pic, ch.noNormalize)`（book 两处 + game 一处）。

### 两张草图重画
- **钥匙**：原草图笔杆在第 5-6 列、齿在第 9 列，**中间空两列 → 齿是浮空的**，所以完全不像钥匙。
  重画为「8 宽圆环（中空）+ 3 宽笔杆 + 两根齿紧贴笔杆右侧」，14 行高。
- **宝箱**：原草图 11×9 只有外框 + 两根竖条，看着就是被拉长的方框。
  重画为「14 宽箱体 + 第 5 行横向箱盖缝 + 中央锁孔」，12 行高。
