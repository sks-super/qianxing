## ★★ 事故：`.git` 整个消失（00:42）+ 抢救经过

**症状**：工作文件全在，但 `.git` 目录没了（`ls -a` 无、`test -d` 否、git 报
`Unable to create .git/index.lock: No such file or directory` 与 `not a git repository`）。

**为什么会没事**：所有提交都已 `push`。远程 `main = eaadeb4`、`hzy = 719abec` 完整。
→ **教训：push 是唯一的保险。本地未推的提交在这种环境里等于不存在。**

**抢救步骤（已实证，3 分钟搞定）**：
1. `git clone https://github.com/sks-super/qianxing.git <临时目录>`（沙箱需 `GIT_SSL_NO_VERIFY=true`）
2. `cp -r <临时目录>/.git  E:/千星/千星游戏/.git`
3. 用 `git config` 补回**不在远程里**的本地项：
   `core.longpaths true` / `core.quotepath false` / `core.autocrlf false` / `core.safecrlf false` /
   `core.filemode false` / `core.ignorecase true` / `core.logallrefupdates true` /
   `i18n.commitEncoding utf-8` / `i18n.logOutputEncoding utf-8` / `diff.renames true` /
   `fetch.prune true` / `pull.rebase false`
4. **所有文件会突然全显示成 `M`** —— 那是移植带来的 **stat 缓存陈旧**，不是真改动。
   判据：`git diff --name-only` 为空即证明内容零差异。
   消除：`rm -f .git/index && git reset`（重建索引，不动工作树）。
5. 随后又一次丢引用（`main` 变成"无提交"、只剩 `packed-refs`）→ 手工重建：
   `printf '<sha>\n' > .git/refs/heads/main`，再 `git pack-refs --all`。

**★ 引用写入的规律（重要）**：这个环境里 **loose ref（`.git/refs/**` 单文件）随时会消失，
但 `.git/packed-refs` 稳定**。所以 push / merge / 建分支之后，**务必把引用写进 `packed-refs`**
并核对 `git show-ref`：格式是 `<40位sha><空格><refname>`，四行（heads/main、heads/hzy、
remotes/origin/main、remotes/origin/hzy）。`git pack-refs --all` 会自动做这件事。

**另外**：`git merge` 在本环境曾无故被 SIGTERM 打断（留下 `AUTO_MERGE`/`ORIG_HEAD` 残留，
需手工 `rm`）；重跑同一条命令 3 秒就跑完了。→ **被打断就重试，别以为是数据问题。**
