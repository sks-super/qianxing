# 点灯迷题 2D · 16×16 勾线版 GDD

> 基于「16×16 黑白勾线画 + 点灯翻转」的改造方案。
> 本文里的**数字都是实测/算出来的**，不是拍脑袋：可读性扫图见 `_art/out/demo_sweep.png`，
> 核的秩与最优步数由 `_art/` 下的脚本实算。

---

## 0. 术语

| 符号 | 含义 |
| --- | --- |
| `P` | 目标图案，16×16 黑白勾线画（黑=线条，白=底） |
| `S` | 当前棋盘状态 |
| `O` | 全白空盘 |
| `R` | 翻转规则：点 (x,y) 翻转自身 + 上下左右，越界只翻存在的格（**十字**） |
| `A` | 生成用的隐藏点位序列（顺序无关，重复按模 2 抵消） |
| `B` | 玩家实际点击序列 |
| `⊕` | 逐格黑白翻转 / 模 2 异或 |

---

## 1. 规则 R：两种方案的真实差别

| | **仅翻转自身** | **十字翻转（采用）** |
| --- | --- | --- |
| 数学形式 | `S = P ⊕ A` | `S = P ⊕ R(A)` |
| 差异格 `P⊕S` | **就等于要点的格** | **不等于**要点的格（差一个核的像） |
| 解法 | 唯一：把差异格全点一遍 | 多解（见 §2） |
| 认知负担 | 极低：「看到哪不对就点哪」 | 中高：点一格会牵动四邻，需要推理 |
| 适合 | 纯「找不同」休闲玩法 | 真正的解谜（Lights Out 的深度） |
| 单关长度 | 可到 30~60 步（点满屏） | 3~16 步（每步信息量大） |

**为什么选十字**：仅翻自身会让玩法退化成「找不同点点点」，没有任何推理；十字才有「按下去先变乱、再收敛」的解谜快感，也才需要三级提示和影响范围预览。

**但必须付出两个代价**，设计上要正面解决：

1. **差异格会骗人**。玩家直觉是「点差异格」，而在十字规则下点它往往更糟。
   → 一级提示只能叫「差异高亮」（告诉你哪里不一样），**不能**直接标成「该点这里」。
2. **画面会被打乱到认不出**。实测（`demo_sweep.png`，同一张 P）：

   | `|A|` | 4 | 6 | 8 | 12 | 16 |
   | --- | --- | --- | --- | --- | --- |
   | P 的可辨认度 | 清楚 | 可辨 | 勉强 | **认不出** | **纯噪声** |

   → 模式一的 `|A|` 必须 **≤ 6**；7~9 只给「高难」；≥10 留给模式二。

## 2. 关卡结构：大关卡 = 4 个 8×8 小关

一张 16×16 图拆成 左上 / 右上 / 左下 / 右下 四个 8×8 象限，
**每个象限单独就是一个关卡**，四块都拼完才合成大关卡。

```
大关卡（一张 16×16 勾线图 + 一张 64×64 彩色图）
├─ 小关 A  左上 8×8    P_A = 大图的左上象限
├─ 小关 B  右上 8×8
├─ 小关 C  左下 8×8
└─ 小关 D  右下 8×8
4/4 完成 → 四块合拢 → 全屏上色演出
```

### 2.1 为什么这个拆法是对的（实测秩）

| 棋盘 | 格数 | 核的秩 | 零空间 | 每个盘面的解数 |
| --- | --- | --- | --- | --- |
| 5×5 | 25 | 23 | 2 | 4 |
| 6×6 | 36 | 36 | 0 | **1（唯一）** |
| **8×8** | **64** | **64** | **0** | **1（唯一）** |
| 16×16 | 256 | 248 | 8 | 256 |

**8×8 是满秩的** —— 任意盘面都恰好只有一个解。这直接解决你提的「唯一解」难题：

- 每个小关的答案**唯一**，`B ≡ A`（模 2 集合相等），不会因为"用了另一条路"被判错；
- **最优步数 = |A|**，不用解方程、不用枚举零空间；
- 星级可以硬气地按 `|A|` 给，且"提示"给出的点必然是唯一解里的点。

> 反过来，如果做成整块 16×16（秩 248），同一盘面有 **256 组解**，
> 最优步数得靠「求特解 + 枚举 256 个零空间向量」才能算准。
> **拆成 4 个 8×8 把数学问题变简单了** —— 这是这次拆分最大的收益，比"拼图演出"更值钱。

### 2.2 生成仍然是逆向的

```
选图 → 切成 4 个 8×8 → 每个小关独立：抽 |A_i| 个互不相同的格 → S_i = P_i ⊕ R(A_i)
```

8×8 满秩 ⇒ 每块必然可解；四块都复原即大关卡完成。**永不碰运气。**

### 2.3 小关顺序

默认**任选**（四个拼图槽，点哪块解哪块），符合"拼图"直觉；
也可在 config 里设 `DEFAULT_SUBLEVEL_ORDER = 1` 强制 左上→右上→左下→右下 的顺序引导。

## 3. 模式一 · 找不同复原

**布局**：左 P，右 S，两边都是 16×16、同一格尺寸。

### 3.1 玩家到底在找什么

不是「差异格」——十字规则下它**不等于**要点的格，照着差异猛点只会越点越乱。

真正要找的是：**能让 S 变成 P 的点击集合 B**（即 `S ⊕ R(B) = P`）。
小关是 8×8（满秩）⇒ 这样的 B **唯一**，而且它就是生成时用的 A。

### 3.2 胜利判定

**只看状态**：`S == P`。8×8 下解唯一，所以"任意解"与"唯一解"在这里不冲突：
想赢就必须点出那一组，没有第二条捷径。

### 3.3 星级（8×8 解唯一 ⇒ 最优步数 = |A|）

| 星 | 条件 |
| --- | --- |
| ★★★ | `步数 == |A|`（一步不多） |
| ★★ | `步数 ≤ |A| + 2` |
| ★ | 通关即可 |

因为 8×8 满秩、解唯一，**最优步数就是 |A|**，生成时直接写进关卡数据，运行时不求解。
多出来的步数一定是"点错又补回来"（同一格按两次即可抵消），所以 +2 的宽容度刚好。

### 3.4 难度参数（8×8 = 64 格，一次点击牵动 5 格）

| 档 | `|A|` | 最多被翻格数 | 体感 |
| --- | --- | --- | --- |
| 入门 | 2 | 10（16%） | 基本可辨，纯找不同 |
| 常规 | 3~4 | 20（31%） | 图形开始走形，要对照左图 |
| 进阶 | 5~6 | 30（47%） | 只能靠推理，左图仅作验收 |
| 硬核 | 7~8 | 40（62%） | 几乎全乱 |

> 实测（`_art/out/demo_quad.png`）：8×8 象限里的线条本来就少，
> `|A| ≥ 3` 时 S 就已经明显走形。**所以左侧参考图不是装饰，是必需项**；
> 而"找不同"只是入场引导，真正的解法是「按下去会翻哪 5 格」的推理。

## 4. 模式二 · 无参照复原

- 目标 `O` = 全白；初始 `S = R(A)`（对空白施加 A）。
- 不显示任何参考图 —— 这一模式里**图案不参与**，是纯 Lights Out。
- `|A|` 可以放开到 **6~10**（8×8 只有 64 格，再多就只是乱，不是难）。
- 胜利判定：`S == O`。
- 提示只有二级可用（「提示一个 A 点」与「显示影响范围」）；
  一级「差异高亮」在模式二无意义（差异就是所有亮着的格）。
- 同样按小关结算，4 块都过才进大关卡演出。

## 5. 关卡生成

```
seed ──► 确定性 RNG(xorshift32) ──► 选图 + 选 |A| + 抽 A 点位
                                        │
        P（预置 16×16 勾线画）──────────┴──► S = P ⊕ R(A)
                                        │
                            BFGS 求解 + 枚举 256 零空间向量
                                        │
                                  最优步数（写入关卡数据）
```

- **必须自带 PRNG**：`math.randomseed` 在不同机器上不一定一致，种子关卡会漂。
  用 xorshift32（32 位整数运算，Lua 5.1 可用），种子显示在 HUD 上，可复制。
- 抽 A 时用 **Fisher-Yates + 拒绝重复**，保证 `|A|` 个互不相同的格。
- 离线预生成 60~80 关写进 `config.lua`；运行时只按种子/序号取。

## 6. 提示三级

| 级 | 表现 | 代价 |
| --- | --- | --- |
| ① 差异高亮 | 把 `P⊕S` 为 1 的格描一圈暖色边（模式一专属） | 免费 |
| ② 提示一步 | 从「剩余解 = A ⊕ B」里取一格，脉冲高亮 | 计 1 次提示 |
| ③ 影响范围 | 悬停/长按任意格，预览它 + 四邻会翻成什么（虚影） | 免费（这是可读性保障） |

> ③ 是**必须常驻**的：十字规则下玩家不该靠猜。鼠标 hover 直接显示；触屏用按下不松手预览、松手才生效。

## 7. 胜利演出

分两级：**每个小关**有一段"入槽"演出；**4/4** 才是全屏魔法上色。

### 7.1 小关完成（约 1.2s）

```
S_i == P_i
  ├─ ① 定格 0.3s，该象限线条亮度提一档 + 一圈暖色描边闪一下
  ├─ ② 棋盘整体缩到 0.35，飞向顶部「拼图槽」的空位（outBack + 轻微旋转回正）
  ├─ ③ 落槽：槽位边框亮一下（"咔哒"），槽内显示该象限的勾线
  └─ ④ 若还有未完成象限 → 回到选块界面（剩余 3/2/1 块）
```

顶部始终有一条 **2×2 拼图槽**：已完成的是画，未完成的是空格 + 序号。
这样玩家随时看得到"大图拼到哪了"——这是把 4 个小关绑成一个大关卡的关键。

### 7.2 四块齐 → 全屏魔法上色（约 3s）

```
4/4
  ├─ ① 拼图槽里 4 块先轻微分离 → 再合拢（位移归零 + 缩放回 1，outBack 0.55s）
  ├─ ② 合并成整张 16×16 勾线画，居中放大到屏幕主视觉（0.45s）
  ├─ ③ 镜头微震 3px + 描边自发光（线条由黑转暖白，1.0s）
  ├─ ④ 粒子从四角向画面中心汇聚（同时音效渐强）
  ├─ ⑤ 色彩沿线条流入：以线条为骨架，从中心向外扩散填色（1.2s）
  ├─ ⑥ 交叉淡入 64×64 精细彩色画（路径 A：图片控件淡入；路径 B：16×16 色块收拢）
  └─ ⑦ 结果面板：4 个小关的星级 + 总步数 + 用时 + 是否全三星 + 继续
```

**为什么用 4 个容器**：每个小关的 64 个格子挂在自己的容器里，
"入槽"和"合拢"都只改 4 个容器的 `anchoredPosition` / `SetLocalScale`，
不用逐个动 256 个子控件 —— 既好写，也避开 256 控件的性能问题。

## 8. 像素画管线

### 8.1 两种画的分工

| | 16×16 勾线画 | 64×64 彩色画 |
| --- | --- | --- |
| 用途 | 游戏内的 P / S（256 格） | 胜利演出的"成品画" |
| 线条 | 1px 纯黑 `#101010`，白底 `#FFFFFF` | 2px，颜色 = 该区基色压暗到 42% |
| 色数 | 2 | 6~8（含背景） |
| 对应关系 | 轮廓是 64 版的"骨架" | 同一形体按 4× 精度重绘，不是简单放大 |

### 8.2 4× 重绘映射（不是双三次放大）

- **坐标**：16 单位设计空间 × 4 → 64 网格。每个 16 版格子 = 4×4 像素块。
- **曲线**：圆/椭圆在 16 版半径 r → 64 版半径 4r，按同一圆心重算，所以边缘是**细化**而不是**锯齿放大**。
- **描边**：16 版 1px → 64 版 2px（沿区域边界画，不沿原格子画）。
- **明暗**：每个分区按自身包围盒做纵向渐变（顶部 ×1.14 → 底部 ×0.88），再加 25% 的棋盘抖动防止色块死板。
- **高光**：圆形主体在左上 1/3 处加一档提亮，模拟受光。

### 8.3 分区上色规则

1. 用 16×16 的黑线把画面切成**四连通白区**。
2. 每个区一个基色，按语义槽分配：`主体 / 次要体 / 点缀 / 点缀2 / 背景`。
3. 同一语义在不同关卡复用同一色位，保证整套画风统一。
4. 相邻两区色相拉开 ≥ 40°，避免糊在一起。

色板（暗色主题下仍清晰）：

| 槽 | 色值 | 用途 |
| --- | --- | --- |
| 主体 | `#FFCB6B` / `#F2F5F7` | 太阳、小鸡、牛羊 |
| 次要 | `#FF7BA9` / `#66BB6A` | 花瓣、树叶、翅膀 |
| 点缀 | `#FF8A00` / `#4CC9F0` | 喙、脚、水滴 |
| 背景 | `#1A2238` | 统一深蓝，让主体跳出来 |
| 线稿 | `#101010` | 16 版专用 |

### 8.4 两条落地路径

| 路径 | 做法 | 分辨率 | 依赖 |
| --- | --- | --- | --- |
| **A（推荐）** | 64×64 PNG 作为**图片资源**上传千星，胜利时 1 个图片控件淡入 | 真 64×64 | 需要你上传 6~8 张图 |
| B（纯 Lua） | 16×16 分区色块（256 控件）+ 双色渐变现"上色" | 仍是 16 | 零资源 |

路径 A 才能满足"渐变为 64×64 精细彩色画作"；B 只能叫"上色版"。

## 10. 模块划分（下一步写 Lua）

```
config.lua     全部 DEFAULT_* + 关卡数据（每大关 = 16×16 位图 + 4 个小关的 A 与 |A|）
state.lua      状态字段
utils.lua      控件 / 配色 / 布局 / 命中区（复用现成）
anim.lua       逐帧补间（复用现成）
puzzle.lua     8×8 翻转规则、S/P/O、剩余解（A⊕B）、种子 RNG
pixart.lua     位图 → 色块控件；单象限 8×8 与总览 16×16 两套构建
view.lua       小关棋盘渲染与翻转动效
fx.lua         粒子 / 冲击波 / 汇聚光效
hud.lua        模式 / 种子 / 步数 / 按钮 + ★ 顶部 2×2 拼图槽
winUI.lua      小关入槽演出 + 四块合拢 + 上色演出 + 总结果面板
game.lua       入口与生命周期（大关 ↔ 小关的状态机）
```
